# Desktop 统一会话与多模态创作：最终重构方案

更新：2026-09-15。用户已确认实施。本次只保留本文，汇总产品边界、最终实现与验证结果。

## 1. 产品与交互

Desktop 会话是讨论、生成、修改和继续创作的统一入口。保留原窗口、会话列表、伙伴区域、Agent 选择器、聊天模型选择器和 Skills/MCP 工具区，增强首页及会话内输入框。

| 状态 | 输入框与执行 |
| --- | --- |
| 普通助理 | 原底栏增加“图片生成、视频生成、音乐生成”文字按钮。用户自然语言提出生成要求时，由当前聊天模型调用生成工具，不出现专业参数面板 |
| 专业创作 | 点击任务按钮自动选择创意工坊 Agent，底栏只显示任务、生成模型和参数摘要；点击摘要打开统一气泡面板。提交直接建立媒体任务，无需聊天模型参与 |
| 返回交流 | 通过原 Agent 选择器切换到普通 Agent，任务模式不再显示关闭按钮。切换保留文字、附件和各任务配置 |
| 继续创作 | 结果归属原消息，可预览、播放、下载、保存到素材、编辑图片、选图转视频、回填配置再次创作 |

现有 Agent 选择器保留位置。右侧聊天模型只在普通 Agent 模式显示；创意工坊模式隐藏该入口，只展示当前任务的生成模型。切回普通 Agent 后恢复之前的聊天模型选择，切换模式不修改其配置。生成模型独立于聊天模型；未配置聊天模型也能建立专业会话。普通 Agent 的变更随下一次普通消息提交生效，不中止已经运行的轮次。

专业任务菜单只提供图片、视频和音乐。语音合成继续作为独立能力，不把 TTS 改名为音乐。输入参数按已接入协议的真实支持范围显示：

- 图片：底栏参数摘要展示比例、分辨率和张数；气泡面板集中选择比例、分辨率、生成数量和支持的质量。带参考图使用图片编辑，蒙版使用重绘任务。
- 视频：生成模型、比例/分辨率、时长、生成数量；输入保留明确首帧、尾帧或参考角色，支持范围由适配器决定。多个视频建立独立任务，不伪装成供应商批量参数。
- 音乐：生成模型、纯音乐/带歌词、风格和歌词。已接入 MiniMax 音乐协议；不展示该协议未支持的时长控件。

底栏移除风格、模板和“更多参数”独立按钮。用户直接在描述中表达风格；素材选择、文本素材回填和原模板工作台入口收进参数面板，多步骤模板继续使用完整编辑、执行与历史功能。视频时长和音乐类型、歌词也在同一面板中按任务显示。

模型选择采用气泡列表，无可用模型、模型失效和加载失败提示，以及模型管理和重试入口都放在气泡内，不额外占用底栏。专业模式禁止空模型提交；多个候选且未设置默认模型时由用户选择，不偷偷按排序决定。模型变更只保留兼容参数。切换任务时保留不兼容附件并说明本轮不使用。

布局遵循项目 880×600 最小桌面窗口约定，按容器宽度自然换行，没有新增移动端布局。

## 2. 两种 Agent 与真正解耦

“共用生成能力”指复用一份执行服务代码。通用助理与创意工坊仍是不同的预设，每次生成拥有独立任务、模型、参数和状态；不存在普通 Agent 调用另一个 Agent 或打开隐藏工作台的关系。

```text
普通 Agent：聊天模型 → 生成工具 ─┐
专业输入框：明确模型与参数 ─────┤
画布节点、模板步骤 ────────────┤
                              ↓
                      CreationService
                              ↓
                     ModelInvoke / 适配器
                              ↓
                       现有素材存储
```

- Agent 工作台保留原 UI、页签和运行设置，负责保存预设。运行时读取冻结的预设，不依赖配置页是否挂载。
- 通用预设补齐图片、图片编辑、视频、音乐及语音生成能力；聊天模型每轮获得当前已授权工具的可用模型目录，优先使用该任务的默认模型；没有默认模型时由聊天模型选择候选并提交精确提供商与模型，专业参数不进入普通输入框。候选和默认配置每轮更新，音乐与语音分别选择。
- 创意工坊预设提供专业多模态任务，模型可以来自不同供应商。保存预设和创建专业会话不要求先配置聊天模型或每一种生成供应商。创建会话复用现有资源选择规则，自动绑定素材库；服务端仍保留资源归属校验。
- 原生生图工具改为 CreationService 适配入口，删除独立调用、轮询、产物入库实现。公共 `creation.*` Host 也直接使用该服务。
- 服务复用现有模型目录、任务仓库和素材服务；不增加工作流引擎、权限中心或另一套素材系统。
- 前端通用参数位于 `renderer/creation`；画布任务控制器位于画布目录，只接受画布节点归属。会话不导入画布控制器。
- 旧 `workbenches` 页面、独立任务历史客户端、独立 owner 和旧写接口已退役。保留的 `nomifun-workshop` 承载画布、素材、提示词、模板等仍在使用的领域服务，不承担旧工坊产品入口。

## 3. 任务与数据

任务主归属只有会话轮次、画布节点、模板步骤三类。任务记录保留实际提供商、模型、参数、输入素材、状态、远端句柄和产物，多个入口引用同一素材，不复制媒体文件。

专业请求使用 UUIDv7 接纳标识。消息和首个任务在仓库事务中建立；视频批次提前保存所有任务 ID。响应丢失后用同一标识恢复已接纳请求，不重新读取已经变化的预设、配置或原附件路径；内容不同则拒绝复用该标识。

普通工具绑定服务端当前用户消息 ID，附加媒体任务，不重写用户原文或原轮次 Agent 快照。工具返回已接纳任务后，持久任务继续执行。界面读取任务快照并刷新，不另建前端工作台队列。

普通聊天每轮读取当前会话最近生成任务的状态和有序作品 ID，供“修改第二张图”“把它生成视频”等跟进使用。待处理任务不会被当成已完成作品，历史接纳回执也不被改写。视觉创作路由允许当前预设已声明的媒体工具，避免原先只允许原生生图工具而挡住编辑或转视频。

模型配置在接纳时固定到配置版本。继续查询使用原配置与远端句柄，无法确定的提交不自动重提或换模型。取消通过任务状态的条件更新避免覆盖刚完成的任务；删除或清空会话前取消仍在执行的关联任务，已保存素材及历史来源保留。

本地附件沿用安装所有者的文件访问与现有素材导入。普通助理具有图片编辑或视频能力时，上传的图片按原顺序保存素材引用，模型从当前会话、当前消息读取准确的素材 ID，以完成“修改这张图”“把上传图片生成视频”。原文和附件列表保持完整；部分导入失败后重试复用已保存引用。参考图片不自动出现在“我的素材”，成果仍沿用原保存流程。附件的上下文来源与实际生成成果的会话/消息归属分开记录，不伪造生成 owner。

## 4. 导航与迁移

| 原区域 | 最终位置 |
| --- | --- |
| 独立生图、视频工作台 | Desktop 首页及会话输入框的任务入口 |
| 创意工坊产品壳与导航 | 删除；保留创意工坊 Agent |
| 我的画布 | 桌面伙伴下方，`/nomi/canvases`；编辑器 `/nomi/canvases/:canvasId` |
| 我的素材 | 原资产库页面，`/asset-library/materials`，保持原样式和操作 |
| 提示词库 | 资产库下方，`/asset-library/prompts` |
| 模板工作台 | 资产库下方，`/asset-library/templates` |

画布是全局资源，零伙伴时仍可使用。保留页面的保存、弹层、导入导出和执行历史继续由页面生命周期管理。素材原操作菜单增加“跳转到会话”，不重画素材页。

使用现有 SQL 迁移机制完成：

- 106：任务增加规范的会话、消息归属。
- 107：迁移旧独立工作台历史，按旧图片/视频/语音类别建立明确标记的历史导入会话，每条记录成为独立轮次。保留任务与素材 ID、配置、输入、输出、时间、远端句柄及删除状态；同步来源引用和正式数据约束，然后删除旧独立 owner 字段和分支。
- 108：模型能力表加入真实 `music_generation` 类型，保留原模型目录及语音能力。

原 sessionStorage 工作台草稿在仍存在时一次性导入，成功后移除旧键。新草稿与尚未确认接纳的请求使用项目已有的浏览器数据代际键，避免数据库恢复后串用旧状态。不存在的临时草稿不承诺恢复。

旧产品路由不保留长期兼容入口。退役检查继续检测旧运行模块、owner 与路由，避免重新引入双写路径。

## 6. 实施验证

本次修复创意会话遗漏素材库绑定导致的 `RESOURCE_SELECTION_REQUIRED`。继续实测后，一并修复通用助理被 WebSearch 错误限制聊天模型、生成工具缺少模型选择信息、视频单任务忽略数量，以及代理 Fake-IP 环境下生成文件无法下载的问题。工具定义变化后，内部会话预设的编译缓存会在新绑定时按原配置刷新；只有契约变化才追加修订，历史快照保留，独立用户预设不自动改写。首页普通会话同步保存用户选中的官方模板身份，供后续提交继续准备。刷新同一引擎下的预设时保留会话原运行引擎绑定；目标引擎先按既有引擎目录验证，真正跨引擎的选择在终止运行时或接纳新消息前拒绝，数据库不可变约束保持。普通下一轮还会从持久快照取回已选资源 ID，按新预设重新验证并重建工具运行绑定，避免更新 Agent 后工具目录丢失；已有元信息遗漏可从快照恢复。专业生成继续只解析任务能力，不额外增加会话启动资源门槛。

真实供应商验证使用现有模型配置，在独立本地测试数据目录完成：

| 链路 | 结果 |
| --- | --- |
| 创意工坊 → StepFun `step-image-edit-2` 生图 | 成功，图片已生成、入库并读取 |
| 创意工坊 → Agnes 生图 | 成功，图片可读取 |
| 原会话引用 Agnes 图片继续编辑 | 成功，同一会话新增带蓝色围巾的图片 |
| 创意工坊 → Agnes 视频 | 成功，MP4 已入库；浏览器实际解码、播放定位通过，约 5 秒 |
| 通用助理 → StepFun `step-3.7-flash` → 生成工具 → Agnes 生图 | 成功；未设置默认生图模型，由聊天模型传入准确的生成模型选择，作品归属原会话和用户消息 |
| 最终构建：通用助理 → StepFun 生图 → 同会话更新 Agent 后续图 | 成功；聊天模型选择 `step-image-edit-2`，随后调用图片编辑工具并引用准确原图 ID，为同一只小猫添加蓝色围巾。两次任务均完成、入库且图片已打开核验 |
| 音乐 | 按用户最新要求暂不进行真实生成测试；当前也未配置 `music_generation` 模型 |

本轮定向验证：前端生成链路回归及后续首页 Agent 身份保存回归通过，类型检查及桌面 UI 边界检查通过；后端联合回归 107 项、随后内部预设缓存回归 18 项、运行绑定及会话应用回归 8 项、最终下一轮工具绑定回归 4 项均通过（网络库另有 1 项原有忽略项）。覆盖三种专业任务资源绑定、五类媒体工具选模、默认配置刷新、禁用/跨任务模型、任务归属、重放固定模型、视频数量和下载地址校验。`nomifun-web` 开发构建通过，实际后端已用于上述供应商验证。

此前整体重构的类型、国际化、主题、架构边界、生产 UI 构建、旧工作台退役检查，以及数据库迁移、素材、会话、生成服务和模型适配器的定向回归已通过。实际组件验证采用 880、1280、1920 桌面宽度；交互稿中固定数据与本轮真实生成结果分别记录，不混为实测。

没有运行整个仓库的全部测试，也没有提交或发布代码。桌面安装包未重新发布，修复需使用重新编译后的后端。本轮没有由助手停止或重启用户正在运行的桌面程序。

现有运行引擎契约固定会话创建时的准确构建摘要。后端重编译改变摘要后，旧构建会话不会自动迁移到新构建，派生会话也继承原摘要；本轮真实续图使用同一最终构建内新建的会话验证，未修改数据库约束或伪造旧会话迁移。


实测清理状态：所有测试生成任务均已终止，独立 API 测试进程已停止，产物与脱敏回执已导出。自动审批拒绝删除独立测试目录及其中复制的加密密钥（仅返回 blocked by policy），因此该测试目录仍保留在本机，未绕过限制执行清理。

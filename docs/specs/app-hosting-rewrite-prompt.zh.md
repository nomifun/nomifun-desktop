1. 仓库及相关目录的 AGENTS.md。
2. docs/specs/app-hosting-and-extensions.zh.md：本次最终设计依据，尤其第6节的无感本机连接。

4. docs/architecture/agent-session.zh.md：涉及 Session 内容、存储、归属或历史时必须遵守。
5. 最新产品结构依据用户手绘原型：docs/reports/assets/app-workspace-product-wireframe.png。
图中的红色“省略了大量开发过程信息”是说明标注，实际产品必须保留普通会话完整开发过程。不能把原型示例数据、模拟状态或成功提示当成实际实现和验收证据。

最终设计优先于旧插件架构和专属创作方案。发现旧约束与本次决策冲突时，按新边界替换它，并同步清理旧要求。核对当前代码，不假定审计时的行号和状态仍完全相同。

二、产品定位已经确定

产品名称「应用托管」，侧栏入口「应用」。用户借助 coding agent 写好自己的应用后，交给通常长期运行的 NomiFun，省去个人使用场景的重型打包发布。

应用统一为普通程序，可以有 UI，也可以无 UI；拥有自己的文件、数据库和业务架构，可以采用任何已有可运行的技术栈。系统增强应用只是增加了可选平台连接，不另建一种插件实体或生命周期。不要求官方 SDK、专有 Manifest、activate(ctx) 或 window.nomi。

平台职责是执行配置的命令、启动、观察和停止受管进程。产品体验应接近 bun install / bun run dev / bun run build / 启动服务这几个操作。

三、必须实现的托管闭环

- 支持文件夹/压缩包导入，支持源码与编译产物；导入到应用自有托管副本，保留原文件。
- 识别项目脚本和锁文件，自动填写可修改的依赖安装、预览、构建、启动命令，以及产物目录、网页地址和环境变量。非必需项可空，参考 Vercel 的命令配置体验。
- 优先使用用户已有 Node，支持指定可执行文件；不设置 Node 版本白名单，不沿用内部 JS Runtime 的版本要求。缺失时提供协助安装官方最新发布版的能力，不自动替换用户已有环境。npm、Bun 等工具分别检测，缺失如实提示。
- 静态产物提供普通小型 HTTP 服务预设；SSR、其他服务端或后台产物按真实启动命令运行。不要把 dist 目录误当进程或把所有产物当静态网页。
- 首次预览：安装→预览；无预览命令时安装→构建→启动。首次开始使用：安装→构建→启动。空命令跳过，失败停止当前操作。
- 日常启动只执行启动命令；修改当前文件后「重新构建并启动」依次停止→安装→构建→启动。不保存应用历史版本或部署修订。
- 预览与使用共用当前目录和数据；切换先结束已有进程，不创建两份常驻服务。无 UI 应用直接开始使用。
- 一个应用只有一个进程所有者，复用通用进程基础，管理前台进程及其受管进程树。不要叠加 PM2 daemon，不让 MCP 另行拉起程序。
- 按应用串行化启停和准备；慢应用不能占全局锁。主要状态为运行中、已停止、失败，保留有限的必要失败输出。
- 非预期退出、启动错误或无法确认运行状态时如实标失败；正常停止和预览切换不标失败。不自动重启、修复或拉起。正常退出 NomiFun 时停止受管服务；崩溃后的状态核对不能仅凭复用风险的 PID。

四、平台连接必须无感

用户导入并启动的应用，按用户自己的本机程序信任。读取自己的进程信息直接使用 OS/语言接口；读取 NomiFun 托管状态或调用公开能力时，Host 自动提供连接。

- 复用现有 Host 启动期 LocalTrust 与 owner 解析，通过预览/启动进程的环境自动注入本机地址、连接凭据及必要的 Agent 连接信息。
- 用户不申请、复制、填写或维护 token；不新增每应用密钥表、权限矩阵、审批面板、续租或吊销系统。共享连接按本机 owner 信任，不伪装成应用隔离沙箱。
- 自动连接覆盖 Desktop 与 Headless。保留外部客户端既有鉴权、管理员初始化和 CORS 行为，不能靠关闭鉴权或无条件信任 localhost 实现。
- 凭据只进入后端运行环境，不注入安装/构建命令，不烘焙进网页或日志。网页通过自己的普通后端使用平台能力，无前端 SDK Bridge。
- 应用调用 Agent 优先复用现有 REST open / turn / observe / cancel 及现有 Agent/RemoteBinding owner。平台准备连接，用户只选择要使用哪个 Agent，不接触绑定术语。
- Host 重启自动更换本机凭据。删除单个应用只移除该应用的来源和连接引用，不吊销共享凭据、不影响其他应用或 NomiFun 界面。

五、只接入已经确定的简单扩展点

应用可以通过 MCP 提供工具，平台自动登记到现有工具目录，在 Agent 工作台提供发现与选择，真实调用复用现役 MCP/Agent 链。来源、进程和配置只有一个 owner，不再建独立可写的能力注册库。

按 Agent/会话明确选择应用工具，默认不全局注入。连接错误局部提示，不拖垮其他应用或普通会话。沿用实际工具容量和会话合同检查，不静默截断，不为托管重写整个 Runtime。附带 MCP 资源、Provider 地址、Skill、主题只复用现有支持范围。

暂不支持：自动上下文、before_model/before_tool、旧 Surface/内嵌面板、系统菜单/事件总线、新 App Cron 类型、动态模型/语音/Channel/机器人/Office 适配器、跨机网页代理、资源专用来源和新的通用 Host API 网关。不为这些点预留新枚举、空配置或兼容执行路径。

应用创建、编辑和导入页复用普通会话和通用 coding 工具，固定使用“内置应用”系统 Agent，用户选择模型；独立右侧手工导入和配置不依赖模型。其他 Agent 可在工作台选择“NomiFun 应用开发”能力，默认不占用上下文。必要管理工具直接调用 UI 同一 owner，不再建立专属创作流水线或 Session 类型。

六、UI、修改和删除保持简单

实现原型中的三个页面：应用首页有并列创建/导入入口、居中搜索、标签分类、三列卡片和每页九项分页；创建/编辑及导入页左侧完整普通会话，底部固定 Agent 和模型选择，右侧应用名、状态、操作、描述、手工编辑和高级命令。高级配置收起，程序预览按需加载并支持放大，同时保留独立浏览器打开。用户最新原型明确授权普通网页内嵌预览，不恢复旧 Surface 或 SDK Bridge。关闭网页不会停止应用。

不要开发版本管理、部署记录、发布审核、维护面板、调试工作台、预览验证资格、交付证明、业务数据库迁移/备份/回滚。数据库迭代归应用及 coding agent；平台只运行当前文件。

应用会话只在「应用 → 对应应用 → 项目会话」管理，不混入普通侧栏、普通项目及批量操作。
应用入口通过内部创建命令在 canonical opening 建立明确的 app_project_id 归属，Agent、模型切换与位置迁移保持归属，新 fork 继承。
普通会话不因相同目录、Agent 或导航引用被收编；当前代既有应用入口只从完整精确 canonical opening 命令身份和原始 typed 工作区识别，不转换退役数据或改写历史。
通用会话删除入口拒绝应用专属 Session。应用删除确认展示专属会话数量，按 canonical Session admission 围栏拒绝在途、未知效果或未确认清理；
结束受管程序，通过现役 canonical 删除流程清理全部专属会话和历史，再删除托管目录内的源码、产物、本地数据及输出，清除来源和登记。
普通会话、其他应用、原始导入目录及外部数据保留；development_session_id 只关联导航，不能提供归属或整会话删除权。
部分失败保留登记和文件，复用现役 deleting 收据供继续删除，不新增删除账本。

只支持 Tauri 桌面和桌面级 WebUI，最低880×600，不添加手机/平板布局或测试。远程管理不能向客户端提供误指向客户端自身的 Host localhost 打开入口。

七、必须彻底汰换旧领域

按设计第8节逐项落实删除清单：旧 nomifun-plugin-platform、nomifun-plugin-development，旧 bootstrap/SDK/Host业务存储，旧 Action/Hook/Surface 路径，专属创作与交付流程，旧 Router、UI、Bridge、DTO、Manifest、活动表、fixtures、测试、脚本、依赖和现役生成指南。

建立唯一薄托管实现，复用可靠的通用基础。正式入口一次切换；不保留新旧双运行、双写、free模式套壳、旧 SDK fallback 或旧 checkpoint shim。不要按 plugin 字样机械删除 kernel 注册、MCP 共用代码、ChannelPlugin 或 Tauri 原生插件。

已发布数据库迁移校验不可改写；通过现有规则进行正向 schema 变更，未知/部分 lineage 拒绝猜测转换。切换前停止旧执行，保护现有作品及已提交的 SQLite/WAL 数据，核对后再删除旧活动结构；保护资料是一次工程切换，不做成新的维护产品。

保留 canonical AgentSession→Turn→Event/Payload→Effect 唯一事实链、合法当前代历史和 immutable Revision/Snapshot。退役配置通过原 owner 处理；旧 PluginAuthoring 仅保留必要 typed 只读识别，不恢复旧执行，不迁入新创作流程，不直接改写历史或重建第二份日志。

八、执行、验证与完成标准

先核对调用链并制定简短实施清单，然后立即实施。可并行拆分薄托管、Agent接入和UI，但文件及owner职责清楚。完成新闭环、无感连接、旧域删除及验证；不能只完成前两项就停下。

至少实际验证：源码、静态/服务端产物、无UI程序；系统Node与自定义路径；缺失命令；预览到使用只有一份进程；重复启动与停止进程树；单应用故障不锁全局；Host退出/崩溃状态；覆盖后重新构建；准确删除范围；Desktop/Headless无感连接和Host重启后旧凭据失效；按Agent选择、真实MCP调用及REST Agent任务往返；外部鉴权与合法历史不受破坏。

运行受影响的Rust/UI测试、必要编译和整体检查。UI必须运行 bun run check:desktop-ui-boundary；涉及Session存储或内容必须运行 bun run check:agent-session-boundary 及受影响用例。不可用的平台检查如实报告，不能用原型、mock成功或旧专项测试通过代替真实闭环。

同步修订现役架构和开发指南，删除已替代的设计要求，历史交给Git。完成前再审查一遍是否仍有版本/发布/维护状态机、双重owner、全局注入或旧体系兜底，并清除残留。

最终给出：实际完成的行为、汰换范围、验证结果和仍存在的具体限制。未经明确要求不提交、推送或发布。现在请开始执行。

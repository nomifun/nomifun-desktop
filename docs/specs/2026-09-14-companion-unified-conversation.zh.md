# 桌面伙伴统一会话与设备能力重构

日期：2026-09-14
状态：已完成实现与软件验收；验证范围与复现方法见第 7 节。

## 1. 已确定的产品决策

一个伙伴拥有一套身份、一份 Agent Binding、一个正式 Conversation、自己的记忆与知识库绑定。桌面窗口、主会话页、已绑定 IM 和物理机器人通过同一伙伴会话交流。不同伙伴仍然隔离。

本次为破坏式重构，采用全新数据基线。不迁移旧机器人消息、线程映射和 Agent Binding，不保留旧入口、兼容别名、旧模板或双读路径。旧版数据不在本版本支持范围内。代码改造不附带清空开发者机器上的应用数据；验证使用隔离的新数据。

## 2. 所有权与生命周期

| 对象 | 唯一归属与规则 |
| --- | --- |
| 人格、Agent 设定、主模型、模态模型、记忆、知识库 | 伙伴 |
| Conversation | 伙伴；设备重连和切换入口不创建新 Conversation |
| 设备名称、固件、音量、权限、连接状态 | 设备 |
| WebSocket、音频处理、设备协议 Session | 当前物理连接；不持有独立聊天历史 |
| 输入来源、回复目标、模态、设备授权快照 | 当前轮次；由可信宿主解析 |

删除 `robot.default` 模板与 `robot` 产品 Agent Binding 目标。设备本身仍是可授权的原子资源。伙伴只通过 `companion` 目标解析 Agent 设定；设置更新在后续轮次生效。

## 3. 会话与轮次

机器人连接直接确保伙伴主会话，不维护 `robot/threads.json` 或 `(robot_id, companion_id)` 聊天映射。主会话不得持久化机器人专用人格、设备 MCP 地址或机器人模式。

可信轮次上下文包含伙伴、入口设备、回复目标、设备连接代次、输入/输出模态及本轮工具授权。公开 JSON 的来源标记不构成设备身份或调用授权。每个执行轮次固定配置版本；设备解绑、权限撤销和断线须在执行设备操作时再次验证。

桌面、IM、机器人共享有序对话上下文。忙碌时输入进入受控队列；不得因冲突丢掉已接受的语音，也不得创建另一 Conversation 绕过顺序。排队请求具备稳定幂等身份，取消后不能重新执行。

模型输出只发给对应轮次的订阅者与明确回复目标。桌面始终可看见主会话记录。机器人停止播报与取消模型轮次分开；取消模型必须匹配精确轮次身份，迟到的停止请求不能影响后继轮次。

## 4. 模态与设备能力

连接、编解码、VAD、转写和播报是交互基础设施，按设备、权限与模型条件自动工作，不要求用户再挑选机器人 Agent。主模型、ASR、TTS、音色和视觉模型仍配置在伙伴上；没有兼容模型时说明缺失项，不虚构可用回退。

Agent 主动感知与动作保持原子化。有效能力为伙伴策略、设备支持、用户授权与实时在线状态的交集。自动装配须进入统一授权链，不能用 MCP 旁路扩大 Agent 权限。普通用户配置有意义的拍摄、主动观察、动作、主动播报许可；高级配置可选择实现。

机器人专用口语表达、TTS 文本处理和目标设备工具只作用于当前轮次。桌面下一轮恢复完整文本表达。视觉材料及观察结果必须关联主会话的原始轮次，保留设备来源，不能产生独立聊天或重复问答。模型故障回退只作用于本轮，不回写伙伴主模型。

## 5. UI

会话列表只显示伙伴主条目，删除机器人子会话。伙伴会话头部承载设备状态与入口；设备卡片移除 Agent 选择器，保留连接、名称、设备设置、授权、解绑与移除。消息可展示轻量来源提示，来源不能充当人格区分。

共享 renderer 仅支持不小于 880×600 的桌面 viewport；沿用现有组件，不增加移动布局。

## 6. 实施顺序与完成标准

1. 持久化本方案，建立新的可信设备轮次契约及回归。
2. 收敛伙伴 Agent 绑定，移除机器人预设、UI 选择器及运行时分支；保留原子设备资源。
3. 将机器人接入伙伴主会话；清除独立线程映射、会话级机器人模式与持久设备工具。
4. 接通轮次级工具/表达/模型回退，输入排队、订阅隔离及精确取消。
5. 接通视觉材料归属、设备状态/权限与主会话 UI。
6. 更新生成契约、文案、文档与测试，执行针对性验证及桌面边界检查。

验收：跨桌面/机器人接话；修改伙伴设定统一生效；多设备不串播；并发不丢输入；停止不误取消；重连不新增会话；解绑撤权阻止迟到动作；视觉进入同一历史；回退不污染配置；旧模板与独立会话路径无运行入口。不能以只隐藏 UI 或只通过结构测试作为全栈完成证据。

## 7. 最终实现与验收

本方案已完成代码实现和软件验收。全新数据基线、不迁移旧机器人数据、不保留旧机器人 Agent 或独立会话入口的决策不变。

| 要求 | 最终实现 | 验收证据 |
| --- | --- | --- |
| 一个伙伴、一条主会话 | 机器人调用伙伴的唯一会话入口；桌面沿用原 Conversation；删除独立线程映射与启动修复 | 真实 AppRobotBackend / ConversationService / Nomi 引擎测试覆盖连接前文字对话、连接后语音接话、重连复用同一 ID |
| 一套 Agent 设定 | 只绑定 companion；删除 robot.default、robot 产品绑定目标和设备 Agent 选择器；重新生成六个官方模板的契约 | 默认伙伴无设备可用；实际切换模型和最简 Agent 后，桌面与机器人一致生效 |
| 统一记忆、知识库 | 使用共同 companion_id、Conversation 和伙伴知识库挂载；补齐原子记忆读写能力到实际原生工具的映射 | 桌面保存记忆、机器人调用真实记忆工具读取同一条记录；知识库归属解析包含在会话单元回归中 |
| 桌面控制与输出路由 | 单设备自动选择，多设备显式选择 control_robot_id；桌面回复默认静音；播报按钮只播放已完成回复 | 多设备无选择时不执行动作；选中设备才收到命令；重放不重复执行；播报不增加模型请求 |
| 原子能力与有效授权 | 基础音频传输自动运行；设备动作从伙伴快照、设备支持、权限和连接状态计算；MCP 使用宿主签发的轮次授权 | URL 参数不能扩大授权；错误设备、过期授权和重连旧 socket 被拒绝；模型启动后撤权不执行物理动作 |
| 权限配置有效 | 设置只展示固件实际支持的控制项；拍照、动作、屏幕、扩展工具、连续观察和桌面播报有执行检查 | 连续观察要求拍照与连续观察两项许可；桌面播报撤权后停止；会话头部即时同步许可变化 |
| 输入有序与精确取消 | 共用主会话的执行顺序；设备输入有稳定幂等身份；取消在同一锁内核对 owner 与持久操作 ID | 并发设备共享有序历史；取消排队语音不误停桌面工作；迟到取消不能影响后继轮次 |
| 模型回退不污染配置 | 在同一逻辑轮次内使用备用模型，不回写主模型；重新解析备用供应商的配置图 | 503 故障真实切换备用端点；数据库和模型上下文都只有一次用户输入；后续轮次恢复主模型 |
| 视觉并入原始会话 | 拍照必须关联当前有效轮次；图片经 ArtifactStore 保存，观察结果附在原消息上，通过注释事件刷新 UI | 实际设备工具 → HTTP 上传 → 视觉服务 → 图片文件与消息注释；无活动轮次及撤权时不调用视觉模型；历史合并保留注释 |
| 断开、解绑和重连不串状态 | 状态发布持有精确连接校验；清理只影响对应 socket；旧连接不能覆盖新连接的在线状态或伙伴归属 | 连接替换、旧清理、同状态重新绑定和断线回归通过；迟到语音结果不复活已撤销连接 |
| 删除历史设计 | 删除 robot/threads.json 路径、永久机器人模式、旧模型同步查询与 027 消息回填迁移 | 旧迁移账本被拒绝且原数据不被迁移、清空或自动退役；源代码扫描无旧运行入口 |
| 桌面 UI | 单一伙伴会话条目，头部设备目标和播报入口，消息来源与视觉观察，设备设置中无第二个 Agent | 1280×800、880×600 实际组件预览；最小尺寸 scrollWidth=880；设备选择与撤销播报许可交互验证 |

# 伙伴会话入口与共享资源修复

## 根因

首页伙伴展示区和侧边栏调用同一个 `POST /api/companion/companions/{id}/companion/threads`。其创建/刷新过程展开 `companion.default`，模板同时启用 `mcp.tool_proxy` 与 `mcp.resource`。新的 Nomi 运行时要求平台资源读取和原生全工具代理使用不同的执行路径，因此在编译配置时拒绝该组合。尚未调用模型就返回 422。

`control_plane_error_to_app` 原来只保留外层错误文本，丢失编译器诊断；首页再把错误替换成通用重试文案。现已保留诊断中的具体原因，并使用统一的错误展示。

首页资源面板还有独立缺陷：所有资源加载共用一个等待状态，任意渠道/机器人/MCP 请求未完成都会禁用已加载的伙伴选项；面板不订阅伙伴创建/删除事件；把渠道、机器人和 MCP 全部当作启动必选项；最终经普通 AgentSession 创建接口产生独立会话，无法与伙伴侧栏共享身份与设置。

### 追加排查：列表加载完成后，点击仍无法选择

后续截图显示伙伴选择框已启用，但仍不能选择。用生产 `AgentResourcePicker` 和首页同样的 `ConfigProvider` 弹层容器，在 Chromium 中复现菜单打开后立即关闭。浏览器事件记录证明一次真实鼠标点击产生两个可信 click：先命中选择框的 `SPAN`，再命中内部 `INPUT`。原因是字段外层使用隐式 `<label>`，浏览器会把点击转发给 Arco Select 的内部输入框，二次触发 Trigger 的打开/关闭逻辑。单独派发一次 `fireEvent.click` 的旧测试未覆盖原生 label 激活，因此此前库存加载修复没有解决这个交互缺陷。

字段改用普通 `div` 容器，保留 Select 自身的 `aria-label`。此修复同时覆盖伙伴、渠道、机器人和 MCP 等共用字段。新增回归测试模拟原生 label 转发，在旧代码上断言 `aria-expanded` 失败，在修复后通过；真实浏览器确认菜单持续展开、选择团团后按钮启用、可选择渠道/机器人/MCP、切换伙伴清除暂存绑定。

可重复的浏览器验证入口：运行 UI 开发服务器后打开 `/test/agent-resource-picker-preview.html`，使用至少 880×600 的桌面视口。该页面只注入固定测试库存，不连接用户后台或发送消息。依次选择伙伴、渠道、机器人、MCP，再切换伙伴；下方显示真实组件回写的选择值。

后续界面调整：伙伴选项和选中值均以头像、名称、小号 `#seq` 在同一行紧凑显示，头像复用侧栏的内置/自定义形象组件。移除资源面板下重复的“打开聊天”按钮及其专用处理函数；发送消息、会话浏览器继续复用伙伴正式会话，提示文案同步更新。

## 修复行为

- 官方伙伴模板保留原生 `mcp.connect` 和 `mcp.tool_proxy`，移除与之冲突的默认 `mcp.resource`。运行时的禁止混用校验保持有效。平台 MCP 资源读取仍属于选择相应能力的 Agent，此次没有给原生代理开放旁路。
- 已保存的、精确匹配旧官方伙伴模板的内部配置可识别并在原会话中刷新。个人 Agent 和带自定义指令的内部配置不被重新归类或覆盖；不清空用户数据和聊天历史。
- 后端确保伙伴会话时串行执行“查找、创建、登记”，并发首次打开复用同一个会话 ID。
- 资源列表按种类独立加载；伙伴创建/删除后重新加载。伙伴模式仅要求选择伙伴，其余资源可选；可选择该伙伴已有或尚未绑定的渠道/机器人。
- 首页选择伙伴后，打开聊天、会话浏览器和发送均确保同一个伙伴正式会话。已配置的伙伴模型、Agent、工作目录、技能和已有 MCP 选择继续由伙伴管理。缺少模型时才保存首页显示的所选模型。
- 首页发送直接使用正式会话的消息接口，不使用仅限空白会话的首次消息投递。丢失响应后的重试复用幂等键。
- 打开/发送时，渠道和机器人绑定使用管理页同一接口；MCP 写入正式会话的 MCP selection。管理伙伴的远程控制页增加同源 MCP 编辑器，可回读和取消选择，保存失败保留原显示。

## 验证

原有应用级测试 `companion_entry_uses_its_official_agent_and_can_switch_to_minimal` 在修改前复现相同 422；修复后通过，并增加并发首次打开返回同一 ID、数据库仅有一条 Conversation 的断言。

定向 UI 回归覆盖可选 MCP 加载未完成时仍能选择伙伴、入口复用、资源绑定保存、所有权变化拒绝提交、重试幂等以及管理页回读/失败保留。后台验证使用隔离数据库和本地替身，不调用真实模型服务、不修改用户伙伴数据。

类型检查、前端生产构建、桌面 UI 边界、双语文案和生成契约一致性检查通过。伙伴相关应用测试初次运行有一个本地 MCP 请求被 Windows 系统代理返回 502；给测试子进程设置 `NO_PROXY=localhost,127.0.0.1,::1` 后，同一 MCP 桌面/机器人共享选择测试通过。未更改系统代理设置。

# 小程序：用户产品重设计评审

日期：2026-09-12。状态：设计已获用户确认；实施与测试记录见 `2026-09-12-miniapps-implementation-progress.zh.md`。

## 产品目标

用户只需要完成三个动作：**提出需求，一键生成 → 试用预览，通过对话调整 → 保存，并随时找到、打开使用。**

“创建项目”“构建成功”都不是交付结果。交付结果是符合需求、能操作、保存后能再次打开的小程序。

这次以用户明确要求的全面重构为准。旧文档里的页面结构、显式技术步骤和历史兼容取舍不构成本轮产品约束。可以复用经过验证的底层能力，但不保留面向用户的技术工作台作为默认路径。

## 原始初衷与偏离

2026-08-09 的设计开头明确描述：AI 生成的小工具，一次保存，随开随用；对话中生成和预览，满意后固化，库页点击即运行。

后续规格引入独立源码、不可变版本、发布和运行生命周期，为应用能力提供工程基础。当前界面把这套底层对象和操作直接映射成产品步骤。缺失的是替用户完成这些步骤的 AI 创作链路与产品编排。

因此返工重点不是换皮、改几个按钮名或折叠几张表，而是恢复创作、预览、保存、复用的完整链路。

## 问题清单

| 问题 | 观察证据 | 对用户的影响 | 重设计决定 |
|---|---|---|---|
| 入口没有需求输入 | 空状态要求 Source → Build → Ready → Publish → Surface；创建表单是名称、说明、运行形态 | 无法立即开始创作 | 首页直接输入需求，一键生成 |
| “创建”没有创作 | `MiniAppCreateProjectDialog.tsx` 仅调用 createProject；实际输出为标题 HTML | 成功提示与用户期待不一致 | AI 自动产出功能并检查可运行后才显示“可以预览” |
| 要求用户选技术架构 | 创建前选纯 UI / 全栈 Service | 普通用户无从判断 | AI 根据需求推断；名称、图标、依赖、存储及运行方式自动处理 |
| 修改入口是源码编辑 | 要求相对路径、读取文件、编辑 HTML、保存 Source | 非程序员无法修改 | “用 AI 修改”，说变化、看效果、保存更新 |
| 预览在发布之后 | 实际需要构建、发布确认、启用、打开 Surface | 无法先试再保存 | 草稿独立预览；保存前不改已用版本 |
| 已有应用仍打开管理页 | 库卡片唯一主要入口是“打开工作台” | 每次使用都重复管理路径 | 点击卡片直接运行 |
| 首屏缺乏主次 | UI-only 工作台首屏有 11 个操作，修订/摘要/指针/发布模式占据主要空间 | 用户不知道下一步是什么 | 每个状态只给一个明确主要操作；管理动作放“更多” |
| 应用画面被挤到下方 | 实际向下滚动约一屏才出现 Surface，上方仍有巨大 Ready 空状态 | 使用核心内容难以到达 | 运行页以应用画面为主体 |
| 导入要求先认包类型 | 三个并列入口，要求 bundle.json、release/artifact.json、metadata.json | 拿到文件也不知道怎么导入 | 一个入口，系统检测文件类型 |
| 导入预览不是应用效果 | 表单读名称和摘要，解释 Schema/digest/后端权威 | 看不到是否是自己想要的工具 | 先呈现应用摘要、可编辑性、必要运行说明，再试用与添加 |
| 导入成功不等于可用 | 导入后进入停用状态的工作台 | 导入后仍需学习发布启用 | 一次“添加并打开”完成可用闭环 |
| 技术错误没有用户恢复路径 | exact Source、revision、descriptor、epoch 等进入提示 | 无法判断如何解决 | 显示发生了什么、现有内容是否保留、一个可执行的恢复动作 |

实现证据入口：`ui/src/renderer/pages/miniApps/index.tsx`、`MiniAppCreateProjectDialog.tsx`、`RunnerPage.tsx`、`MiniAppTransferDialog.tsx`、`model.ts`、`MiniAppSurfacePanel.tsx`，以及 `ui/src/renderer/services/i18n/locales/zh-CN/miniApps.json`。

## 新信息架构

### 2026-09-12 评审修订：集合管理必须是默认首页

用户指出第一版偏向首次创作，缺少小程序数量增长后的集合管理。此修订覆盖第一版对已有应用首页的简略描述。

- 默认进入“小程序库”，以查找、打开、组织已有小程序为主体；大面积需求输入单独放在“新建小程序”页面。空库仍直接提供需求输入，不要求用户先建立集合。
- 库内左侧提供全部小程序、最近使用、已固定、草稿、自建集合、未分类和最近删除；右侧只展示当前范围，避免在首页纵向堆满所有集合与应用。
- 自建集合是单层、单一归属的整理目录，一个应用属于一个集合；“已固定”和“最近使用”是同一应用的快捷视图，不复制应用。首版不引入多层目录与复杂标签体系。
- 新建集合、重命名、删除集中在“管理集合”。删除集合只将成员移入未分类，不删除小程序、使用数据或已有快捷入口。
- 支持在当前范围按名称/用途搜索，提供搜索全部的退路；支持最近使用、最近更新、名称排序，以及网格/列表视图。搜索、排序和翻页不会把用户带离当前集合。
- 进入“批量整理”后才出现复选框和批量动作，支持移动集合、固定、移到最近删除；普通状态点击名称直接运行。拖入集合是快捷方式，不能替代键盘可操作的移动入口。
- 创建和导入不增加必选集合的表单，默认未分类，保存后可选整理。草稿单列，正式小程序库不会混入未完成或失败的半成品。
- 数据量增长后使用有界分页/窗口化加载，按小程序 ID 保持选中和返回位置；正式实现必须在 0、1、24、200 个应用以及长名称、空集合、跨页选择场景验收。交互稿以 24 个示例、4 个集合展示，不能代替 200 条数据的性能验收。
- 重新进入库页恢复上次集合与视图，打开应用再返回保持搜索及滚动位置；“全部小程序”随时可达。

本轮交互稿新增集合管理、新建/重命名/删除集合、当前范围搜索、排序、分页、列表切换、批量移动、固定与删除恢复。仍处于设计评审，未开始修改实际产品实现。

本轮已实际检查 24 个示例的集合首页布局，点击验证：新建“个人项目”集合；把两个应用批量移入，来源与目标计数同步更新；删除该集合后两个应用进入未分类且快捷入口保留；切换列表并搜索能找到移动后的应用。分页、拖动、批量删除恢复等虽已提供模拟交互，但不记作真实产品端到端验收。

只保留一个“小程序”产品入口，内部围绕三种用户任务组织：

1. **创作**：一句需求 → 对话和预览。
2. **使用**：我的小程序 → 直接运行；侧栏固定项提供一步直达。
3. **导入**：选文件/拖入 → 自动识别 → 预览 → 添加并打开。

分享、重命名、上一版本恢复、停用和最近删除是次级管理动作。备份放在应用更多菜单内；识别出备份时在统一导入流程中说明数据恢复内容。无需让用户先学习三种导入类型。

普通会话中也可提出创建小程序需求，进入相同的创作能力与预览；不产生另一套创建/发布实现。小程序自身持有可继续修改的上下文，删除普通聊天记录不应让保存的小程序消失。

## 页面与交互

### 1. 首次打开

主标题：“你想做一个怎样的小程序？”

主输入：“例如：帮我做一个每日待办，能勾选完成，下次打开还在。”主按钮：“一键生成”。

下方三个小例子用于降低空白页压力，点击填入需求，仍由用户发送。不出现名称表单、模型选择、项目路径、架构、构建配置或空的发布管理面板。

已存在应用时，“我的小程序”成为默认内容主体，顶部保留紧凑的新建入口；回访不强制重新看大型创作欢迎区。空库进入首次创作页。

### 2. 创作中

同一个页面内左侧需求对话、右侧效果预览。顶部显示自动名称和“草稿已保留／正在制作”。

首次发送即自动开始。合理缺省直接采用，只对确实影响可用结果的缺失信息提出短问题。复用全局可用模型，不在普通创作里引入 Agent/模型/工具链配置表。

如果没有可用模型，在原输入位置说明“连接 AI 后就能开始”，保留需求，提供单一设置入口；连接完成回来继续，不重新填写需求。

生成中显示实际阶段的日常表达，例如“正在制作界面”“正在检查能否使用”；不伪造百分比。支持停止和离开后继续，草稿可找回。失败后尽可能自动修复，有界重试后给“重试”或一次必要补充输入。

### 3. 预览与修改

预览必须能点击、输入和试用，不能是截图。生成完成自动显示，不需要先发布或启用。默认并排，预览获得较大面积；较窄窗口上下排列。支持放大预览，返回时保留对话。

用户说“增加分类”“字再大一点”“改成周视图”，AI 在同一上下文中修改，自动检查并刷新可用预览。失败时保留上一次成功预览。技术日志在需要排查时才提供详情。

正式应用和草稿预览的存储范围必须明确：预览不能悄悄修改正在使用的数据或启动正式后台任务。首次保存只提交应用成果；演示/测试数据不自动变成正式业务数据。

若预览需要连接外部服务或会产生实际业务动作，按当时的用户操作说明并连接；不把缺连接伪装成完整通过，也不宣传任意代码预览为安全沙箱。

### 4. 保存与使用

首次主要动作：“保存并打开”。名称和图标由 AI 给出合理结果，可后改，不弹第二张必填表单。

保存将当前成功预览的版本变成正式可用小程序，自动完成必要部署和启用，直接进入运行画面。此按钮仅表示本机保存和使用，不代表公开发布。

修改已保存的小程序时主要动作：“保存更新”。保存前旧版本持续可用，失败不影响旧版本。保存失败要保留草稿并允许重试。

保存后有轻量提示：“已保存到我的小程序”，并提供“固定到侧栏”。库卡片展示名称、效果缩略图和一句用途，主动作只有“打开”，编辑入口为次级操作。默认最近使用排序，提供名称搜索；固定项在侧栏直接打开。

普通运行页展示应用本身，顶部只需返回、名称、用 AI 修改和更多。打开一个停用应用时提供“启用并打开”；后台型任务只在用户需求明确包含后台工作时开启，状态在使用页可理解地提示。

### 5. 导入

统一入口：“导入小程序”。支持拖入和选择文件，目标格式为单个可分享文件，并支持合规自包含 HTML、现有包目录的自动识别。无需先选择 Share Bundle/Artifact/Backup。格式识别与校验必须由真实导入服务完成。

识别后显示：应用名称、一句用途、可用预览、是否可继续修改，以及是否包含业务数据。展示必要事实，移除摘要和路径规则。名称不是必须再填一次的表单。

主动作：“添加并打开”；次动作：“查看效果”。预览后的页面仍必须有添加按钮及返回入口。

识别出有使用数据的备份：用普通语言说明“将恢复小程序及其数据”，提供“恢复并打开”。如需重新连接账号，只提出该项操作。

没有可编辑源码：可以添加使用；“用 AI 修改”改为“用 AI 重新制作”，明确这是新副本，不假装能无损修改原软件。

同名不覆盖；默认自动加后缀作为新应用。完全相同内容已存在时优先“打开已有”，仍允许“另存一份”。取消或失败不污染我的小程序。

文件损坏/不支持：说明“这个文件无法导入”，给出可操作原因和“重新选择”。不能让用户修复 manifest、填 digest 或搬文件凑目录。

导入前不自动执行不受控来源代码。静态预览可直接展示；确需本机服务才能预览时，用清楚的一次运行说明和明确操作处理。这是运行条件，不扩大为普遍配置向导。

### 6. 次级操作

- 分享：导出一个文件，默认包含可继续制作的内容，不包含用户数据或账号秘密；不让用户选 Ready/Active 或填写父目录与新目录名。
- 备份：更多中“备份小程序和数据”，系统协调暂停、保存和恢复运行；只在确实会打断工作时说明影响。
- 版本：显示“当前版本／上一个版本”和保存时间；恢复代码不会冒充数据回滚。若只支持上一版，就不展示不存在的任意历史列表。
- 停用：保留内容和数据，打开时可一键恢复。
- 删除：先移到“最近删除”，支持恢复；永久删除是独立明确操作，说明会删除哪些数据。

## 需要重构的能力

这些是实施范围，不是已交付能力：

1. 以用户意图为入口的真实 AI 创作与修改编排，包括自动命名、生成、检查、修复和可恢复任务。
2. 与正式运行分开的草稿预览能力；当前 Active-only Surface 不能只改名充当预览。
3. 保存并打开、保存更新、添加并打开的统一产品操作，内部协调构建/版本/运行状态，并保证失败可恢复。
4. 统一导入识别及单文件分享、直接 HTML 导入、可编辑性与数据恢复的真实支持。
5. 以使用为中心的库页、运行页、最近使用和侧栏固定；草稿与正式小程序的数据生命周期清晰分开。
6. 替换当前强制表单、技术工作台、术语文案和相应结构测试，不通过保留旧默认流程来降低重构范围。

## 验收标准

| 场景 | 必须达到的结果 |
|---|---|
| 首次创作 | 进入小程序即可输入需求；发送后不填任何项目配置，得到实际可操作的小程序 |
| AI 闭环 | 至少以待办持久化、计时器、需要本地存储的小工具进行真实模型验收；生成文本或标题模板不算通过 |
| 继续修改 | 用一句自然语言修改，预览更新；无需查路径、编辑源码、点构建 |
| 先试后存 | 未保存即可试用；已用版本与数据不被草稿预览意外改变 |
| 保存 | 一个“保存并打开”动作后进入可使用画面；重启程序后仍可找到并打开 |
| 快捷复用 | 库卡片一步打开；侧栏固定项一步打开；搜索能找到名称 |
| 修改失败 | 旧版本仍能使用，成功预览和需求不丢失，有明确恢复动作 |
| 导入 | 一次选文件，自动识别；预览后一次添加即能打开，不要求类型、名称或技术配置表 |
| 重名/取消 | 不静默覆盖已有应用；取消不产生正式库垃圾项 |
| 运行依赖 | 缺连接或运行条件时明确提示一个必要动作，保留上下文，不能虚报成功 |
| 分享/备份 | 分享不带个人业务数据；备份清楚说明数据，恢复不冒充连接账号已完成 |
| UI | 桌面常用尺寸无重叠或横向截断；预览为主体；主操作和错误恢复清楚；键盘可完成主流程 |

## 评审方式

会话中的交互稿包含：首页、对话与可点击预览、保存后的运行和库页、固定侧栏、统一导入和导入预览。顶部四个入口仅用于评审切换，不是正式产品导航。

已在浏览器实际检查交互稿的首页、并排预览、库页和导入确认布局，并点击验证：一句话发送、生成中状态、预览添加任务、保存直接运行、侧栏固定、返回库页、导入预览、添加后与已有应用共存、退出草稿后继续创作。检查中修正了表单提交、导入预览返回入口和已有快捷入口被预览状态影响的问题。

请先审阅流程、页面主次和关键动作。根据反馈完成定稿后，再实施上述真实能力和 UI 重构。

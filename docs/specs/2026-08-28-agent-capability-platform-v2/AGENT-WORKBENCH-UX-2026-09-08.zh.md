# Agent 工作台交互重构

## 目标与实现

旧页面把全局能力目录直接铺在 Agent 编辑器里。名称、版本、来源、资源要求重复占据列表，用户难以确认当前授权范围，也不能先调整有不可用能力的官方预设再创建个人 Agent。

本次以“先看当前配置，需要时再去能力库挑选”为主线，直接重构现有工作台，继续使用 Arco、IconPark、产品主题变量和 v2 Preset/Revision/Compiler。

| 使用任务 | 交互 |
| --- | --- |
| 找到 Agent | 我的 Agent / 官方预设分栏标签，名称与描述搜索；个人 Agent 保留删除确认 |
| 看清当前范围 | 默认只显示已配置能力；顶部显示总数、启动即用、按需启用、待处理数量，点击即可筛选 |
| 浏览能力 | 按知识与记忆、文件与开发、网页与电脑、协作与设备、创作与内容、业务与自动化、模型能力、技能与扩展分类；列表每页 12 项 |
| 添加能力 | 抽屉式能力库，分类、名称/用途/来源搜索、内置/插件来源筛选；多选后统一添加，默认按需启用 |
| 禁用和移除 | 每项可调整启动方式或禁用并移除；支持选中多项统一切换或移除 |
| 检查详情 | 点击能力名称打开详情；来源、分类、使用时资源要求在详情内；ID、版本、包和贡献数量折叠展示 |
| 调整官方预设 | 直接在预设页面增减能力、调整方式、命名；保存为个人 Agent；可恢复原始预设能力 |
| 编辑个人 Agent | 能力配置、基本设置、技能与扩展、试用与检查分别置于标签页；保存状态和主要操作固定在底部 |
| 处理未保存修改 | 工作台内切换 Agent、新建或打开模型设置前确认；刷新/关闭网页使用 beforeunload 提醒；再次点击当前 Agent 不重载草稿 |

桌面采用双栏和内部滚动，窄窗口采用上下布局，编辑区仍保留内部滚动与底部操作区。长描述在列表中省略，详情中可完整查看。

## 保存语义和架构边界

- 官方种子保持不变。用户编辑的是本地草稿，保存后得到独立的个人 Preset 和初始稳定 Revision，不在官方种子上写用户覆盖数据。
- `POST /api/agent-presets` 的创建请求新增可选 `document`，与 `fork_from_revision` 互斥。原有空白创建和已保存 Revision 复制行为保留。
- 指定完整配置时，后端先补全已有默认聊天模型，再通过现有 canonical compiler 校验并原子创建 Preset/Revision/Snapshot。缺模型、无效能力等失败不会留下空 Preset。
- 自定义副本按用户选择的能力编译，不保留强制恢复官方模板能力范围的来源约束。完整 Coding 范围仍由既有 compiler 的能力推导逻辑选择 Coding profile。
- 禁用在现有契约中意味着从该 Agent 的授权选择中移除，保存后生效；不卸载能力所属插件，不修改全局目录，不把已有会话冻结的 Snapshot 改写成新配置。
- 启动方式的单项和批量调整沿用 `placeCapability`，保留精确版本及已有 action allowlist，不扩大未选中能力的权限。
- 资源实例仍在使用 Agent 时选择；配置页面展示所需资源种类，不要求用户输入 UUID 或 JSON。
- UI/API 契约版本由 23 升至 24，避免新 UI 对旧后台发送未支持的完整配置创建请求。

## 尚未接入的能力

本次不扩大上一轮低成本运行时修复范围。尚未实现的高成本能力继续以之前的缺口清单为准。能力库默认只展示可用项，可选择显示暂不可用项以查看原因，但不能添加不可用项。

已配置的不可用项不会被静默丢弃：显示在“待处理”筛选中，用户可逐项或统一移除。官方内置项标为“待接入”，插件/缺失来源项分别解释，不能只更改颜色或状态文案就声称实现已经可执行。

# Agent 工作台交互重构

## 目标与实现

旧页面把全局能力目录直接铺在 Agent 编辑器里。名称、版本、来源、资源要求重复占据列表，用户难以确认当前授权范围，也不能先调整有不可用能力的官方预设再创建个人 Agent。

本次以“先看当前配置，需要时再去能力库挑选”为主线，直接重构现有工作台，继续使用 Arco、IconPark、产品主题变量和 v2 Preset/Revision/Compiler。

| 使用任务 | 交互 |
| --- | --- |
| 找到 Agent | 我的 Agent / 官方预设分栏标签，名称与描述搜索；个人 Agent 保留删除确认 |
| 看清当前范围 | 默认只显示已配置能力；顶部显示总数、启动即用、按需启用、待处理数量，点击即可筛选 |
| 浏览能力 | 按知识与记忆、文件与开发、网页与电脑、协作与设备、创作与内容、业务与自动化、模型能力、技能与扩展分类；列表每页 12 项 |
| 添加能力 | 抽屉式能力库，分类、名称/用途/来源搜索、内置/插件来源筛选；多选后统一添加，默认按需启用 |
| 禁用和移除 | 每项可调整启动方式或禁用并移除；支持选中多项统一切换或移除 |
| 检查详情 | 点击能力名称打开详情；来源、分类、使用时资源要求在详情内；ID、版本、包和贡献数量折叠展示 |
| 调整官方预设 | 直接在预设页面增减能力、调整方式、命名；保存为个人 Agent；可恢复原始预设能力 |
| 编辑个人 Agent | 能力配置、基本设置、技能与扩展、试用与检查分别置于标签页；保存状态和主要操作固定在底部 |
| 处理未保存修改 | 工作台内切换 Agent、新建或打开模型设置前确认；刷新/关闭网页使用 beforeunload 提醒；再次点击当前 Agent 不重载草稿 |

桌面采用双栏和内部滚动，窄窗口采用上下布局，编辑区仍保留内部滚动与底部操作区。长描述在列表中省略，详情中可完整查看。

## 保存语义和架构边界

- 官方种子保持不变。用户编辑的是本地草稿，保存后得到独立的个人 Preset 和初始稳定 Revision，不在官方种子上写用户覆盖数据。
- `POST /api/agent-presets` 的创建请求新增可选 `document`，与 `fork_from_revision` 互斥。原有空白创建和已保存 Revision 复制行为保留。
- 指定完整配置时，后端先补全已有默认聊天模型，再通过现有 canonical compiler 校验并原子创建 Preset/Revision/Snapshot。缺模型、无效能力等失败不会留下空 Preset。
- 自定义副本按用户选择的能力编译，不保留强制恢复官方模板能力范围的来源约束。完整 Coding 范围仍由既有 compiler 的能力推导逻辑选择 Coding profile。
- 禁用在现有契约中意味着从该 Agent 的授权选择中移除，保存后生效；不卸载能力所属插件，不修改全局目录，不把已有会话冻结的 Snapshot 改写成新配置。
- 启动方式的单项和批量调整沿用 `placeCapability`，保留精确版本及已有 action allowlist，不扩大未选中能力的权限。
- 资源实例仍在使用 Agent 时选择；配置页面展示所需资源种类，不要求用户输入 UUID 或 JSON。
- UI/API 契约版本由 23 升至 24，避免新 UI 对旧后台发送未支持的完整配置创建请求。

## 尚未接入的能力

本次不扩大上一轮低成本运行时修复范围。尚未实现的高成本能力继续以之前的缺口清单为准。能力库默认只展示可用项，可选择显示暂不可用项以查看原因，但不能添加不可用项。

已配置的不可用项不会被静默丢弃：显示在“待处理”筛选中，用户可逐项或统一移除。官方内置项标为“待接入”，插件/缺失来源项分别解释，不能只更改颜色或状态文案就声称实现已经可执行。

## 会话选择器修正（2026-09-08）

会话输入框的 Agent 下拉菜单原先把官方条目当作工作台导航链接，导致选择 Agent 必须离开会话页。现改为原地选择，菜单关闭后显示当前名称，重新展开显示勾选；“管理 Agent”单独导航。官方选择与个人 Preset ID 分别保存，支持重新进入页面恢复和 @ 选择，输入、附件及待绑定资源不因选择而清空。

发送时才调用已有模板展开与 AgentSession 创建接口，不在点击菜单时写入 Preset 或创建会话。模板创建请求新增 `reuse_existing`：默认仍为显式复制；会话入口启用复用，查找当前用户拥有且配置相同、具有稳定 Revision/Snapshot 的个人配置。若用户已改过该副本，重新准备原始模板配置，不覆盖个人修改。

默认聊天路由每次查询都会分配新的内部 route/credential 引用，因此复用比较在默认路由场景仅归一化这些引用；服务商、模型、协议、连接、配置摘要、功能、候选顺序及其他配置仍须一致。显式传入的路由保持精确比较。复用准备使用互斥保护，避免并发发送重复创建相同副本。UI/API 契约升级至 25。

这项修正不补齐仍未实现的运行时能力。缺模型、缺能力或服务不可达时，错误留在会话页，输入和选择保留；不会自动改成其他 Agent，也不会静默裁剪模板能力。浏览器可通过同一测试预览的 `#/selector` 复查原地选择。

本次前端全量测试 3274 项通过，后端控制面 22 项通过，类型检查、i18n 检查与生产构建通过。新增测试覆盖原地选择与勾选、首次发送才准备配置、通过冻结会话传递首条消息、失败不导航、并发复用、用户隔离、模型配置比较及个人修改保留。

真实隔离 Router 测试 `official_agent_direct_launch_reuses_configuration_and_creates_sessions` 通过：重复准备返回同一个 Preset/Revision，创建两个不同会话并绑定同一份 Snapshot，数据库仅持久化一份 Revision。本次不调用真实模型服务。

## 会话模型选择修正

移除首页 `isDefaultAgent` 对模型选择器的显示限制。默认、官方和个人 Agent 都保留模型入口，切换 Agent 不清空模型或输入；所有发送方式在发起请求前检查是否已选模型。

模板准备请求和 AgentSession 创建请求接受可选的 `{ provider_id, model }` 产品选择。服务端从当前已启用的 Chat 目录精确解析对应服务商和模型，生成协议、路由和凭据引用；前端不构造这些内部事实。所选模型必须精确匹配，未知或不可用模型返回错误，不退回默认模型。明确选择模型时，冻结的路由不额外附带其他模型作为候选。

个人 Agent 的模型覆盖只影响新会话：服务端保留能力、技能、角色、工作要求和运行配置，编译一份独立的会话配置并按相同配置复用。原 Preset 的稳定版本及已有会话保持不变。内部配置在存储中显式标记 `session_only`，不进入“我的 Agent”列表。Nomi-core 使用追加迁移 `076_agent_session_model_configurations.sql`，原有数据默认标记为非内部配置；独立平台存储在现有显示元数据中保存同一标记。客户端/API 契约升至 26。

新增真实隔离接口测试 `agent_session_model_selection_is_exact_persistent_and_keeps_the_agent_unchanged` 检查 Conversation 模型、冻结路由、原 Agent 不变、内部配置复用与列表隔离，以及未知模型拒绝。前端发送测试验证官方模板与个人 Agent 均发送当前模型身份，原先“只有默认 Agent 显示模型选择器”的断言已改为三类 Agent 均保留入口。

浏览器测试使用实际 Agent/模型选择器组件与独立测试模型目录，已操作官方 Agent → 模型 B → 个人 Agent，并确认模型 B 和输入内容保留。预览路径仍为 `#/selector`；不连接用户模型服务，不把预览视为真实 Tauri 或模型请求验收。

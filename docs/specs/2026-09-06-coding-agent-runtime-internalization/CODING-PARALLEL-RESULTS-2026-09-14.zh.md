# Coding 并行结果收取与模型排列（切片 65，未验证）

## 实现

并行只读批次从 `join_all` 改为 `FuturesUnordered` 逐项收取，不再等待最慢的调用
返回后才处理其他结果。仍须整批都是已冻结、声明 parallel_safe 的 ReadOnly 工具；
每次调用保留原 Session、Snapshot、generation、工具映射与调用 ID，不动态补授权。

每个收取结果先核对索引/调用 ID 和内容结构，然后串行进行已有的 search 路径指令
后处理，最后经生产事件 sink 持久化 `ToolCompleted`。搜索片段仍不能早于其所需
指令检查进入模型或日志。已记录结果不因另一个读取随后失败/取消而丢失。
指令处理或事件存储本身可能等待；本实现不承诺每个原始 owner 返回都立即成为
模型可见结果，也不从取消期间尚未收取的内存结果补造记录。

等待 future 不拥有真实效果生命周期：取消或异常丢弃待收取 future 后，已准入
工作仍由平台 EngineToolHost/EngineTaskGroup 持有，清理和 unknown 隔离照旧。
尚未开始的调用先检查取消；steering 与持久准入检查保持在调用之前。

## 两种顺序必须分开

- `ToolCompleted` 是结果完成处理并被记录的顺序，可以是 B、A。
- 模型上下文仍按原先首次提出的调用顺序排列，如 A、B，不受异步完成快慢影响。
- 新增 Coding 内部事件 `ToolResultsOrdered { step, call_ids }`，仅在全部结果成功
  记录后保存预定模型排列，再将按该排列收集的结果返回主循环。
- 该事件不是模型已经收到结果的确认，不是执行顺序、任务成功或 owner 清理证明。

历史重建分别保留首次 proposal 顺序、实际结果记录顺序和可选模型排列。新事件必须
对应当前非零 model step、完整且未丢弃的批次、最多 64 个唯一原 proposal ID，且
每个 ID 都有真实已记录结果；重复、缺失、跨步、乱序或 finalized 后继续写工具事件
均拒绝。完整的新并行批次按显式模型排列重建；旧日志或中断前未写顺序事件的批次
保留既有结果记录顺序，缺失结果仍按中断规则呈现未知，不执行历史工具。

顺序事件不进入 UI 的新产品概念，现有事件投影只把逐项 ToolCompleted 显示为工具
结果；持久化先于 UI 发布。工具档案仍按实际入档顺序展示，并经过历史结构校验；
不把模型排列当作结果正文或完成证据。

## 兼容与状态

Coding 构建为 `host2-coding-loop65`，Nomi 保持 `host42`。新事件是 Coding codec 的
变化，不修改通用 Engine 端口、授权或注册方式。社区源码若穷举 CodingEngineEvent
需处理新事件并重新编译；未认识该 codec 的旧 exact build 不自动接管新 Session。
不进行数据库迁移、跨构建热切换、原工具重放或第二套历史存储。

只在本地重构分支完成源码实施与局部格式化，按用户要求未运行构建/测试、服务、
模型调用或迁移，未 commit/push。并行快慢、取消、顺序伪造及真实生产回归尚无本轮
执行证据，整体 CAR 目标仍未完成。

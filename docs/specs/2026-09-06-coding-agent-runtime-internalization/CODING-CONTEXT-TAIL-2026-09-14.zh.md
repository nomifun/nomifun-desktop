# Coding 压缩后的近期工具交换保留（slice50，未验证）

所有开发仍在本地 `rf/agent-capability-platform-v2`，未 commit/push。
本轮只阅读和修改源码、局部格式化，没有运行构建、测试、模型/服务请求或迁移。

## 补齐的能力

此前压缩保留接受输入及待处理图片，但普通文本工具结果全部进入派生摘要。
这会使刚读取的代码、精确报错、行号或修改结果失去逐字上下文。
图片交换保留还把所有追加输入放在调用之前，未保留它们相对工具交换的原顺序。

本轮参考本地 Codex `codex-rs/core/src/compact_remote_v2.rs` 的分组和近期优先预算
处理思路，在 Coding 内部增加 `context_tail.rs`，不增加 Agent 身份或平台 owner。

- 选择最后一个 assistant 消息对应的完整工具批次，不从更早批次挑零散结果。
- 最多 64 个调用，与 Coding 单模型步工具批次上限一致；保留原调用顺序、参数、
  provider metadata 和每个结果的内容/失败标记。
- 结果必须完整且唯一地匹配调用。未知 ID、重复 ID、空结果消息、错误角色或
  不完整批次报错；不通过压缩制造成功、占位结果或补执行工具。
- 普通文本交换在序列化后 32 KiB 以内才参与保留；其余还要满足总消息数、字节、
  token 估算预算，以及最终上下文小于压缩前上下文。
- 若普通文本交换不满足预算，继续使用包含该批次的摘要；不会先从摘要源删掉它，
  也不为选择保留方式新增模型请求。该回退不保证逐字细节。
- 待处理图片所在的完整交换继续是强制保留项，不能回退成描述。其预算和必保输入
  在发起摘要请求前检查，不受可选文本的 32 KiB 上限限制。
- slice49 的超限恢复仍要求低于被拒请求估算量的 75%；尾部保留不能放宽此限制。

## 输入顺序与上下文

保留尾部时，接受输入按原有 role/content 从后向前匹配上下文中的有序子序列。
保留重复输入的次数，不按文本集合去重；provider round ID 不参与内容匹配。
匹配到工具批次之前的接受输入独立保留，之后的接受输入随原尾部保留，因此后来的
用户追加仍位于原工具交换之后，而不是被挪到调用之前。找不到接受输入则报错。

这只是已有模型上下文的排列/保留，不是对输入重新授权或发出新回合指令。
尾部中的其他已有用户角色上下文也保留其原顺序；整个替换清除 provider round ID
和 continuation parent。实际工具重新派发仍须通过原有平台准入。

派生摘要说明原工具交换若保留在后面，其精确细节优先于冲突的摘要转述，同时明确
它们是以前的观察，不是本轮重新执行的证据。旧图片专用配对函数已被统一实现替代。

## 持久化与恢复

`ContextCompacted` 增加可缺省的 `retained_tool_call_ids`，记录原批次 ID 顺序：

- 事件本身不复制工具正文、思考内容或图片，平台现有输出裁剪/指令正文隐藏策略不变。
- 正常闭合回合的历史重建，在清除已被摘要覆盖的历史前，核对最新完整交换 ID，
  仅保留已有历史中的那个交换及输入顺序。
- 旧事件没有该字段时保留原来的纯摘要行为。
- 历史工具输出仍可能只有平台保存的有界摘录、图片描述或指令摘要，不声称重建了
  实时原始输出。不会调用工具、读取文件、拉取资源或恢复二进制像素。
- 引用缺失或不匹配则拒绝该历史重建；不会猜测另一批结果。

这不是 checkpoint 自动续跑，也不是未知效果解除。跨重启恢复证明、永久效果凭据
以及完成证据的新鲜度规则均未放宽。

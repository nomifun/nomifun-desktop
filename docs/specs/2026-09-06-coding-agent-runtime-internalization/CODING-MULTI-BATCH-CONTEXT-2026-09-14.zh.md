# Coding：有界多批次工具上下文保留

分支 rf/agent-capability-platform-v2；Coding host2-coding-loop72，Nomi host45 不变。

## 缺口与实现

之前压缩只尝试保留最新一批工具原文。“读取 → 修改 → 诊断”等相邻批次中更早的
细节，即使总预算还有空间，也只能依靠摘要或显式历史检索。这次扩展的是 Coding
自己的上下文策略，不增加平台能力，也不改变 Agent 与 Engine 的职责。

- 从最新完整批次开始，按时间向前最多扩展到三批，总调用数仍不超过 64。
- 每次扩展必须同时满足原有 32 KiB 可选尾部预算、整个请求的 token 估计、
  编码字节、消息数预算，并确实比原请求小。超限保留已能容纳的较新后缀；不
  跳过过大的中间批次，不裁剪工具参数/结果以凑出一个不完整调用。
- 调用/结果全对保留，包括中间响应和 User 消息。已接受输入仍按内容及出现
  次数反向匹配，既不重复插入，也不把工具之后的更正搬到之前。
- 不跨 System/Developer 等权限消息边界；跨历史 turn 的重复调用 ID 会阻止
  向前扩展。最新批次未经过后续模型响应的图片仍必须保留，不用描述替代像素。
- 完整原始模型历史仍是摘要源，扩大原文尾部不增加摘要模型调用。更早或过大
  批次仍依赖摘要及已有显式归档检索，不声称永远保留全部原文。

## 历史恢复

沿用 ContextCompacted.retained_tool_call_ids，记录选中连续后缀的有序调用 ID，
不新增事件字段或重复存储输出。正常恢复必须找到完全相同的有界连续后缀，
不能用缺失历史、重排、跳批或不完整结果凑出匹配；旧单批记录仍可解析。

独立加载一个历史 turn 时，压缩引用可能跨到该 turn 之前，即使压缩发生在它的
执行中。归档验证允许“缺失旧前缀 + 完整本地后缀”，但先检查 64-ID 上限、
唯一性和格式；缺失 ID 不得跟在本地 ID 后，也不能跨过仍可见的本地工具批次。
本地后缀仍精确匹配，不导入或构造旧前缀的结果。仅凭孤立 turn 无法证明旧前缀
的完整性；完整重放不采用这个放宽分支。归档内容仍只来自本 turn 的真实记录。

历史回执本身可能已经是截断文本或图片描述，因此恢复不承诺与当时模型输入
逐字相同，也不把历史观察转换成当前工作区证据或重新执行操作。

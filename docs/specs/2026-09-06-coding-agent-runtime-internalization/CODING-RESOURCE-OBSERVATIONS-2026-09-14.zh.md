# Coding 资源调用与工作区观察边界

日期：2026-09-14。任务：CAR-03 / CAR-06。状态：已写入代码，未验证。
本地分支 rf/agent-capability-platform-v2；Coding host2-coding-loop71，Nomi host45 不变。

## 修复的问题

MCP 资源控制调用原先只让完成报告失效，没有让之前的工作区检查、路径指令缓存
和失败 Patch 的重读义务失效。资源 owner 可以初始化本地 stdio 进程，因此不能
把这条路径视为纯内存读取。另一个缺口是 Patch 目标完全重读之后，后续潜在
副作用不会重新要求读取；批次入口的门禁也看不到同一串行批次中新产生的义务。

## 实现

- remote_resources 将本地参数准备和宿主端口执行分开。无效 JSON、分页字段或
  图片准备条件在本地返回工具错误，不推进工作区观察 epoch。URI/模板成员资格、
  服务端绑定和权限仍由宿主检查；这里不是完整 admission 预演。
- 准备完成后，调用端口之前持久化 PatchRecoveryUpdated 和 WorkStatus，清除
  当前命令证据标记，并令路径指令、完成报告失效。任何持久化失败阻止继续调用。
- 该 epoch 是保守的潜在副作用排序，不是文件版本、实际远端请求或修改成功证明。
  宿主后续拒绝、取消先于 IO 时也可能保留这次失效。不增加成功命令/修改计数。
- PatchRecovery 保留的目标在后续潜在副作用发生前重新变为 pending，即使之前
  已完成重读。串行调用逐项复查 gate；非 Patch 副作用和 process 操作调用前
  持久化重读义务。原有 poll/cancel/close_stdin 清理例外不变。
- 模型可见工具说明解释此边界。不自动重新读文件、重放资源、启动验证或重试。

沿用结果归档和原始提议顺序，不新增事件格式、SDK 权限或 Session 存储。
本切片是现有实现的内部正确性补充，不声称移植了 Codex 的此项算法。

## 边界与未完成项

完全解决的重读义务在跨 turn 恢复时仍不构成永久文件观察库。保守失效也无法
监控任意外部进程未来对工作区的修改；跨 Session/外部编辑协调仍属已有边界。
没有声称资源返回意味着进程静止，实际 owner 的清理、未知结果隔离契约不变。

按用户要求未构建、测试、E2E、启动服务、调用模型或执行迁移，也未 commit/push。
仅源码推理和限定文件格式化；历史通过的检查不覆盖这次改动，整体 CAR 未完成。

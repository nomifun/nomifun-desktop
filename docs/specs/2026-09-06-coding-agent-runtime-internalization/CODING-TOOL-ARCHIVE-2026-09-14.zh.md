具体错误、文件片段或搜索输出。本切片将有限工具文本档案独立于模型窗口维护。

## 新能力

- `ToolArchive` 在初次压缩前，只从宿主已提供的结构化 Assistant call / Tool result
  配对中取数据；重复声明不覆盖来源，未配对结果计入遗漏。随后记录当前回合已返回
  结果，包括因新输入而未执行的提议；不从 User 文本或摘要伪造工具结果。
- `search_tool_history` 按大小写敏感的字面子串搜索保留文本或投影 JSON；空串按
  最新顺序列举。返回 ID、工具名、来源、模型步、原始错误标记、片段和截断提示，
  每页最多 8 项，按 `next_after_id` 继续。不是语义/正则或全库搜索。
- `read_tool_history` 根据搜索 ID 分页返回 JSON 文本片段。ID 摘要包含 Session/
  回合 scope、档案序号和不可变投影，不会在新回合把旧 ID 解释为另一条记录。
- 最多 128 条、4 MiB 计账容量，按最旧记录淘汰；单条保留至多 64 KiB 文本、64 个
  文本 part、8 KiB 完整参数。超长参数整体省略，文本按 UTF-8 截断且保留原长度；
  媒体只记录遗漏数量。文本搜索副本也计入容量。
- 每页 4～8192 UTF-8 字节，默认 4096；序列化后再次 JSON 字符串编码须不超过
  24 KiB。读取 EOF 只表示已读完保留投影，不表示原始结果完整。
- 检索工具单独单调用派发，不与效果/其他控制工具混用；名称不可被平台工具覆盖。
  页面沿用原工具结果事件和模型步预算，档案不递归收录自身搜索/回读结果。

## 引擎与平台边界

这是 Coding 的上下文策略，不要求 Nomi 使用相同方法，也不增加 Agent 能力授权。
读取档案不调用 Kernel、文件、进程或远端资源 owner，不读取数据库/任意路径，
不获得新的执行证据。回读控制不会进入 `work_status.observe` 或 Patch 重新读取
确认；它只能让模型重新理解已观察文本，完成报告仍须依据原有有效证据。

`original_is_error` 在搜索项和每页重复；回读工具自身成功只表示拿到历史页面。
当前平台工具的 `invocation_attempted` 沿用派发跟踪；旧宿主历史缺少该事实时为
null，不推断执行、回滚、清理或任务完成。已淘汰/过期 ID 明确报错，不自动重执行。

隐藏/签名推理、Provider metadata 和结构化图片/音频载荷不入档案。文本仍是不可信
历史数据，不因进入档案升级为指令。档案随当前执行回合释放，不跨 Session 共享。

## 范围与状态

这不是持久化全量 Conversation 搜索：旧回合已被宿主重建/截断/压缩而未提供的
结果无法从本档案恢复。跨回合/重启原文按需读取仍需平台历史端口设计，不能绕过
owner 直接读数据库，也不应为了回读旧状态而重放命令。

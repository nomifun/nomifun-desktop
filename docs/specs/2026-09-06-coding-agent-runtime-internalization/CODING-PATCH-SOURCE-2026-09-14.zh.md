# Patch 显式源版本前置条件

日期：2026-09-14。任务 CAR-05 / CAR-06。代码已写入，未验证。
分支 rf/agent-capability-platform-v2；Coding host2-coding-loop73，Nomi host46。

## 解决的缺口

逐行 hunk 匹配只能发现被匹配部分的变化。此前发布前比较的是“这次准备刚读到
的源字节”，而不是“模型先前阅读并据此规划的版本”。文件其他位置已变化、
hunk 仍匹配时，模型不能表达拒绝这次修改的前置条件。

文件项现在增加 expected_source：

```json
{"kind":"existing","sha256":"这里填写 read_file 返回的完整 64 位小写十六进制摘要"}
```

上例为字段示意，摘要占位文字不是可执行参数。新建且已观察到目标不存在时用
`{"kind":"absent"}`。省略字段或 `{"kind":"any"}` 保留旧逐行匹配语义，不做
调用者源版本检查；不应把它当作有版本保护。null、未知 kind/字段、不合法摘要
不属于契约。existing 不接受不存在的目标，空文件与不存在也严格区分。

## 平台执行边界

1. canonical schema 与 typed serde 约束输入，owner 再检查摘要格式，不能只
   依赖模型按 schema 生成参数。
2. 保持既有工作区授权、路径解析和有界源读取。摘要对原始完整 UTF-8 字节计算，
   包含 BOM、CR/LF 和末尾换行，不是页内容或 hunk 文本的摘要。
3. 每个目标在应用 hunk 前检查源前置条件；所有目标仍在第一笔发布前准备完毕。
   一个条件冲突就返回对应零基 files 索引，没有这次 patch 的已发布文件。
   错误不携带源文本或预期/实际摘要。
4. 发布继续比较准备版本字节、保持创建 no-clobber；条件不会被丢弃后再准备或
   自动重试。已有部分发布、尽力恢复和未知结果记录语义不变。

生产副作用指纹使用重新序列化的 typed request，existing/absent 条件保留其中；
显式 any 与省略字段规范化为相同旧语义。没有新增权限、文件 owner 或引擎存储。
Coding 模型说明优先使用观察到的摘要/不存在，遇到冲突先重新读取、重规划，
不得仅删除条件让重试通过。提示不是防止模型任意选择 any 的独立权限机制。

## 兼容与未解决边界

- 旧 JSON 省略字段继续可用；Rust 源码直接构造 AgentSessionFilePatch 需增加
  expected_source，可使用 Default::default() 保留旧行为。仓库原有构造点已
  机械适配，没有新增测试断言或运行测试。
- canonical schema 和共享 owner 源码变化进入两个官方 Engine 新构建指纹。
  不迁移或热换旧会话，不提供打包后挂载。
- SHA-256 条件不证明模型完整检查了所有页面，也不提供权限。检查后外部原生
  编辑、rename 竞态、跨进程事务仍不由这个条件解决；不承诺线性一致的 CAS。
- 读取新摘要/确认新意图之后可以显式提交新请求，但没有自动刷新摘要、隐式
  降级到 any、模糊定位或重放副作用。

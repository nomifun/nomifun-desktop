# Coding 持久化工具历史按需加载（切片 62，未验证）

## 本次实现

Coding 新增内部控制工具 `load_tool_history`，每次读取同一 Session 的一个旧回合，
再通过已有 `search_tool_history` / `read_tool_history` 搜索和分页读取工具结果。
它补齐了仅靠初始模型窗口无法取回更早持久化结果的缺口，不是数据库全文索引。
无需执行原工具；应用重启后，仍须成功打开原 exact binding 的 Session 才能加载。

- 平台公共 `EngineSessionHost::read_history_before` 接收 admitted receipt、1～32
  回合预算及可选旧回合 operation ID。SQL 在同一读事务内核对用户、Session 和
  当前 root 截止位置，拒绝外部 Session、当前/未来或不存在的游标。
- 平台先查字节数再取正文，保留每回合最多 4096 条事件、8 MiB 事件数据和每窗口
  16 MiB 的现有上限；日志序号必须连续。平台不解释 Coding 事件或执行历史工具。
- Coding 的可选 `CodingHistoryPort` 接收平台受限结果；生产适配器传入取消令牌，
  校验 Session/turn/root/snapshot，只解析正文、附件描述及自身事件，不加载旧媒体。
- 导入要求 exact EngineBinding、回合身份及完整结构校验。仅从真实记录的调用和
  `ToolCompleted` 提取结果，不导入中断重建产生的未知占位结果。
- 单回合校验允许首次模型调用前的压缩引用未提供的更早前缀；只检查这些引用的
  有界唯一身份，不声称已核对缺失前缀。正常完整上下文重建的检查不变。
- 先校验再构造候选档案，全部成功后替换；失败不留下部分导入或淘汰。搜索/分页
  重复呈现 `source_turn`、原始错误和截断信息，历史 attempted 状态保持未知。
- 保留 128 条/4 MiB 档案上限，以及额外最多 64 个有界来源回合 ID 的去重索引。
  最近已加载回合再次请求返回 `already_loaded`，不会重复挤占档案。被淘汰的内容
  不因此复原；来源离开去重索引后可再次导入。搜索顺序是入档顺序倒序，不是假称
  跨回合执行时间倒序。
- 控制工具必须单独调用，不能与效果工具混合；不触发工具 owner、不产生当前
  work_status、Patch 重读或完成/清理证明，控制结果也不会递归收进工具档案。

## 架构与兼容性

Agent 仍选择 Engine，Session 冻结构建与权限。平台拥有历史数据和访问边界，Engine
拥有何时加载、如何解释、压缩和检索的策略。社区 Engine 可用相同原始分页接口，
无需采用 Coding 编解码器或工具名称；源码接入后重新编译打包，不允许打包后挂载。

Coding 构建标识更新为 `host2-coding-loop62`；共享历史端口进入 Nomi 构建摘要，
Nomi 更新为 `host40`，未给 Nomi 强行加入 Coding 的历史控制工具。无数据库迁移，
不自动升级既有 exact Session，也不静默回退到另一引擎。

沿用既有 Codex 固定源码基线及 ContextManager 的“模型窗口与保留事实分离”原则；
不改变源码基线、不引入 Guardian 或 Codex 专属存储。旧输出在持久化前已经截断的
部分不能恢复；原媒体、私有推理和 provider 元数据不会从档案重建。

## 未覆盖与验证状态

不支持跨 Session/Fork 父会话扫描、历史全文搜索、旧协议自动迁移或自动恢复执行。
首个候选回合超预算、日志缺行或无法解析时只报读取失败；没有用于绕过损坏/超大
记录的元数据扫描接口。可解析但 exact binding/结构不兼容的回合返回拒绝和有界
来源游标，允许明确向前翻页，不把缺失记录解释为没有执行。

本次仅源码实施和局部格式化。按用户要求未运行构建、测试、E2E、服务、模型调用
或数据库迁移，未 commit/push。历史验证结果不覆盖这些更改；整体 CAR 尚未完成。

## 设计依据与归属

参考本地 Codex `codex-rs/core/src/agents_md.rs` 的环境文件系统端口、根目录到 cwd
指令层次，以及真实 I/O 错误与文件缺失的区分。没有复制 Codex 的权限系统或会话 owner。
Nomifun 使用 Session 已绑定工作区作为边界，不向工作区之外追溯项目根。

- FileService 负责权限、规范路径和有界元数据读取，不决定 Engine 的执行计划。
- Coding 负责何时发现目录规则、暂停调用、替换上下文、重新规划和使完成报告失效。
- 社区 Engine 可使用同一 `fs.read` 平台能力，自行决定任务循环和上下文策略。
- Agent 的能力授权不变；未选择 `fs.read` 时不隐式添加读取权限。
- Engine 仍只允许源码/依赖集成后重新打包注册，不增加动态挂载入口。

## 已写入的能力

`fs.read(format="instruction_scope", path=".")` 返回工作区根的规范路径、目标类型和待读
指令目录；文件/缺失目标返回父目录，目录目标包含自身。`recursive=true` 额外发现子树内
的 AGENTS.md/AGENTS.override.md 所在目录。这里只返回元数据，指令正文继续走有权读取、
摘要关联的完整文本分页接口。

平台遍历包含隐藏/忽略目录，限制 20,000 项、5 秒检查预算、32 层、2,048 个待处理目录、
64 个指令目录及序列化结果大小。两个并发扫描许可由阻塞任务持有，调用方取消等待不会
提前释放扫描配额。子符号链接、不完整读取、深度/数量/时间耗尽均不能报告 complete。
Windows 指令文件名识别兼顾大小写；目录别名在规范路径检查处拒绝或显式报告。

Coding 在显式文件读写、patch、目录删除/暂存、搜索根及 process cwd 前发现作用域。
删除/暂存和显式递归检查会扫描子树；普通搜索不隐式扫描全部隐藏依赖。
引擎检查响应的路径、类型、递归标志、目录归属与完整性，再加载根到各目录的指令。
同批路径的递归要求取并集，不能被另一条非递归调用覆盖。别名导致整批延后，提示真实
工作区路径；不静默修改工具参数，也不把规范路径当成新增授权。

操作后保留已知目录重新读取，并重扫已登记的递归范围；因此被删除的规则会退出上下文，
新出现的子目录规则会进入下一轮。只读调用或能力激活时提前更新的规则，也通过实际模型
指令槽比较使 provider parent 和旧完成报告失效，不只依赖“发生写操作”的 dirty 标记。

文本专用 `missing_ok=true` 仅对 owner 确认的缺失返回 `workspace_file_absent`；拒绝访问、
权限异常及其他工具错误不再靠错误字符串猜成缺失。指令页核对确切路径和分页版本。
共享 Wave2 schema、Coding 工具说明和两个官方构建指纹已同步。

## 仍然明确保留的边界

- 任意 shell 脚本的实际访问路径无法靠 cwd 或命令文本可靠推断。工具指导要求模型先检查
  计划访问的范围，但这不是操作系统级文件访问拦截，不能宣称覆盖了任意动态 shell。
- 搜索只自动加载搜索根层次；命中条目的指令在后续明确读取/修改目标时加载。搜索结果本身
  不证明所有被扫描文件的指令都已阅读。
- 递归范围太大、有链接或不可读项会失败，需要缩小目标；不会跳过问题并宣称完整。
- 这里没有文件系统快照、写锁、并发重命名的原子隔离或任务语义完成证明。
- 工具/指令读取仍受宿主既有回合预算约束，没有为扫描提高副作用/日志上限。
- 跨启动进程证明、人工解隔离、checkpoint 续跑、其他协议及生态生命周期尚未完成。

整体 CAR 仍在实施中；历史测试结果不覆盖本切片。

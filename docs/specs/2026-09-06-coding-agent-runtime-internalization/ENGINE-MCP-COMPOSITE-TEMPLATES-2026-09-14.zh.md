# MCP 复合模板变量（切片 63，未验证）

## 实现范围

共享 MCP resource 端口不再限制模板变量只能是字符串。官方 Nomi/Coding 和源码
集成的社区 Engine 可以提交字符串、字符串列表和字符串值字典。URI 展开仍由
平台 MCP owner 完成；Engine 不获得 URL 抓取、文件访问或额外工具调用权限。

`EngineResourceQuery::ReadMcpResourceTemplate` 与 `McpResourceOperation::ReadTemplate`
的 variables 由 `BTreeMap<String, String>` 改为 `BTreeMap<String, serde_json::Value>`。
JSON 字符串请求格式保持兼容；Rust 构造调用者须改为 JSON 值并重新编译打包。
允许的值类型由平台在任何连接/持久效果占位之前检查，不进行类型强转：null、数字、
布尔、混合列表和嵌套集合均拒绝。

两个官方 Engine 使用同一 `mcp_template_variables_schema()`，避免模型入口参数
说明漂移。社区 Engine 可以复用它，但 schema 本身不构成授权或替代 owner 校验。

## 展开规则

沿用 RFC6570 操作符及编码策略，补齐列表/字典的 `*` explode 与非 explode 形式。
列表保留输入顺序；字典按原始键排序，避免 JSON map 编译 feature 改变展开顺序。
不伪称模板参数展开代表服务端接受了某个资源。

以下为设计语义示例，不是测试运行结果（列表为 `["a", "b"]`，字典为
`{"x":"1", "y":""}`）：

| 表达式 | 预期展开片段 |
|---|---|
| `{?list}` | `?list=a,b` |
| `{?list*}` | `?list=a&list=b` |
| `{/list*}` | `/a/b` |
| `{?map*}` | `?x=1&y=` |
| `{;map*}` | `;x=1;y` |
| `{map*}` | `x=1,y=` |

空列表/字典当作未定义变量省略，不产生多余表达式前缀；空字符串保留“已定义”
语义，包含空字符串的列表也不是空集合。`:n` 前缀只允许字符串且继续拒绝已含 `%`
的输入，避免切断编码序列；复合值即使为空，也不允许使用字符串前缀修饰符。
未知变量、非法模板、控制字符和不合法的最终绝对 URI 仍拒绝。

## 预算和效果边界

- 最多 64 个变量；变量名最长 256 字节；模板与最终 URI 各最多 4096 UTF-8 字节。
- 变量名、字典键及字符串值合计最多 4096 UTF-8 字节。
- 最多 256 个叶字符串，字典的键和值分别计数；因此单个字典最多 128 对。
- 输出在逐片段追加时检查上限，空集合名称也计入输入预算；不会因展开复合值
  放宽原有连接、读取、64 次回合调用和结果分页预算。
- 共享 `validate_page` 首先进行纯本地 owner 模板校验，Nomi 在平台 activation
  之前调用它，Coding 在注册资源任务/派发日志之前调用它。底层 owner 仍再次校验。
- exact server 的当前会话目录仍须存在完全一致的 uri_template，随后才发送
  `resources/read`；没有通配 URI 匹配、客户端 URL 抓取、自动重试或效果重放。
- 请求摘要和分页摘要包含原始参数结构及服务器身份；改变列表、字典或目标不能
  沿用旧分页摘要。返回/拒绝与未知效果隔离、任务回收和持久收据逻辑保持不变。

## 构建与剩余工作

Coding 更新为 `host2-coding-loop63`，Nomi 为 `host41`；两个构建摘要已覆盖修改的
共享契约和 owner 源码。仍只允许编译期注册和整体应用打包；旧 Session 不热换构建。
无数据库迁移，不将旧 scalar 收据自动升级成当前会话的执行许可。

MCP 二进制资源、订阅及服务端发起的 user/model/workspace 授权生命周期尚未完成；
Git 网络凭据、跨重启未知进程处置和其他 CAR 缺口不因本切片而关闭。

整体目标仍未完成，也没有以历史测试结果代替本次验证。

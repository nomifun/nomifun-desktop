## 本次借鉴与实现

继续参考指定的本地 Codex：`codex-rs/core/src/agents_md.rs` 的工作区层级/override
规则，以及 `compact.rs` / `session/turn.rs` 的初始上下文保留、轮次内压缩和后续执行。
仍然是 NomiFun 所有权边界内的重新实现，不依赖 Codex 可执行文件或动态挂载。

- **进程执行**：生产 Coding initial 能力集合增加 `process.exec`。仅在 Agent 已授权
  独立 `process_session.execute` 资源时暴露；不从文件权限推导执行权限。宿主将根目录
  绑定到当前 Conversation 的服务端工作区，再经 Kernel/Wave2 复用现有 PTY 进程 owner。
  已启动调用继续由 `JoinedTools` 持有，等待退出/超时收尾；取消不表示回滚，也不声称
  已支持立即中断正在执行的命令。非零退出成为错误工具结果，而不是成功执行反馈。
- **仓库指令**：轮次入口经已授权 `fs.read` 读取工作区根 AGENTS；同层优先
  `AGENTS.override.md`，有文件/总字节上限，读取事件可追踪。没有 read 授权就不绕过
  Kernel 读取。生产工作目录当前为根目录；嵌套目录指令仍要求模型在修改前主动检查，
  不能称为完整的路径感知自动注入。读取失败/截断的警告进入 `context_prepared`。
- **模型窗口预算**：从已保存精确 route 的主模型及候补模型能力记录读取窗口/输出
  限制，取共同可承受范围。没有窗口声明时使用 32768 的显式开发默认值；没有实际
  tokenizer 保证。每次调用前用保守字节估计和已观测 usage 校正，并预留输出空间。
- **自动压缩**：裁剪历史前以及每个已完成工具批次之后检查压力；有界地把历史数据
  分块摘要，保留原用户要求、Agent/仓库指令和工具定义。压缩请求不执行工具，拥有
  独立 operation id，复用原会话调用领取，记录压缩 usage。每轮最多 32 次摘要调用，
  开始前检查剩余调用预算；过大输入、摘要失败或不能缩小到安全范围时明确失败。
  全部摘要成功且新上下文满足预算后才替换模型视图，并记录 `context_compacted`。
- **执行反馈**：记录文件变更、成功/失败命令和工具错误。结束前最多一次完成证据
  提醒，让模型继续被授权工作或明确报告阻塞/未验证。该提醒不授权执行测试；用户
  禁止验证时应直接说明未验证。命令 exit=0 不等于测试通过。这是观察反馈循环，
  不是已经完成的独立 planner/replanner。
- **正常重开**：对有完整 engine 事件的关闭轮次，重建结构化 tool call/result，
  重放压缩摘要和完成提醒，而不是把工具 JSON 一律扁平化。只读重建，不重执行工具。
  最近最多 32 轮，每轮最多 4096 事件，总读取内容最多 8MiB；缺少事件的旧/Fork 历史
  保留旧的有界文本投影。缺少模型可见结果时明确标记未知副作用，不虚构成功或回滚。
- **精确身份**：同一轮拒绝重用模型 tool-call id 和内部指令读取保留前缀，避免重复
  操作领取。新构建名为 `<app-version>-host2-coding-loop1`，开发指纹纳入新增算法模块。

1. 真正独立的任务计划状态机、失败分类/重规划算法及完成标准契约；当前只有策略提示
   与结构化观察反馈，不以此宣称优于 Nomi。

   on-demand、Skills/MCP/MiniApp 与附件接入。
3. 异常重启终态证明和 checkpoint 恢复。运行中孤儿仍隔离，不能用正常重放解除隔离。
4. 全量历史分页 SDK、摘要质量、token 估算校准、工具结果保真，以及边界/行为测试。
   本轮改变模型调用次数与自动指令读取行为，既有 fixture/断言需随验收更新。
5. 应用升级旧构建保留/迁移。旧 `host1` Session 不自动改成新 build；当前应用若不含
   原构建，旧会话执行会明确拒绝。源码指纹不是完整发行制品证明。

只有实际编码任务的可重复收益才能证明专用 Coding engine 的优势。本轮不提供
通过率、性能分数或“已优于 Nomi/Codex”的结论。

# Coding 搜索命中指令上下文（2026-09-14，未验证）

## 范围与设计

补齐 CAR-05 / CAR-06：搜索根目录的规则不代表所有命中文件的规则。借鉴本地
Codex `codex-rs/core/gpt_5_2_prompt.md` 的目录作用域/深层指令优先约定，Coding
现在在 `fs.search` 结果进入模型上下文之前，通过现有授权 `fs.read` 端口发现并加载
每个命中文件的指令层级。没有导入 Codex 的 Session、Provider 或文件权限体系。

这是 Coding 自己的上下文/执行循环策略，不是平台统一规划器；Nomi 和源码集成社区
Engine 可以采用自己的策略。注册仍限二次开发编译打包，不增加安装、热挂载或同会话
切换入口。本轮 Coding 为 `host2-coding-loop37`，Nomi 保持 `host20`。

## 已写入源码的行为

- 只接受单个有界 JSON 文本结果，严格解码 canonical search 字段；核对原 query、
  limit、搜索根路径、规范命中路径、匹配片段/字节列/SHA-256 和结果预算。任意工具
  文本或媒体不能变成隐式指令读取请求。
- 对去重后的文件做非递归 `instruction_scope` 观察；要求仍是相同规范路径的文件。
  命中路径已经消失、变为目录或产生别名时不改写调用参数、不猜测旧片段的规则。
- 加载 root 到命中目录的 AGENTS 层级，继续遵守 override 存在优先、深层规则优先、
  64 个已知目录、16 KiB/文件、24 KiB/层级、48 KiB/合并上下文与读取次数预算。
  同次刷新复用祖先读取；不递归扫描整个仓库，不跨刷新复用过期缓存。
- 搜索不完整与指令发现不完整分开处理：合法的截断搜索保留已返回命中及其原始
  incomplete 信息；空命中不暗示仓库范围不存在。不能完整加载命中规则时，返回
  `search_context_withheld` 模型结果，明确搜索已执行、片段暂未提供，不冒充回滚。
- 不授予缺少的 `fs.read`，不直接访问原生文件系统。选中但未激活时提示走既有能力
  激活路径；无法读取或超预算时提示缩小目标/修复读取条件。
- 串行调用发现新规则或片段被暂扣后，剩余尚未执行调用推迟到新模型轮次。只读并行
  调用全部结算后、任何模型结果发布前处理命中规则。已有指令槽比较负责使规划、
  完成 review 与 Provider continuation 失效。
- InstructionsUpdated 成功持久化后再更新内存层级；事件写入失败和取消继续向上传播，
  不当作可忽略的 AGENTS 读取警告。指令读取同样不再静默丢弃非文本结果部件。

## 历史与边界

平台 host_tool_settled 保留真实执行事实；Coding ToolCompleted 保存模型可见投影。
现有 Coding history 明确过滤 host 工具记录，仅从引擎 ToolCompleted 重放模型结果，
不会通过 host 原始搜索回执重新提供被暂扣片段。内部指令读取 step=0 不变成模型工具
交换，InstructionsUpdated 作为历史观察而非下一回合新鲜权限。

路径发现和规则读取不是文件锁或原子快照；源码 SHA-256 仍是搜索时的历史版本，
并不证明后续读取时内容未变化。外部改名/编辑竞态、不透明 shell 内路径访问、跨 Session
写协调、任务语义正确性与独立需求抽取仍不由本切片解决。其他 MCP/生态生命周期和
人工未知效果解除等剩余项仍在 TASK-MANIFEST 中，整体 CAR 未完成。

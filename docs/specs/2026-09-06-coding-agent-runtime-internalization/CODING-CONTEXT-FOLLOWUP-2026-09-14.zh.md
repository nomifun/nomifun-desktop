# Coding 续接/复核后的完整工具尾部（slice57，未验证）

分支 `rf/agent-capability-platform-v2`，Coding 构建身份 `host2-coding-loop57`，Nomi
保持 `host38`。本轮没有构建、测试、模型请求、服务、迁移、commit 或 push。

## 缺口

slice50 的 recent tool exchange 仅检查最后一个 assistant 消息。工具结果后出现
普通回答、完成复核回答或 slice54 的部分回答时，最后一个 assistant 不含调用，
保留逻辑直接返回 None。压缩仍有摘要，但刚取得的错误细节、文件片段等原文无法
进入已有的有界保留路径。

本地 Codex `core/src/compact.rs` 在上下文超限分支中优先裁剪旧历史以保留近期消息。
本轮沿用“近期上下文优先”的思路；完整批次核对、32 KiB 尾部预算以及下面的保留
协议是 NomiFun Coding 的策略，不声称是 Codex 的同款实现。

## 实现边界

- 从后向前定位最近包含 ToolCall 的 assistant 批次，不再被普通 assistant 回答
  遮住。保留范围包括这批调用、完整结果和其后的非工具回答、用户补充/引擎说明。
- 必须一一匹配调用与结果，调用最多 64 个；不完整结果之前不得出现 assistant
  后续回答，后续回答之后不能又出现工具结果。矛盾、重复、错序仍失败，不向前
  搜索更老的“看起来完整”的批次来掩盖最近的坏序列。
- 接受输入继续按反向子序列匹配保留顺序和重复次数；在批次后的输入不前移。
  只有实际匹配的 accepted inputs 豁免可选尾部预算，而不是豁免所有 User role。
  引擎复核/续接说明同样使用 User role，现在会与工具结果、后续回答一起计入
  32 KiB 的可选尾部预算，且仍必须满足整份请求的 token/字节/消息数限制。
- 最近结果含图片且尚无后续 assistant 响应时，原图仍为强制保留状态。已有后续
  响应表示上下文经过了后续模型边界，不等于模型理解了图片或完成了验证；该尾部
  可按预算选择原文保留，否则使用全量源摘要/附件描述。未追加任何图片重读行为。
- 压缩预检现同时校验必需消息数量，并预留一条摘要消息；最终替换也检查消息数。
  必需输入/图片超过该限制时，在发送摘要请求前失败，不让后续通用 assembler
  通过再次截断消息去“修好”已完成的压缩结果。
- ContextCompacted 仍只引用原调用 ID，历史使用相同的尾部定位/配对算法，保留
  后续消息的原顺序；不重复执行工具，不重新加载历史媒体，不增加秘密推理持久化。

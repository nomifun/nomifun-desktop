中间批次修补成已完成观察，也不能因模型参数流的完成顺序不同而重排工具结果。

NomiFun 的现有 Conversation journal、精确 Binding 和平台恢复凭据。

## 源码改动

- `replay_closed_turn` 在临时投影上重建，所有事件处理成功后才替换调用者上下文；
  后续事件报错不留下半截追加或半截压缩结果。不写数据库、不执行工具。
- 要求唯一回合起点、唯一末尾终态，模型步从 1 连续增长；模型文本、用量和工具
  事件必须归属活跃的模型步。step=0 只允许保留前缀的内部指令调用，并继续排除
  在模型历史之外，不能用该通道绕过模型调用身份检查。
- 跨模型步禁止复用旧 call ID；单批次保持最多 64 个提议；重复完成、重复准入或
  重复结果拒绝，不再用后一个结果覆盖前一个。工具准入必须有已完成的调用声明，
  模型流事件不能出现在同一步的工具准入/结果之后。
- 进入下一模型步、完成复核、压缩或普通完成终态前，当前提议、完整调用和结果
  必须配对。只有 Failed/Cancelled 的最后一批允许缺失结果，并保留明确的未知
  观察，绝不推断未执行、回滚或可安全重试；半截参数不恢复成工具调用。
- 宿主 SDK 可因取消、丢弃 driver future 或 panic 写入零步的 Failed/Cancelled；
  这是该层未知步数，不是“没有模型调用”的证据。正数中断计数及普通完成计数
  必须与 journal 一致，零步中断仍从实际事件重建已有模型步骤。
- 按 ToolCompleted 的持久化发布顺序恢复真实结果。模型参数流可交错结束，
  ToolCallCompleted 顺序并不总是执行或结果发布顺序；不再用它重排实际结果。
  最后中断批次缺失的观察单独附后；不从任何顺序推断并行副作用发生顺序。

# Agent 命令与会话可靠性：聚焦执行计划

更新：2026-10-01。用户明确收敛目的：减少真实会话中由NomiFun自身导致的命令、步骤、过程状态和结果错误。
本计划替代此前按675共享Case＋82 Windows专属Case、五角色全功能矩阵推进本轮的排程。
原目录、首败、修复及验证记录保留；移出本轮的条目不记PASS。

## 1. 本轮交付目标

业务命令正常启动后返回非零是合法结果，不要求业务命令永远成功。UI应显示命令已结束、
退出码及可展开输出；参数预检拒绝应显示未执行，真正的调度/执行/清理故障仍明确展示。
不把上述结果统称为“操作出现异常”，不删除历史失败或把非零结果改成成功。

正式 Tauri 会话优先使用已有加密 StepFun Coding Plan / step-3.7-flash 配置：

- 第一次正确选择本机命令和工具，正确传递command/args或显式shell/script、cwd及特殊路径。
- 步骤按用户要求执行，命令、读写、检查和后续纠正能连续衔接。
- 过程区如实显示执行、非零、失败、等待、取消和完成，结果准确回配调用。
- 最终回答与exit code、stdout/stderr、磁盘字节/hash和canonical记录一致。
- 停止/取消后不继续新副作用；完成效果不被重放，旧Turn不复活。

通用和编程是本轮实际命令入口，两者各有正式样本。共同根因只核对一次，
不再把每个底层断言乘以五角色、两OS、全部业务Action。

## 6. 执行与结案

1. 每批一个问题簇或少量相关断言，边测、排查、修复；UI场景使用正式Tauri及隔离data/work/profile。
2. 实际模型优先已有加密StepFun配置，先设小型任务/调用上限。缺夹具只阻断相应场景。
3. 核对首次/修后结果、可见错误、真实副作用、API/UI/canonical终态、清理和交付；不扩权限、吞错或放宽断言。
4. 只运行直接相关检查；复用自动证据与新产品运行分开，移出/手测/未验均不记PASS。
5. 三组场景及GEN/COD关键入口达标、核心bad-case根因闭环后，单独通知共享命令链路达标；
   再补其中尚缺的Windows命令/native断言并阶段收尾，不回到82条全业务队列。
6. 完整日志/DB/截图/事件/模型轨迹在仓库外；Git只收必要源码、最小回归、简短进度。
7. 每批核对staged，使用配置Git身份commit+push；正常同步远端，不force或覆盖他人工作。

## 3. 执行顺序与交付门槛

当前接续优先级按用户 2026-09-28 的要求调整：先推进全部 675 个共享 Case 的公共修复及本机验证，
相关 Windows 原生问题一起处理；共享阶段达到验收门槛后明确通知，并提供 macOS 并行验证/修复
接续 prompt，随后推进 Windows 专属 82 项。macOS 原生验证仍需对应宿主，组件结果不代替完整 Case。

1. **共享 P0**：先完成 S-P0-01～05。P0 使用目录 §24 的“静态清单、Schema、边界”口径；
   发现运行时高影响缺陷时补最小确定性反例，不把一次静态检查当完整 Case PASS。
2. **提交共享批次**：处理与远端的重叠，保留已验证修复；检查 staged 路径、diff 和必要合同产物，
   按配置 Git 身份 commit，并正常 push 当前跟踪分支。禁止 force push、重写共享历史。
3. **共享后续 S-D01～11**：继续 675 个共享 Case 的公共实现与本机验收，关联 Windows 原生
   问题一并修复。每批先测试现状，首次失败单独保留；修复后重跑原反例和相邻负向。
4. **macOS M01～M06**：由原生 macOS 执行者接续，导入已有报告作为历史证据；
   本 Windows 宿主不执行或代判 macOS 原生结果。
5. **Windows 专属余项**：共享阶段结算后，继续 W01～W06 中 82 个 Windows 专属 Case 的剩余验收。
6. **长稳与发布**：D09/LONG、重复命令、跨重启及统计验收放在功能和故障边界稳定之后；
   仍须满足原目录与 README 的样本及 99% 统计条件。

各批次的最小闭环：Case 子断言/适用 Agent → 首次结果 → 问题 owner → 修复 → 定向回归 →
未覆盖断言/平台 → 下一任务。禁止以修复后成功覆盖旧 FAIL。

## 4. 精简进度与证据规则

- 三个进度文档固定文件名，按领域/问题簇更新一行；不逐次追加完整运行记录，不展开 4,740 行状态表。
- Git 只收生产代码、必要回归、必需合同生成物和简短进度；不收 DB、JSONL 事件、截图、模型正文、
  完整 stdout/stderr、provider 工具面快照、凭据、逐槽复制的环境信息。
- 完整证据写到仓库外：Windows `%USERPROFILE%/code/temp/nomifun-agent-reliability/phase-2-3/`；
  macOS `~/code/temp/nomifun-agent-reliability/phase-2-3/`。层级为日期/lane/batch/run。
- 文档只记命令、Case 子断言、简短结果、代码提交/构建身份、相对证据路径与必要摘要；输出重定向到外部文件。
- 本机历史归档 `archive/2026-09-26-phase2-generated` 只作追溯，不复制回 Git。
- `待走查/进行中/发现问题/已修待回归/已验证/阻断` 是**任务状态**；仅全部验收断言满足时才写 Case PASS。
  “P0 已验证”“组件已验证”“历史报告导入”均不折算为产品验收通过率。
- 每批至多维护一份简短摘要；Case 的只读清单/计数校验可临时生成在外部目录，不提交派生索引。
- 外部模型只在需要证明产品行为时调用；先冻结该批预算/资源，UI 单写者，不运行无关媒体任务。

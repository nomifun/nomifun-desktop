# 小程序(Mini-Apps)— 应用内程序能力设计规格

日期:2026-08-09
状态:设计定稿,随码实施
范围:会话启动页创建能力、会话右侧预览、固化持久化、左侧边栏库页面 — Rust 后端 + SQLite + WebUI/Tauri 前端

## 1. 背景与目标

NomiFun 的会话已经能生成任意网页产物,但产物困在会话工作区里:下次要用只能翻
历史会话或重新生成。本设计引入「小程序」:**AI 生成的单文件自包含网页小工具,
一次固化,随开随用**。

产品闭环:

1. **创建** — 会话启动页(`/guid`)composer 入口条新增「创建小程序」能力。用户
   点选后 composer 进入小程序模式,输入诉求并发送,即以内置「小程序构建模式」
   系统提示词创建一个 Nomi 会话。
2. **生成与预览** — AI 在会话工作区生成单文件 `miniapp.html`。会话内容区右侧
   预览面板(与文件预览同位)新增 `miniapp` 预览类型,以沙箱 iframe 实时渲染,
   文件每次被改写自动刷新。
3. **迭代** — 用户不满意就继续对话(调整需求/重新生成),预览随之更新;废弃
   即关闭标签,不留任何持久数据。
4. **固化** — 满意后点预览工具栏「固化为小程序」,输入名称/描述/图标,HTML
   全文入库。同一会话再次固化可选「更新」或「另存为新」。
5. **复用** — 左侧边栏「小程序」入口 → `/mini-apps` 库页面(卡片网格),点击
   即在 `/mini-apps/:id` 全页运行 — HTML 由后端直出,实时渲染加载,无需再生成。

## 2. 关键决策

| # | 决策点 | 结论 |
|---|--------|------|
| D1 | 小程序形态 | **单文件自包含 HTML**(内联 CSS/JS,允许 CDN 引第三方库);多文件工程留待后续 |
| D2 | 固化存储 | HTML 全文**内联存 SQLite**(`miniapps.html` TEXT);不落 `{data_dir}` 子目录,免去路径守卫/备份注册 |
| D3 | 运行渲染 | 免认证 `GET /api/miniapps/{miniapp_id}/serve` 直出 `text/html`,iframe `src` 加载(文档不出 JSON;sandbox 不给 `allow-same-origin`,origin 保持 opaque,存储 API 可能不可用);安全性依赖不可猜测的 UUIDv7(workshop 公共文件路由既有先例) |
| D4 | 生成引擎 | 小程序模式**固定走 Nomi 引擎**(`extra.system_prompt` 注入构建指令,该字段后端不剥离且随会话持久化);ACP 引擎留待后续 |
| D5 | 会话标记 | 创建时写 `extra.miniapp: true`(唯一标记;产物路径是契约常量,不重复写进 `extra`),会话界面据此启用自动预览与固化工具栏 |
| D6 | 迭代/废弃 | 固化前的重新生成=继续对话;废弃=不固化,无需任何后端状态 |
| D7 | 契约版本 | 新增 HTTP 路由 + DTO → `ui-api-contract-version.txt` 16 → 17,同一提交内 `bun run build:ui` |

## 3. 数据模型

迁移 `crates/backend/nomifun-db/migrations/028_miniapps.sql`(表头注释风格照抄
`024_ssh_hosts.sql`):

```sql
CREATE TABLE miniapps (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  miniapp_id TEXT NOT NULL UNIQUE,        -- 裸小写 UUIDv7,4 条 GLOB/长度/小写 CHECK
  user_id TEXT NOT NULL,                  -- 同上 CHECK,属主隔离
  name TEXT NOT NULL,
  description TEXT NOT NULL DEFAULT '',
  icon TEXT,                              -- 可选,emoji 或短文本
  html TEXT NOT NULL,                     -- 自包含 HTML 全文
  source_conversation_id TEXT,            -- 可空;来源会话逻辑引用
  created_at INTEGER NOT NULL,            -- ms epoch
  updated_at INTEGER NOT NULL
);
CREATE INDEX idx_miniapps_user_id ON miniapps(user_id);
CREATE INDEX idx_miniapps_source_conversation_id ON miniapps(source_conversation_id);
```

配套注册(缺一项启动即失败):`id_schema_contract.rs` 的 `PRODUCT_TABLES`、两处
`UUIDV7_BUSINESS_COLUMNS`、`text_ref!`(`user_id → users` 沿用 ssh_hosts 策略;
`source_conversation_id → conversations` 选择删除会话后小程序存续的策略,可空引用
参照既有可空 `text_ref!` 先例)。ID 类型:`define_entity_id!(MiniAppId)`。

## 4. HTTP 契约(wire 一律 snake_case,请求 `deny_unknown_fields`)

新域 crate `crates/backend/nomifun-miniapp`(布局 `lib/dto/service/routes/state`,
照抄 `nomifun-ssh`)。

认证路由(`protect_instance_owner` 包裹,merge 进认证链):

| 方法/路径 | 请求 | 响应 `data` |
|---|---|---|
| `GET /api/miniapps` | — | `MiniAppResponse[]`(按 `updated_at` 降序) |
| `POST /api/miniapps` | `{ name, description?, icon?, html, source_conversation_id? }` | `MiniAppResponse` |
| `GET /api/miniapps/{miniapp_id}` | — | `MiniAppResponse` |
| `PUT /api/miniapps/{miniapp_id}` | `{ name?, description?, icon?, html? }`(至少一项) | `MiniAppResponse` |
| `DELETE /api/miniapps/{miniapp_id}` | — | `true` |

`MiniAppResponse = { miniapp_id, name, description, icon, source_conversation_id,
html_size, created_at, updated_at }` — **列表与详情均不含 `html` 全文**(运行走
serve;`html_size` 字节数供 UI 展示)。校验:`name` 非空 ≤ 100 字符;`html` 非空
≤ 4 MiB;`source_conversation_id` 若给出必须是合法 UUIDv7。

免认证路由(post-CSRF 组,handler **绝不提取 `Extension<CurrentUser>`**,模块注释
照抄 workshop `routes.rs:73-82` 的理由):

- `GET /api/miniapps/{miniapp_id}/serve` → `200 text/html; charset=utf-8`,
  `Cache-Control: private, no-cache`。未命中 404。

iframe 嵌入:`crates/backend/nomifun-auth/src/security.rs` 的 `allows_embedding()`
增加 `/api/miniapps/` 前缀且 `/serve` 结尾的路径,否则 `X-Frame-Options: DENY`
会拦死预览与运行。

WS 事件:v1 不新增(列表页用 SWR 拉取即可)。

## 5. 前端

### 5.1 契约主干(集成前置,先于各工作流落地)

- `ui/src/common/types/ids.ts`:tag 联合加 `'miniapp'`,`MiniAppId`、`parseMiniAppId`。
- `ui/src/common/adapter/ipcBridge.ts`:新增 `miniapps` 段(`IApiMiniApp` /
  create/update 请求形状 / `fromApiMiniApp` 品牌化映射 / `list get create update

- `ui/src/renderer/pages/miniApps/contract.ts`:`MINI_APP_FILE_NAME = 'miniapp.html'`、
  构建模式系统提示词 `MINI_APP_BUILDER_SYSTEM_PROMPT`、`isMiniAppConversation(extra)`、
  `resolveMiniAppServeUrl(id)`(基于 `getBaseUrl()`)。
- i18n 命名空间 `miniApps`(zh-CN 与 en-US 对称,注册进两侧 `locales/*/index.ts`,
  `bun run gen:i18n`)。

### 5.2 预览(`miniapp` 类型)

- `PreviewContentType` 加 `'miniapp'`(`ui/src/common/types/office/preview.ts`);
  `fileUtils.ts` 的 `FILE_EXTENSION_MAP` 补穷举键(`[]`,类型只显式打开);
  `PreviewContext.tsx` fallback 标题;**不进** `PERSISTABLE_CONTENT_TYPES`(重开
  会话由自动预览钩子恢复);`usePreviewLauncher` 将 `miniapp` 与截断隔离(截断的
  应用就是坏应用)。Rust 侧 `PreviewContentType` 枚举不动(该类型不跨 wire)。
- `MiniAppViewer`(`Preview/components/viewers/`):以 `HTMLRenderer` 为基底 —
  iframe `srcDoc` + `sandbox='allow-scripts allow-forms allow-popups
  allow-modals'`(**有意不同于** `HTMLRenderer` 的历史策略:`allow-scripts` +
  `allow-same-origin` 同时给出等于取消沙箱,AI 生成的文档必须是 opaque origin);
  渲染文档在 `content` 静默 ~1200ms 后才推进(避免 agent 迭代时不停重载、抹掉
  运行中应用的状态),手动刷新立即取最新并重挂;去打字动画、去资源内联(D1 自
  包含);工具栏经
  `usePreviewToolbarExtras` портал(照抄 `PDFViewer.tsx:34-76` 模式):左侧
  「小程序预览」标签,右侧「刷新」(重挂 iframe)与「固化为小程序」。
- 固化按钮:点击时以 `ipcBridge.fs.readFile` 读最新文件内容;查
  `miniapps.list` 中 `source_conversation_id === 当前会话` 的既有项,存在则弹窗
  提供「更新」/「另存为新」,否则名称/描述/图标表单直接创建。成功 Message 提示
  已入侧边栏「小程序」。
- 自动预览钩子 `useAutoPreviewMiniApp`:挂在会话预览 Provider 之下(参照
  `useAutoPreviewOfficeFiles` 的挂载点),仅当 `isMiniAppConversation`;订阅
  `ipcBridge.conversation.turnCompleted` 过滤本会话 + 首次挂载各触发一次探测:
  文件存在(`fs.getFileMetadata`)→ `launchPreview({ relativePath:
  MINI_APP_FILE_NAME, contentType: 'miniapp' })`,`findPreviewTab` 去重;已开
  标签由既有 `fileStream.contentUpdate` 订阅 + 1s mtime 轮询保持新鲜。

### 5.3 启动页「创建小程序」

- `ComposerEntryStrip` 增加「创建小程序」入口(激活态 token 可关闭,复用
  active-preset token 模式);激活时 composer placeholder 换为小程序引导文案。
- `GuidPage` 持有 `miniAppMode` 状态;发送时该模式走专用分支
  `useMiniAppQuickStart` —— `useNomiQuickStart` 的**薄封装**(后者接受可选
  `model` / `extra` / `name`,创建 → 历史刷新 → 首条消息交接 → 导航只此一份):
  `extra: { workspace: 选中目录, custom_workspace, default_files: 暂存附件,
  system_prompt: MINI_APP_BUILDER_SYSTEM_PROMPT, miniapp:true }`;model 取
  `GuidPage` 自己那个 `useGuidModelSelection` 实例(第二个实例看不到用户的选择)。
  发送有同步 ref 去重,成功后与常规路径一样清空输入/附件/目录/mention。
- 小程序模式与 AutoWork 入口互斥:AutoWork 武装时隐藏入口并强制退出小程序模式。
- 支持 `/guid?miniapp=1`(HashRouter query)激活模式 — 库页面空态 CTA 用;query
  用后即从 URL 剥离,这也是防重入的唯一机制。

构建模式系统提示词(注入 `extra.system_prompt`,即 Nomi 引擎 `custom` 段):

```
[NomiFun 小程序构建模式]
你正在为用户构建一个「小程序」— 独立、自包含的网页小工具。规则:
1. 产物永远是工作区根目录下的单个文件 miniapp.html,用文件工具创建与修改它。
2. miniapp.html 必须完全自包含:内联全部 CSS 与 JavaScript;需要第三方库时可
   经 CDN 引入;不得依赖工作区内其他文件。
3. 界面追求现代、美观、可即时上手;无需任何构建步骤。
4. 需要持久化数据时优先使用 localStorage,键名加应用专属前缀;但沙箱可能禁用
   存储,所有存储读写必须包在 try/catch 里并在失败时优雅降级,核心功能不得依赖
   持久化。
5. 每一轮回复结束时 miniapp.html 都必须是完整可运行的版本:首轮直接给出可用
   版本,之后按用户反馈迭代。
6. 除非用户明确要求,不创建其他文件;回复里简述改动即可,不要粘贴大段代码。
```

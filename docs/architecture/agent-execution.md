# Agent Execution and collaboration

AgentExecution is the domain aggregate for one goal. AgentSession remains the sole authority for Sessions, Turns, events, content, effects and cancellation. Execution composes the current Runtime; it does not implement another model/tool loop, transcript or completion contract. See [Agent Session](agent-session.md) and the [Chinese execution architecture](agent-execution.zh.md).

## Lifecycle constraints

U01–U13 remain implementation and product constraints. The [lifecycle validation record](../validation/agent-lifecycle.zh.md) separates tested builds from platform gaps. These constraints do not add Agent admission requirements.

| ID | Stable constraint |
| --- | --- |
| U01 | Repair the original owner, admission and handoff failure; changing display state, hiding errors or stacking business retries is insufficient. |
| U02 | Reuse Session, Execution, TaskTracker, native Supervisors and existing outboxes; add no platform Broker, generic lifecycle platform or second ledger. |
| U03 | Preserve tools, permissions, model selection, arbitrary shells, shared workspaces, background/long tasks and explicit settings. Supporting every pause/force-stop mode is not an admission requirement. |
| U04 | Preserve user concurrency and explicit tool deadlines. Add no fixed machine quotas, universal task TTLs or resource-pressure, idle or wait-duration task killing. |
| U05 | Require no worktrees, resource/path declarations, read-only downgrade or extra resource selection. Arbitrary shell side effects cannot be fully inferred. |
| U06 | Parent Turn completion, model return or foreground navigation does not revoke authorized delegation; cancellation follows the actual authorized scope. |
| U07 | Caches cannot start, resume, retry, send original inputs, create Attempts or execute tools. Loading failure grants no replay authority. |
| U08 | Preserve necessary live state during waiting, pause, recovery and unknown effects. Idle, Finished, checkpoints and active counts do not prove safe retirement. |
| U09 | Every Agent has host-side User Stop and visible cleanup progress, including exceptional states. Stop cannot wait for the model, Steer or ordinary business FIFO. |
| U10 | Keep local task, delegated ownership, DAG dependencies and whole-Execution control distinct. Old controls cannot target successors; recovery or derivation cannot bypass a stopped scope. |
| U11 | Continuing the original Turn is distinct from retrying a new Attempt. Cancel-plus-retry cannot impersonate continuation or reset progress, effects or budgets; legitimate explicit budget changes and retry policies remain. |
| U12 | Users see tasks, waiting reasons, Stop and actual cleanup state. Owner, generation and checkpoint checks do not add ordinary setup or confirmation requirements. |
| U13 | Heavy resources without remaining responsibility retire without closing history. Actual Quit closes app-owned resources, with native parent-death coverage for crashes, while preserving user browsers, shared services, legitimate writers and persistent data. |

## Ownership

`AgentExecutionEngine` is the public facade. The Planner produces a DAG, the Router assigns Participants, the private Scheduler manages readiness, leases and concurrency, and AttemptRunner executes each Attempt through the existing Session owner. Other domains use facade commands or narrow read guards rather than updating execution state directly.

| Record | Responsibility |
| --- | --- |
| AgentExecution | Goal, policies, version and lifecycle |
| Participant | Immutable Agent/model snapshot available to this execution |
| Step / Dependency | Work unit and blocker-to-blocked DAG |
| Attempt | Actual dispatch configuration, operation identity and result |
| ConversationExecutionLink | Explicit Session-to-Execution/Step/Attempt relation |
| ExecutionEvent | Durable state, decision and audit facts |
| AgentExecutionTemplate | Reusable creation input, captured once when instantiated |

An active Execution never rereads a mutable template. Template edits or deletion do not change an existing snapshot. Delegation within an Attempt appends Steps atomically to the same aggregate, reusing its Participants, policies, Scheduler and lifecycle. It does not create nested execution aggregates. Domain events reference Session facts without replacing model, tool or Effect evidence.

Each admitted Step has an exact host-side job retained by the existing lifecycle `TaskTracker`, from its reservation through Attempt settlement or an acknowledged handoff. The scheduling loop observes completion notifications; polling its `FuturesUnordered` is not what runs the job. Losing that observer, pausing dispatch or changing scheduler generation cannot drop an input, a returned outcome or the responsibility to settle it. Registration precedes the queued writer; the original reservation version proves ownership during the short interval before the created Attempt ID is bound. A successor scheduler may assign its confirmed lease to that same job, without invoking the business operation again. The registry is a live-owner observation, not another persistent execution ledger.

Lease observation distinguishes `Confirmed`, `Unconfirmed` and `Fenced`. A renewal error or missing acknowledgement is `Unconfirmed`, not proof that another owner took over. New dispatch waits while the original owner retains its jobs and rereads the actual lease owner and expiry. A committed renewal whose reply was lost can be confirmed from those facts. A different owner, deleted aggregate or terminal authority fences the old generation. Every admission and settlement still passes the original writer's lease and version checks; retained work never grants an expired lease new authority.

Before runner preparation, the Queued Attempt retains its complete original `SendMessageRequest` in the existing `InitialInput` outbox. The initial operation key derives from the immutable Attempt ID. Preparation proves that exact queued reservation and its Session opening or continuation; it preserves the original content, origin, visibility and channel, and may add the original authorized frozen files and Skills without removing prior selections. A typed temporary storage error or pending admission retains the same job, Attempt, Session and creation key even before linking; it is neither an Agent failure nor permission to discard and recreate the Session. `on_linked` commits the exact child link, prepared input and Attempt transition together; it means the Session is linked, not that input was accepted or a model started. The canonical input writer checks the same source lease, link, Step/Attempt versions and pending input in the transaction that accepts that exact operation and acknowledges the original queue head. A read before that transaction cannot authorize startup. No template, current brief or latest Session input may reconstruct the original pending intent.

Execution events are durable before publication. Business admission, linking and settlement notify the existing publication owner and do not wait for unrelated UI/WebSocket delivery. Explicit publication barriers remain available where observation ordering requires them.

## Policies and concurrency

The top-level policies remain independent:

| Policy | Meaning |
| --- | --- |
| `delegation_policy` | Disabled, automatic or prefer parallel |
| `decision_policy` | Automatic decisions or ask the user |
| `adaptation_policy` | Fixed plan or bounded retry, reassignment and replanning |

A free-form Step role is descriptive. The typed tool policy only narrows the inherited Session authority; a role cannot grant tools. Each Attempt records the effective configuration. Model pools and the current lead/template selection are validated together; a bounded pool must contain its lead.

The shared bounds are defined in [agent_execution.rs](../../crates/backend/nomifun-common/src/agent_execution.rs): 16 models, 64 current Participants, 128 current Steps, parallelism up to 64, and delegation depth up to four. Historical revisions do not count as current work and cannot be deleted to satisfy limits. Templates use the same executable bounds.

Ready children may run concurrently under the user's `max_parallel`, Participant limits, actual dependencies and native reservations. `Full` or `ReadShell` no longer makes a complete Step an exclusive workspace lock. The tool policy remains an authority ceiling; parallelism cannot silently replace Full with ReadOnly and remove selected capabilities. Exact file, process, Browser, Computer and Effect owners continue to enforce their own operation and settlement rules.

One Session still admits one model Turn at a time. Independent child Sessions can execute together. Model capacity is separate from real resource ownership: an exact InputRequired terminal or native child-wait proof can yield a model slot, but display status, checkpoint presence, idle state and cache eviction do not prove resource release. Computation must pass the original writer's capacity fence before resuming.

## Children and the original parent Turn

`agent/delegate` with `strategy=parallel` materializes a bounded `tasks` array as ordinary independent Agent roots. `strategy=planned` asks the current Planner to derive the goal's real dependency DAG. The retired `synthesize` switch is rejected. Explicit synthesis Steps and templates remain ordinary supported DAG work; a hidden automatically appended child does not replace parent integration.

The acceptance receipt retains `execution_id` and any committed `step_ids`. A new execution can still be planning, so its Step IDs may appear through subsequent status reads. Acceptance proves neither startup nor completion. Explicit collaboration intent preserves the parent's complete frozen ToolPlan and does not force every model step to delegate. Already accepted work must not be resubmitted under fresh call IDs. Recovery reuses the original Effect and domain idempotency facts. Later work from the same source Turn and delegation within an Attempt remain in the original Execution, with ownership from the exact Effect and `PlanChanged` facts rather than names, directories or inferred DAG ancestry.

A required initial delegation is derived from the current canonical human-intake event and admitted source, including its producer, owner, command namespace and message identity. A client `origin`, child role or parent brief cannot declare that requirement, and a Host continuation does not renew it by repeating the original text. Interpreting a Step envelope separately requires an existing verified Execution source scope and internal input. This only selects task text: children retain their complete tools, explicit nested delegation, useful further division, concurrency settings and parallel preferences.

The parent can continue independent work before joining children:

- `agent_status` reads work belonging to the exact source Session and Turn, optionally selecting precise Steps. Result bodies and artifacts come from the existing canonical output reader with Execution, Step, Attempt, child Session, Turn and terminal-event references. UI summaries and child prose are not integration evidence.
- `agent_message` sends an idempotent message to an owned Step through the existing Step and Session command path. It cannot address unrelated work or widen permissions.
- `agent_wait` waits for all selected child work or a new actionable state. It records typed `AwaitingChildren` and paired `ChildrenWaitResolved` observations within the original Turn.

Guidance, explicit question replies and `task_control` have distinct typed intents. `question_reply` pins the returned child Session, Turn, Question Event and request ID. Admission checks the original parent command, ownership, binding, clear boundary and current question, then reuses that Attempt's DecisionInput outbox. The Host derives formal `reply_to` from the original question and retains parent-Agent provenance, without impersonating a human or granting consent. `task_control` uses the existing Engine commands for exact-Step recheck, retry, Stop or replacement with a verified completed Step. It retains the source-owned scope, expected versions, immutable command digest and original receipt. Human consent, unknown effects, Stop and stale sources remain fenced. Ordinary command races return structured tool errors so the parent can continue coordinating; corrupt canonical sources remain fatal. A lost write acknowledgement is resolved through the original command receipt without resending under another key.

An accepted answer waiting for capacity is no longer an unanswered question. Pending delivery remains a wait condition. An unanswered question or unresolved review is presented through its exact decision identity, rather than repeatedly waking the model for the same state. The parent's native wait can release its original model slot so the same outbox can advance, without changing user concurrency settings.

The wait checkpoint retains the original operation, model steps, budget accounting, plan, settled tool observations and wait selection. Recovery reattaches the wait instead of spawning children again or renewing model budgets. A wake is a data observation, not a fabricated human input or completion proof; the parent reads canonical status and integrates the results. Ordinary queued inputs retain FIFO, while explicit steering joins at the original safe boundary. Stop fences reject late wakes without selecting a successor Turn.

Waiting uses committed-change notifications for the exact owner/Execution and input notifications for the original Turn, registering before reading state. Unrelated Executions do not wake that wait. A 30-second fallback compares batched domain and relevant Session native revisions. Unchanged revisions reuse cached content; changes load narrow snapshots and incrementally merge minimal source/control/settlement proof entries. Scoped read-only owner checks independently verify whether original work can still advance, even without a new domain event. Waiting does not hydrate Participant Snapshots, launch configuration or complete startup DTOs. Result bodies remain with the canonical output reader for status delivery. Subscriptions, cursors and caches are rebuildable observations, not execution, ownership or delivery authorities.

Domain cancellation can precede actual native closure. Successful exact cancellation and cleanup acknowledgement notify existing owner/Execution observers to reread the original facts even after the domain outcome was published. These hints create no domain event, model polling or business retry. Sparse cursor checks still cover lost notifications.

Initial wait admission, an acknowledged wait and pure `agent_status` reads retain the original Turn and use cancellable backoff on typed `PoolTimedOut` or SQLite `Busy`/`Locked`. A read retry adds no model steps, resets no budget, redelegates no child and never retries an `agent_message` write command automatically. Corruption, I/O, closed pools, missing facts and permission errors retain their original failure handling. Notifications and restored availability do not consume results; complete paged consumption and original durable receipts remain the delivery authority.

Database diagnostics observe admission, acquired and finished phases at existing read-snapshot and writer-admission boundaries, with sparse slow-operation logs and pool size/idle counts. They install no SQLx acquire/release hooks, call no SQLite APIs for diagnostics, change no connection health or task state, and create no diagnostic fact ledger.

Explicit `agent_wait`, automatic waiting and recovered waiting share the latest successfully observed cursor for each selected Execution. Omitting `after_cursor` cannot discard that existing watermark. An explicit cursor must belong to the selected scope; cursors from another Execution, Step or body page grant no authority. At most 64 Execution references form a canonical cursor of at most 16 KiB. Source observations cover the complete owned headers, including Attempt/admission, terminal, question, review, control and formal replacement identities, independently of body selection. Changing one Step invalidates only its changed source and result-page coverage. Selecting scopes in a different combination does not make a consumed, unchanged source new again. State and ready-source digests are separate: a reduction of already-presented ready sources only advances the local subscription, without `ChildrenWaitResolved` or another model step. Original build/checkpoint fences still govern recovery.

New real questions, review decisions and a scheduler pause wake the parent once through their original fact identities. Presenting a decision does not resolve it: resolution still requires the original accepted control or verified facts. When already-presented decisions or Running work have no exact Step job, accepted input, native owner or dispatch owner able to advance them, waiting returns typed `decision_blocked` and the Runtime parks for technical reconciliation instead of repeatedly sampling the model or waiting without an owner. A dispatch owner must have actual dispatchable work; a loop merely retaining a review is insufficient. This is distinct from user Pause and from a real pending input, and creates no human question. If planning formally fails or is cancelled before any Step exists, status returns the original aggregate terminal receipt: an empty set is neither success nor a reason to wait forever. Controller-domain outcomes and ordinary Agent canonical Turn output retain their separate source readers.

Result bodies use UTF-8 byte pages of at most 32 KiB. `result_page` pins the immutable Attempt/native terminal source, the complete body's SHA-256 and length, and exact offsets. A response with no remaining body budget returns an explicit unread first-page reference; it never reports truncated text as a complete result. The parent consumes a terminal child only after contiguous coverage from zero through the complete original body. Reading only its final page is insufficient. The native checkpoint retains bounded source/digest/coverage references, with bodies remaining in their original canonical events. Full ownership and wake cursors do not change when selecting another body page.

An exact child result also reports whether that Turn's workspace effects or native process commands may have changed the workspace. Partial or unknown effects invalidate previous observations; only the process owner's exact typed pre-I/O rejection can exclude an unexecuted command. Each new immutable source advances the parent's work epoch and invalidates previous completion evidence and scoped-instruction observations once. Repeated reads of the same result do not repeatedly invalidate them. Tool policy and unrelated Execution event growth are not mutation evidence.

`workspace_change_sources` covers every original Attempt and its exact initial/question/decision Turns, independently of the current result body. A newer zero-start cancelled Attempt cannot erase an earlier writer. A business-terminal Agent whose original native Turn is still running remains in the `delivery_pending` wait state and is excluded from consumable terminal IDs. An exact closed native receipt or durable domain admission fence plus proven absence of that exact Turn resolves delivery; `started_at`, a guessed latest Turn and display cancellation cannot prove zero startup. Native result closure remains distinct from heavy resource cleanup.

Child waiting is distinct from user Pause, InputRequired and process waiting. Yielding model capacity does not close real resources or erase pending/unknown effects. Queries, notifications, cache hydration and an idle Session do not authorize new work or replay a closed Turn.

Each ChildAttempt creates its own Session and Runtime from the exact immutable Snapshot, model and typed resource bindings, then applies its explicit Attempt ceiling. It does not inherit the parent's temporary schema window. Attachments and explicit Skill selections from the original accepted input and steering actually applied before delegation pass through exact source/Effect/Turn/owner checks into ordinary child input preparation. Skills must remain in the child Snapshot and media must satisfy its real model/resource constraints. The child retains its own Step spec; original user constraints are source data, not another copied transcript or a permission grant.

An explicit followup reuses the original child's Session and verified frozen binding while preserving its prior canonical history. Its `message_source.command_event_id` points to the actual native `ToolCallCompleted` proposal. Delegation ownership stays with the original source; input preparation reads the followup sender's exact accepted Turn and only steering applied before that command. It neither reinjects the first delegation's selections nor chooses the latest input. Messages to running children resolve these same selections through the original StepChanged event, target Attempt and command. Initial dispatch, running guidance and completed-child continuation all retain selected files and Skills through canonical input preparation. A direct UI followup without model-source input metadata retains its own input and does not borrow old selections. Reader and writer share the immutable command, target, content digest and idempotency binding proof; current native-epoch checks govern new command admission separately.

After explicit steering joins the parent Turn, question answers and recording handoffs read the original input of the last typed SteeringInputs actually applied before the current tool's cause. They use the original Turn input only when no such steering exists. Queued inputs and inputs arriving after the command cannot authorize that answer, question presentation or recording handoff.

Robot child-question notices and actual playback share a transaction-scoped source-authority check. New notices cite the original delegation's real Returned Effect terminal event, allowing the coordinating parent Turn to remain active. A running source must still be the exact active Turn and pass domain admission; existing canonical notices from completed source Turns retain their genuine terminal proof. The Store's original accepted-input and Effect readers supply the sole fact validation. Current binding, clear floor, device, connection, exact pending Step/Attempt and playback writer lease continue to govern delivery; cancellation or an expired presentation cannot authorize replay.

## Results and public delivery

Normal settlement, restart recovery and explicit adoption use [canonical_output.rs](../../crates/backend/nomifun-agent-execution/src/canonical_output.rs). The reader resolves the exact Turn's event window and terminal output in one transaction. Artifacts must come from settled file or publication receipts with verified root, path, length and digest. Directory scans, UI messages and model claims cannot establish them. Later changes to the same path are interpreted in event order.

A Step spec is task input. The sole Runtime owns typed requirements, completion and delivery. The Scheduler does not infer a second acceptance gate from natural-language file names, formats or counts. Exact canonical results are available independently of abbreviated UI summaries.

Source delegation produces no `lead_report_operation_id` or suppressed-delivery acknowledgement. Its committed changes wake the original observer; only exact receipts and complete result consumption prove delivery, and neither grants resume authority. Real reports for non-source Executions and source question notices retain their existing contracts. The original Session owner supervises interrupted parent settlement from canonical facts; `source_continuation` cannot start a replacement parent or background synthesizer. An admitted child retains its independent lifecycle and results when the parent fails. Safe continuation still requires the original nonterminal Turn, control/effect proof, exact build, unchanged budget and existing capacity admission.

One scheduler job's failed handoff or observation returns to its exact Step/Attempt receipt owner without draining all sibling jobs first. Its original reservation still counts against user concurrency settings while healthy jobs, ready Steps, independent controls and Stop progress. Recovery reconciles the original facts through one reducer. A Queued reservation keeps the same Attempt and frozen input. If the exact input is provably not admitted, the writer fences the old sender before allowing delivery of that original pending input under its original key. An ongoing Turn is observed; a terminal Turn contributes its original output. A terminal fact committed after the first read causes a fresh exact read, not a fabricated missing-output review. Missing original intent, genuinely unknown effects or unproved ownership remain review-blocked. Recheck verifies those original facts; it does not invoke business work. A failed observation or entering the runner alone authorizes neither replay nor a new Attempt.

For source-authored delegation, the parent Turn reads child results, integrates and verifies them, and publishes its ordinary Runtime answer. No independent background-report writer publishes a child's output as the parent's final answer, and no hidden user message starts a second result-model pipeline. Robot and Channel delivery retain the original input, binding and connection authority. Direct user-created Executions without a tool source retain their idempotent public-summary projection. AutoWork's root still executes in its original lead Session, avoiding duplicate public output.

A later parent failure or parent-only stop does not revoke a Returned delegation with verified original causation. Children remain subject to their Step, delegated-work, whole-Execution and native admission fences. Real human-input handoffs continue task authority and result references only through verified, decreasing `reply_to` ancestry with the exact terminal question, current binding and clear floor. An unrelated new Turn gains no general authority over old collaboration.

Deleting an already consumed Execution does not turn its old consumption index into a live prerequisite for a later human reply. Pending deleted work still requires its original source proof; the parent can observe only the exact original `Deleted` event and persisted terminal status as user revocation with outputs unavailable. That receipt resolves the pending handoff without declaring child success, restoring ordinary reads, sending guidance, or reopening scheduling. Missing, foreign or damaged deletion evidence remains an error.

`request_user_input` normally closes the child Turn with InputRequired; that does not complete its Step. Questions retain their exact DecisionRequested and presentation identities. Background process output, exit or timeout cannot replace a human answer or reopen model work. The real answer passes through the canonical Session and domain admission path.

The active parent can receive real physical-entry followups as steering and publish an intermediate reply while keeping its original child wait. A task-question answer reads the original input actually applied before that exact tool's canonical cause; it retains that recording's presentation ID, socket and accepted sequence. It cannot borrow the initial request, an unapplied queue item or a later presentation as answer authority.

### Child restart and pause handoff

The child **Restart task** control calls `POST /api/agent-executions/{execution_id}/steps/{step_id}/restart`. Its immutable key, Execution/Step versions and original Attempt identify one command. Existing `restart_requested` and `restart_resolved` events distinguish acceptance from outcome and supply cold recovery. A lifecycle owner retains that exact responsibility across disconnected observers and lost acknowledgements. The UI keeps only unconfirmed request drafts; neither a projection nor a second execution ledger owns restart.

Typed technical suspension carries its original pause/checkpoint identity, reason and cleanup evidence into the Step review. An authenticated user Restart may continue the same Attempt/Turn through native resume. The original command, real User actor, frozen fence/checkpoint, Stop, unknown-effect and capacity checks apply under both the direct and queued authorization writers. Parent-agent management cannot mint a human native resume grant. User Pause retains its explicit Continue control; continuation adds no budget and replays no settled effect.

A fresh execution first cancels only the original Attempt and obtains its exact native closure and existing cleanup acknowledgement, then readmits that same logical Step. Restart does not reuse the permanent task Stop fence or reset unrelated siblings/DAG descendants. Queued reservations keep their original input and key; an original Attempt that already advanced is confirmed from its own facts instead of endlessly conflicting with a cached observation. Unknown effects, changed targets and dependencies requiring explicit replanning produce a durable blocked resolution. Later task Stop/replacement wins. Ownership stays with the logical Step, and restart never creates a hidden parent turn.

InitialInput acknowledges admission: the writer verifies the exact accepted/started pair, immutable key, full input and causality before removing only that intent. The original Turn still owns business completion; later Steer/Stop is no longer held behind a terminal-dependent input ACK. A parent receives each native decision and new failed Restart receipt once. A verified human Restart boundary keeps the original parent Turn's external-control subscription; passive observers never count as business producers. Successful acceptance and later domain projection do not repeat model calls. The original parent consumes and integrates the child's eventual result. Other boundaries without a valid control route or producer retain `decision_blocked` parking.

## Lifecycle, controls and retirement

Planning, running, paused, waiting-input and terminal states use the Engine state machine and optimistic versions. Each dispatch rechecks dependencies, Step version, active Attempts and retry time under the admission writer. One Execution has one active scheduling loop.

Execution Pause stops new dispatch. Already admitted Attempts retain their Sessions, Turns, links, reservations and original runtime owners for observation and settlement, including across scheduler takeover. A paused scheduler with live retained jobs but no local completion observer parks rather than repeatedly polling an empty notification stream. Pause neither freezes native operations nor fabricates review failures or cancellation. Resume does not replay completed Attempts or settled effects. Native Turn pause/checkpoint/resume remains a separate exact-owner contract.

Late receipts cannot reopen a terminal result. Explicit retry, adopt, add or replan commands require their original version/state fences; a cancelled scope cannot be reopened. A permitted retry keeps the same Execution and logical Step, creates a new Attempt and child Session link, and preserves previous results and effect evidence. Source ownership belongs to that Step, so the verified original parent can manage its current Attempt. An accepted guidance, reply or stop target stays fixed to its original Attempt and operation; a late old command cannot silently select the retry's Session. DAG dependencies describe work ordering and do not grant delegation ownership.

Recheck, continuation, retry and replacement are separate decisions. Recheck only reads and reconciles the original Attempt. Continuation needs its exact live Turn and accepted input. Retry requires the original unknown-effect and version guards. Replacement with an existing completed Step verifies that Step's canonical delivery and commits the replacement relation and allowed downstream dependency changes in the original plan writer. Merely adding another successful Step does not discharge the old obligation. Other completed Steps, original outcomes and cleanup responsibilities remain intact. Restart follows the original lease, Attempt and receipt; missing or unknown outcomes never authorize automatic business retries.

Step stop selects `task`, `delegated_work` or `task_and_delegated` explicitly. Ownership comes from the original caller Step/Attempt and committed `added_step_ids`, not DAG edges. The original writer commits the cancellation fence before signaling the exact owner. An empty `delegated_work` selection can fence future derivation, but it has not stopped the selected task and must be presented as such. Ordinary control FIFO cannot delay User Stop. Unrelated siblings may finish, while cancelled scopes cannot dispatch, retry or delegate again. Whole-Execution cancellation remains an explicitly different command. Cancellation acceptance alone proves neither native closure nor safe release of unknown effects.

Durable initial inputs, question answers, Steer and StopTurn use their existing Attempt write-ahead effects. The original owner retains delivery through observer loss and confirms only the exact original command. A durable pending item alone is not Session custody or input acceptance: admission, its commit and callbacks must remain owned through the exact Session acknowledgement. Only after that acknowledgement may shutdown close pure outcome observation; it leaves the original input, outbox and settlement responsibility intact rather than cancelling admission or inventing a terminal result. Slow controls do not block other Attempts' settlement or a direct user stop. Canonical Turn cancellation settles its exact Attempt/Step without being promoted to aggregate cancellation.

Runtime retirement requires the actual original cleanup witness. An inactive Link, terminal-looking status, missing owner/cache entry or checkpoint is insufficient. Background processes, user Browser state, legitimate writebacks and unknown effects keep their real owners. Cleanup retries release original resources without rerunning Agent work. History is not a permanent runtime reference.

An Attempt-created Session that has not yet linked is not automatically disposable. Its original owner and creation receipt, a durable terminal or superseded domain disposition, and the absence of any Link, input, Turn or Effect must be checked in the same canonical deletion writer. A lost lease can leave a successor preparing the same Queued Attempt; cleanup retains that reservation until its domain disposition or real link arrives. The Session lifecycle owner acknowledges responsibility early enough for the runner to report its error, then retains cleanup through caller loss and transient database failures. This acknowledgement does not declare deletion or business success. Startup discovers outstanding pre-fence cleanup from the original Attempt and opening; after fencing it uses ordinary `deleting` recovery. No additional ledger or business retry is introduced.

AutoWork cancellation also fences its exact Requirement claim generation, execution creation and dispatch. Restart may finish the already-authorized cancellation from those facts, never choose another claim or manufacture an Attempt. Accepted cancellation, actual stop and confirmed resource retirement remain separate observations.

## Activity and process presentation

The activity API aggregates existing Session, Step/Attempt, Cron, AutoWork, Remote and resource-owner facts. Reads and polling never acquire a Runtime or start work. Stop commands route exact captured targets to their domain owners; a transient stop-all snapshot is not a second execution ledger. Single task, delegated ownership, DAG dependencies and whole Execution remain distinct scopes.

The shared chat timeline displays accepted delegation and real Step terminal records. An accepted Step is not proof of startup; an Attempt ending, retry, loop or parent Turn ending is not Step completion. Adjacent records from the same original request/tool Effect and semantic kind may compact in presentation, while every record retains its exact identity and navigation target. Historical terminal entries pin the original Attempt; current-task control requires an explicit selection.

`GET /api/conversations/{session}/delegation-records` reads source-owned Execution events within the loaded accepted-input window. Session and Execution sequences are never compared across streams. Pagination pins original event bounds, and asynchronous completion does not require another parent message. Opening a record cannot start, resume or retry an Agent.

## IDMM and validation

[IDMM](../../crates/backend/nomifun-idmm/src/lib.rs) reads bounded verified observations through its Session port. It owns no Runtime, Session or tool authority. Rule or explicitly configured side-model decisions retain the exact source question; credentials, payment, destructive choices and ordinary permissions cannot be auto-approved through that route. Failed parsing and stale questions preserve failure/wait state rather than creating arbitrary input.

Targeted execution validation covers real overlap, dependency joins, parent integration, repeated proposals, version races, exact cancellation, native child-wait recovery, budgets, pending/unknown effects, question continuation and resource retirement. Run `bun run check:agent-session-boundary`; Session content changes also run affected canonical history, reset and consumer tests. Controlled local model fixtures do not establish real-provider, device or other-platform support.

# 定时任务

定时任务在 NomiFun 宿主运行且电脑唤醒时，按计划向 canonical AgentSession 提交任务。Agent、模型、工具和资源沿用普通会话的同一执行架构。

> 需要尽快执行的一次性后台工作，请参见 [AutoWork](./autowork-requirements.zh.md)。

## 创建任务

打开 `/scheduled`，点击新建任务，填写名称、执行指令和频率。

- **执行 Agent**：从 Agent 工作台的官方 Agent 或个人预设中选择，默认通用 Agent（`assistant.general`）。不再选择 CLI 或运行时 backend。
- **模型**：独立选择已配置且支持 Chat 的 provider/model。已有任务的明确模型会保留；切换 Agent 不会清空已选模型。模型不兼容或不可用时显示原因，不能静默换成另一模型。
- **项目**：可选择现有工作目录。默认托管工作区由宿主分配；路径本身不是资源授权。
- 官方 Agent 可以结合当前所选模型直接准备执行配置，无需为了首次启动先去工作台保存作者默认。个人预设必须有可执行的保存配置。

任务保存时，宿主一次性解析 Agent、模型、扩展和资源授权，冻结精确 Revision/Snapshot 与 typed resource binding。临时模型选择不改写工作台作者默认，也不改变应用全局模型偏好。

只改名称、说明、指令、调度时间不会重新读取工作台最新配置。明确修改 Agent、模型或项目时，才按正式准备合同生成新冻结配置。

## 会话模式

| 模式 | 行为 |
| --- | --- |
| 新建会话 | 每轮触发创建独立 Session，使用任务冻结配置；各轮按现有并发设置运行。 |
| 持续会话 | 首次合法 opening 后固定同一 Session，后续复用其历史、Agent 与模型。失败、等待或取消不使下一轮从头创建另一份持续会话。 |
| 指定会话 | 使用明确选定的现有 Session；Agent、模型和项目由该会话的 canonical binding 决定。 |

已绑定 Session 的任务不维护另一份可执行 Agent/model/workspace 配置。变更它们须进入该会话的显式配置切换；不能只改 Cron 元数据。

持续会话可以保留“每次运行前清空上下文”的选项。清空由同一 Session owner 处理，不删除历史，也不重建 Session。活动回合、暂停、未知效果等安全边界仍适用。

任务正文按原文提交。后台运行规则放在独立的系统指令通道，避免系统添加的编号被误当成用户的多步骤要求；用户正文里的真实编号与步骤顺序保留。

同一 Session 尚在运行时，新的触发记录为 `skipped`，不会取消或重复发送原输入。停止本次运行与停用未来调度是两个不同操作。

## 调度与恢复

支持一次性 `At`、固定间隔 `Every` 和带 IANA 时区的 cron 表达式。5 字段 Unix cron 会自动补秒；6 字段表达式可显式声明秒。

```text
分 时 日 月 星期
0 9 * * MON
```

上述表达式表示任务时区的每周一 09:00。常用频率可以直接在创建表单选择，自定义表达式在输入时校验。

每次定时触发先在同一数据库事务验证 owner、schedule revision 与确切计划时间，预留本次运行并推进后继时间。定时器只安装已提交的后继计划；本轮模型执行结束不会再次推动下一次计划。因此长任务跨越一个周期时，新建会话可独立准入，持续会话则按忙碌规则留出明确跳过记录。

休眠或应用关闭期间错过的触发不会被悄悄全部补跑。启动/唤醒按原漏触发策略记录 `missed` 并重装未来计划。已预留的旧运行只核对其原 Session/Turn 收据，不能当成新的触发重新发送输入。

## 查看、控制和故障

任务详情提供运行记录、对应会话入口和确切错误信息。历史直接投影自原运行 reservation；界面的显示数量上限不会删除幂等、取消或恢复证明。

| 状态 | 含义 |
| --- | --- |
| `ok` | 原 Turn 已确认正常交付。 |
| `error` | 准备或执行失败；详情区分应用配置、模型服务与具体工具故障。 |
| `skipped` | 本轮因同一会话忙碌等明确原因未执行。 |
| `missed` | 宿主不可用/休眠导致错过计划。 |
| `input_required` | Agent 已交还输入，需要用户回答。 |
| `cancelled` | 本次运行已由其原 owner 取消。 |

应用自身缺少工作区/进程资源绑定时，显示“本地 Agent 工作环境未准备完整”，标明失败发生在资源准备阶段，而不是归咎于上游模型；同样的配置错误不提供无效重试建议。模型认证、额度、限流、网络和协议错误保留现有正式分类。缺少依据时仅显示原因尚未确认，不猜测责任方。

错误说明只读原 canonical 终态；尚未形成 Turn 的准备拒绝由原 reservation 承载。历史失败不会被改写为成功，未知效果不授权自动重放。

保持唤醒开关只抑制系统睡眠，不代替宿主运行或恢复协议。新建会话的单次重资源按使命完成证据自动退休；持续工作区和合法后台责任继续保留。

## 从聊天安排任务

工作台 Agent 可使用原生 `automation.schedule` 动作管理当前会话的计划。宿主从已授权的调用身份获取 owner 和 Session，Agent 不能通过参数替换任意 provider/model 或其他人的会话。旧文本标记协议已退役。

## 每任务技能

现有每任务技能保留。SQLite 的 `skill_content` 为原文事实，`cron/skills/<job-id>/SKILL.md` 为生成产物；生成文件不是配置回退来源。删除任务会移除其生成技能目录，已经产生的会话历史仍按各自生命周期保留。

## 配置升级

当前代可核验的冻结 binding 只做无损存储归一，保留原工件引用。旧 CLI、缺资源或无法证明完整绑定的任务保留名称、计划、指令和已选择模型，停用旧执行入口并显示重新配置原因。保存新的工作台 Agent 配置后再启用；升级不会悄悄替换成权限更大的通用 Agent。

真实用户数据不用于故障实验。supported schema 的损坏或 I/O 失败继续拒绝启动；不兼容数据库 lineage 仍只由既有数据集协调器处理，不手工删除数据库或改写已提交迁移。

## 路由

| 操作 | API |
| --- | --- |
| 列表、创建 | `GET/POST /api/cron/jobs` |
| 读取、更新、删除 | `GET/PUT/DELETE /api/cron/jobs/:id` |
| 立即运行 | `POST /api/cron/jobs/:id/run`，必须提供稳定 `Idempotency-Key` |
| 历史、会话 | `GET /api/cron/jobs/:id/runs`、`.../:id/conversations` |
| 技能 | `GET/POST/DELETE /api/cron/jobs/:id/skill` |

创建请求使用工作台 `agent_selection`、独立 `model`、`message` 以及必要的工作区/资源选择。执行 binding 只由宿主生成，客户端不能提交冻结快照、CLI 或 backend 配置。指定会话模式只传会话引用，不复制执行配置。

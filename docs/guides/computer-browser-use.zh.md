# Computer Use 与 Browser Workspace

NomiFun 将桌面范围的 Computer 自动化与会话中的原生浏览器区分开。两者都受 Agent 能力授权约束，网页或模型提示不能自行授予权限。

## 会话浏览器（v2，实施中）

通过会话工作区的“浏览器”按钮打开。旧全局浏览器管理/设置页及兼容重定向已移除。

内嵌浏览器是主要浏览方式，导航和异常恢复在当前面板内进行。系统浏览器及 Attached Chrome 保留为用户明确选择的部分场景功能，不会因内嵌页面失败自动切换。

用户和 Agent 看到的是同一个原生网页。Agent 工作期间锁定用户页面输入；停止 Agent 并等待在途操作完成清理后，用户才能操作。隐藏面板会保留页面和标签，不是接管，也不是重置。

在最低 880×600 桌面窗口中，主导航和会话列表会在空间不足时临时收起，让聊天与内嵌浏览器并排显示。窗口变宽或关闭浏览器面板后，恢复你原来的侧栏状态与宽度；缩窗不会改写保存的分栏比例。明确展开让位中的侧栏会收起浏览器面板，再点“浏览器”可显示同一会话的网页；收起面板仍保留运行中 Agent 的输入锁。

网页反复跳转时，浏览器可以显示提示，并提供“暂停网页跳转”。暂停保留当前可用内容，阻止当前标签的网页后续跳转和新弹窗；其他已打开标签继续运行。“恢复网页跳转”只解除暂停，不会自动刷新。手动输入地址、刷新或历史导航也可继续浏览。“停止加载”只停止当前加载，网页自己的下一次定时请求可能仍会开始。暂停不代表关闭全部网页网络活动，需要彻底停止该页时可关闭标签。Agent 工作期间这些用户操作仍被锁定。

暂停功能只在原生浏览器能证明支持时显示。没有该入口时，仍可停止当前加载或关闭标签。

Windows 已验证暂停时对在途弹窗的清理。macOS 的在途弹窗处理仍待原生修补与验收，暂不能保证暂停前已经开始创建的弹窗会被拦截。若 Windows 的暂停控制报告不可用，请关闭受影响标签后重新打开。

菜单的“复制导航诊断”可用于区分应用命令、网站发起的新导航和 HTTP 重定向。它不包含完整 Fetch/XHR 网络记录，不收集 Cookie、认证头或表单内容。遇到网站验证或不支持内嵌环境时，可明确选择在系统浏览器打开；两边登录态独立，不会自动同步。请分别记录正常页面、验证页和反复跳转，验证码页面不代表正常访问已经通过。

开发前端项目时，先启动开发服务器，再让 Agent 在会话浏览器中打开 localhost 地址，观察页面、执行交互并验证结果。导航、点击、键盘输入和标准 HTML 选择操作使用真实浏览器，交互表面不是截图流。

Windows 原生输入已有真实 smoke 验证。macOS、frame、dialog、文件和打包等完整产品验收仍在进行，请参阅[架构说明](../architecture/browser-platform.zh.md)中的当前限制。

## 可选 Attached Chrome（macOS 与 Windows）

Agent session 的 `browser` 能力可以由一个附着的、正在运行的 Chrome 提供，
而不必使用内嵌 Browser Workspace。该 Provider 是安装级的。创建含 Browser
动作的会话前，在资源选择器旁操作：在运行 NomiFun 的电脑上打开 Chrome 144
或更新版本，在 `chrome://inspect/#remote-debugging` 中启用远程调试并批准
提示，点击「连接 Chrome」，再明确将浏览器资源选为「已打开的 Chrome」。
连接不会改变默认的 NomiFun 浏览器选择。「刷新状态」读取当前连接，
「断开连接」只释放确切的已观察连接。这些控件调用
`GET`/`POST`/`DELETE /api/browser-providers/attached-chrome`。

不要求重启 Chrome，不创建替代 Profile，也不导入 Cookie、密码或历史。断开
只释放连接和自动化状态，不关闭用户浏览器或标签。Agent 持有 run 时，浏览器
可变操作 fail closed。

明确选中的 Chrome 连接丢失时，资源选择器保留原选择；需重新连接或明确改选
NomiFun 浏览器后才能开始。Session 只冻结 `browser`/`attached-chrome` 的
kind/id，所属、动作权限和连接身份仍由服务端派生。Quick Start 复用同一
typed 资源选择合同，缺省使用 NomiFun 浏览器。

此 Provider 可观察、导航和操作已有标签页；不支持新建标签、上传、下载或
任意 evaluate。macOS 与 Windows 的发现实现和前端连接流程已具备，真实
个人 Chrome 及完整 iframe/对话框产品验收仍需原生验证。Edge 与 Linux 不
支持。这项能力与内嵌浏览器、本地/厂商搜索相互独立。

## 可选网页研究

`web.research` 能力模块独立于模型厂商的原生搜索承担公网检索。查询通过隔离
后台浏览器运行时执行，不读取会话登录态；启用它不授予 Browser 自动化权限。

Windows 与 macOS 桌面会识别已安装的 Chrome 120+；macOS 从
`/Applications/Google Chrome.app` 和 `~/Applications/Google Chrome.app` 发现安装。
没有合格安装时不能启用。发现过程不启动浏览器，实际查询才使用独立临时
Profile 启动隔离运行时并核对版本，不读取个人 Chrome Profile。
搜索词发送给 Bing，引擎域名通过 Google Public DNS（HTTPS）解析，不读取会话
登录态。Chrome 更新导致旧绑定失效时需重启应用。

## Computer Use

Computer 仍是独立的桌面控制能力。在 Agent 工作台选择对应能力，在“设置 → 能力与权限 → Computer Use”查看并开通操作系统权限。创建包含 Computer 动作的会话时，产品会按该 Agent 的精确动作集检查权限并在未就绪时直接给出此入口，但不会阻止创建会话或使用 Agent 的其他能力；真正调用受影响动作时才返回可恢复的权限错误。仅 `launch` 动作不依赖屏幕录制或辅助功能权限。

Agent 工作台中，已启用的 Computer 能力卡片会显示当前缺少的精确系统权限和“去开启”入口；这只是运行条件提醒，不会把系统授权写进 Agent 配置。已有会话若权限被撤销或从未授予，会在会话标题栏自动展开一次提示气泡；关闭气泡后警告入口仍保留，从系统设置返回时会自动复检。

独立 Nomi 的 Computer 配置仍可使用：

```toml
[tools]
max_recent_images = 3
[tools.computer]
enabled = true
max_screenshot_edge = 1568
```

## macOS 权限

Computer 能力首次使用需在「系统设置 → 隐私与安全性」中授权宿主应用：

- **辅助功能（Accessibility）**：鼠标键盘合成输入、现役可访问性树读取与动作需要此项。
- **屏幕录制（Screen Recording）**：截图需要此项（截图全黑或失败时检查）。

“能力与权限”读取运行中 NomiFun 进程的实时 TCC 状态，并可注册应用、触发系统提示、打开准确的隐私面板。`not_granted` 只说明当前未授权：Accessibility 与 Screen Recording 的公开布尔探针不能区分从未申请和曾经拒绝。回到 NomiFun 后先重新检测；若系统要求重启或授权仍未生效，彻底退出并重新打开后继续任务。每次原生操作重新检查，输入前须重新观察，不重放授权前的鼠标键盘动作。系统授权不会增加 Agent 的工具选择。

## 语音、Browser 与通知权限

- **语音输入（ASR）**：仅在用户点击语音或测试按钮后请求麦克风。测试会立即释放音频流，不保存或上传；正式录音只提交给用户选择的 ASR 服务。拒绝后，语音按钮直接提供“能力与权限 → 语音输入”入口。
- **Browser Use**：基础导航、页面观察、可见页面截图、点击与输入不依赖 Computer Use 的辅助功能/屏幕录制权限。macOS 14+ 使用系统 WKWebView，Agent 点击与填表采用网页语义操作，不获得真实用户激活。首版不支持拖拽、悬停、组合键、嵌入框架和自动文件传输，详见[能力矩阵](../architecture/browser-platform.zh.md)。网站及设备权限仍由用户明确决定，系统可能追加权限提示。若具体 Browser provider 不可用，会话仍可启动，只省略对应工具面。
- **本地网络**：macOS 15 及以上版本会在 Browser 打开局域网地址，或 NomiFun 主动连接局域网 SSH、MCP 服务及伙伴设备时按需询问。仅监听 WebUI 的入站 TCP 连接不需要这项授权；应用带有本地网络用途说明。
- **系统通知**：产品内通知开关与操作系统通知授权是两层设置。开启普通通知或定时任务通知时会先请求系统授权；拒绝后提供通知权限页与系统设置入口。
- **文件与受保护目录**：现役文件与进程工具可以使用本机绝对路径、默认目录之外的相对路径和卷；工作区只提供默认目录与项目归属。macOS 的属主、ACL、受保护目录与卷许可仍然生效。完全磁盘访问没有可靠的全局就绪探针，界面保留“使用时检测”，不通过读取无关私有文件猜测授权；管理员身份不能代替 TCC。
- **跨应用自动化**：Agent 可通过正常程序或 Shell 调用 AppleScript/Apple Events。正式 App 带有用途说明及 Hardened Runtime Apple Events entitlement；macOS 仍按发送方和目标应用请求原生许可。该许可没有单一的全局就绪状态。
- **macOS 网页文件选择**：公开 WK 文件面板 API 不提供 HTML `accept` 的 MIME/扩展名提示，因此不会预筛选文件类型，请选择网站接受的类型。Windows 保留现有文件筛选。
- **机器人设备权限**：摄像头、运动、显示、主动语音等仍由设备与伙伴设置管理，在工具面解析及真正下发动作前按 Agent 所需动作复检。设备离线时只省略 Robot 工具，不阻塞 Agent 的其他能力；它们不是宿主 macOS 权限，此页的授权不会替代设备授权。

对应控制面为 `GET/POST /api/system/permissions[/request|/open-settings]`；读取要求安装 owner，会弹出宿主 UI 的请求/设置操作还要求桌面进程的本地信任。旧 `/api/computer/permissions*` 路径仅保留兼容。

设置中的 Browser 页同时实时显示宿主摄像头、麦克风状态。宿主许可和网站的本次决定分别保留；系统已授权不证明设备存在或采集成功。可探测范围、实际调用者和平台未完项见[系统许可与执行身份](../architecture/system-permissions.zh.md)。

## 工具语义与任务要求

- Computer 为单工具 + `action` 参数形态。
- 默认可信 Agent 不要求用户切换权限模式，也没有按 Info/Exec 再增加的应用审批。用户明确提出只读排查、不要执行或停止时仍须遵守。
- Session 冻结的工具选择、资源归属、观察代次、Effect 与取消事实保持有效；页面内容不能改变它们。
- 按动作选择观察：像素操作先截图，可访问性操作先读取树，窗口聚焦先列出窗口。操作后通过相应原生观察验证结果。
- 缺失系统许可只证明该动作尚未执行。授权恢复后重新观察，再继续原任务，不把打开设置或认证成功当成动作完成。

## 截图与 token 治理

- 截图自动降采样到长边 ≤ `max_screenshot_edge`（默认 1568px，Anthropic 视觉推荐区间），最终 PNG 还受 5 MiB 上限约束；高熵画面会再次确定性降采样，坐标几何始终以实际发给模型的图片为准，并自动映射回真实屏幕（含 Retina 缩放）。
- 历史消息中只保留最近 `max_recent_images`（默认 3）张工具结果图片，并同时受每次请求最多 20 张和累计编码体积预算约束；超出的附件会被剥离，但保留文本和省略说明。提供商调用失败后也会清除待重放的历史截图，再持久化可恢复会话，避免会话文件、请求 token 和网关负载持续膨胀。
- OpenAI 协议的 tool 消息不支持图片：图片以紧随其后的 user 消息（`image_url` data URI）传递，并标注来源 call id。Anthropic/Bedrock/Vertex 走原生 `tool_result` 图片块。
- 外接 MCP 工具回传的图片同样经 `McpToolProxy` 映射进图片管道（单图 ≤ 5 MiB 上限）。

## 替代路径：其他外接 MCP

除内置 Computer 与 native Browser 外，仍可外接任意社区 MCP server（在 MCP 设置中添加），与上述能力互不冲突（工具名不同）。

# 连接小智机器人

[English](xiaozhi-robot.md)

NomiFun 可以作为兼容小智 ESP32 机器人的本地 AI 后端。机器人负责麦克风、
扬声器、显示屏、按键和设备端 MCP 工具；NomiFun 负责桌面伙伴、对话模型、
ASR、TTS、记忆、会话和工具协同。

这是一个可选接入方式。配置为连接 NomiFun 的固件会通过局域网连接桌面端，
而不是使用默认的 `xiaozhi.me` 服务。

## 准备工作

绑定后，物理设备使用同一伙伴下独立的**机器人**角色和设备会话，共用伙伴的人格、声音与长期记忆。桌面伙伴仍使用**伙伴**角色，两个角色同时可用；无需把桌面会话切换成机器人 Agent。设备重连复用对应设备的接收会话，页面上查看其他会话不会改变设备的输入目标。

伙伴相处页右侧分别提供**伙伴**和**机器人**设置区。默认由机器人角色负责设备控制；查看机器人会话时，**连接 → 当前会话机器人**显示对应设备的资源设置。设备配对并不授予任意工具权限，实际调用仍须满足所选 Agent 的 Action、确切设备资源和设备许可。请在回复结束、操作结算后应用配置；活动或暂停的回合会阻止切换。

物理设备集成使用机器人角色的正式产品绑定入口 `PUT /api/product-agent-bindings/robot/{companion_id}`，携带机器人角色的 `selection`、确切 `conversation_id` 和完整 `resource_selections`。用户也可给伙伴角色显式选择 Robot 能力和真实设备资源，沿伙伴自身的正式配置入口应用；这不会改变设备输入路由。应用现有会话时沿正式绑定切换生效，保留 Session 身份和历史。物理输入的设备身份来自该机器人会话的归属，不能靠显示名、页面选择或消息正文改投另一设备。

设备设置仅展示当前固件实际提供的控制权限。拍照、动作和设备扩展工具需要相应许可；持续观察还需要单独许可，并限于当前对话轮次。撤销权限、解绑或断开连接会使旧轮次的设备授权失效。拍照得到的图片和观察结果保存在原会话消息下。

本版本采用全新机器人数据基线，不提供旧机器人线程、旧 Agent 绑定或旧消息的迁移。

双角色、多会话、桌面委派与共享上下文的实施及验收状态见[伙伴架构](../architecture/companion.zh.md)。本文不代表真实机器人动作、语音时延或跨设备审批已完成验收。

- 在与机器人相同的局域网内运行
  [NomiFun 桌面应用](https://github.com/nomifun/nomifun-desktop)。
- 准备兼容的小智固件。
  [nomifun-xiaozhi-yuntai](https://github.com/nomifun/nomifun-xiaozhi-yuntai)
  项目包含 `esp32-s3n16r8-emoji` 板型和头部舵机 MCP 工具。
- 在 NomiFun 中创建或选择一个桌面伙伴。
- 准备可用的对话、语音识别（ASR）和语音合成（TTS）模型。

机器人必须能够直接访问电脑。访客 Wi-Fi 或 AP 隔离可能会阻止同一 Wi-Fi
下的设备互相通信。

## 1. 配置伙伴与机器人角色

1. 打开 NomiFun 的**桌面伙伴**，选择或创建一个伙伴。
2. 在伙伴的**总览**页配置主对话模型。
3. 在同一页的**模型配置**中选择 ASR 和 TTS 模型；如果供应商要求音色，
   同时选择音色。
4. 先在普通文字会话中确认该伙伴能够正常回复。

在**机器人**设置区为设备入口选择官方**机器人**（`companion.robot`）或满足机器人角色要求的个人 Agent。
官方配置保留伙伴身份、长期记忆、机器人操作及窄范围桌面委派，减少通用工具与历史上下文的开销。
**伙伴**设置区继续配置桌面工作，两个角色并存可用。现有普通伙伴和个人 Agent 不会被升级自动替换或增加权限；
采用已编辑的新版本时，须在目标会话空闲后明确**应用最新设定**，再单独开启所需设备许可。

机器人可以单独选择默认对话模型；未设置覆盖（`robot.model=null`）时继承伙伴模型。
**后续默认改为继承伙伴模型**只影响后续机器人会话，不改写已经存在的会话。
相处页查看机器人会话时，同角色设置明确更新当前会话并保存后续默认；只修改另一个角色的设置时，已有会话保留原值。

对话模型仍由你选择，推理强度沿用已有显式设置或模型默认值；此配置不会强制替换全局模型。
自然语言动作的响应仍包括语音识别、模型决策、设备通信和语音合成，不能仅凭轻量配置保证毫秒级响应；实际延迟须用真实设备测量。

仅在模型目录中添加供应商并不等于配置完成：机器人角色须有可用的独立或继承对话模型，
语音对话还须配置伙伴的 ASR、TTS 和所需音色。

## 2. 获取 NomiFun OTA 地址

1. 打开伙伴的**渠道与机器人**页。
2. 在**机器人连接**区域点击**添加机器人**。
3. 如果 NomiFun 提示局域网访问未开启，点击**现在开启**。
4. 保持弹窗打开，复制其中任意一个 OTA 地址。地址以 `/robot/ota` 结尾，
   通常使用 NomiFun 的局域网端口 `25808`。

请选择与机器人处于同一网络的电脑 IP。不要使用 `127.0.0.1`，因为它在
ESP32 上指向机器人自身。

## 3. 让固件连接 NomiFun

烧录兼容固件后，打开机器人的 Wi-Fi 配网页。在**高级设置**中，把 NomiFun
显示的完整地址粘贴到 **OTA 地址**，保存 Wi-Fi 设置并重启机器人。

设备启动时会请求这个地址。NomiFun 会返回连接 `/robot/v1` 所需的 WebSocket
配置，无需手工拼接或填写 WebSocket 地址。

板型选择、编译、烧录、接线和舵机注意事项，请遵循固件仓库 README 及板级
文档 `main/boards/esp32-s3n16r8-emoji/README.md`。

## 4. 绑定机器人

1. 重启后，机器人会在屏幕上显示并读出 6 位激活码。
2. 返回 NomiFun 的**添加机器人**弹窗。
3. 输入激活码，点击**绑定到本伙伴**。
4. 等待机器人出现在伙伴的**机器人连接**列表中。

激活码会过期。如果输入后提示无效，请重新开始连接并使用设备最新显示的
号码。已经绑定到其他伙伴的机器人，需要先在原伙伴处解绑。

## 5. 验证接入

验证设备工具前，需要同时满足以下条件：机器人角色的当前 Agent 已明确授权相应的机器人
Action，该设备的机器人会话绑定正确的 `robot` 资源，设备设置中也已允许对应操作。
配对本身不授予 Agent 工具权限；普通语音对话不要求摄像头或动作许可。

| 机器人 Action | 设备工具范围 |
| --- | --- |
| `robot/vision` | 摄像头和视觉工具；持续观察还需单独许可。 |
| `robot/display` | 屏幕、表情和灯光工具。 |
| `robot/motion` | 头部、云台和舵机工具，包括 `self.head.get_status` 这类状态读取，以及会联动舵机的 `self.head.express`。 |
| `robot/device` | 固件提供的其他设备扩展工具。 |

官方**机器人** Agent 包含这四类 Action；官方**伙伴** Agent 负责电脑工作，不再默认提供物理设备控制。
实际工具取决于确切设备、固件和许可。已保存的官方 Agent 配置和已有会话不会随升级自动获得新增授权。
需要补齐时，在**机器人**设置区选择**编辑 Agent → 补齐推荐能力**，核对新增项后**补齐并保存**。
回到对应机器人会话，在回复结束后**应用最新设定**；需要刷新设备资源版本时再**应用机器人**，
并在设备设置中开启所需许可。使用个人 Agent 时，也须明确启用所需的机器人 Action。

建议依次验证：

1. 对机器人说话，在会话选择器中打开对应的**机器人**会话，确认识别文本出现在正确设备的历史中。
2. 确认回复能够从机器人扬声器播放，并按固件支持的方式通过说话或交互按键
   打断播放。
3. 让伙伴读取头部状态或转动头部。`esp32-s3n16r8-emoji` 固件通过
   `self.head.*` 暴露设备端 MCP 工具，其中包括 `self.head.get_status`。

自然聊天中的表情与手势使用同一会话已授权的 MCP 工具。更新后的云台固件提供
`self.head.express`，可组合表情和头部动作。云台的表情动画本身也可能移动舵机，
因此这个组合工具需要 `robot/motion` 和设备动作许可。
模型在合适时机选择动作，不要求每句话都动作，也不会从聊天正文的情绪标签生成
控制指令。工具返回 `accepted` 或已入队只表示受理，不能证明机械动作已完成。

需要校准的固件默认不会启用舵机动作。启用自动动作前，请按照板级文档校准
中位和行程；错误的限位可能导致舵机堵转或损坏。

## 6. 通用能力配置与扩展

在伙伴的**渠道与机器人 → 机器人连接**中，点击设备的**能力配置**。界面从该设备
实际公布的 MCP 工具和 JSON Schema 生成，不限定云台、舵机数量或工具名称。

- **工具配置**：启停工具、编辑用途说明、设置默认参数，以及为未知命名的工具选择
  控制类别。摄像头和机械动作的既有类别不能降级为较低许可；参数仍受设备原始
  Schema 约束，不能在桌面端扩大物理行程或创造固件不支持的参数。
- **命名动作**：选择已有工具，填写固定参数和说明，保存为“打招呼”等可复用能力。
  一个设备工具可以定义多个命名动作；Agent 调用时沿同一权限和效果回执路径执行。
  配置和刷新本身不调用动作工具。
- **聊天行为**：人格继续归属原伙伴。在**机器人**角色的 **Agent 设定**中编辑动作时机与频率。
  给精简配置增加通用工作区、办公等能力后，将按
  扩展后的完整职责运行，不再自动套用精简上下文策略。工具用途说明不授予控制权限。

保存会更新设备能力配置版本，但不会自动修改 Agent Action 或设备许可。返回相处页，打开该设备的机器人会话，
在**当前会话机器人**中于回合空闲时点击**应用机器人**，将新版本应用到该会话；身份、
模型、历史和其他资源保留。旧版本工具在配置修改后不能继续派发，避免按旧说明执行
新配置。固件公布了新工具时，可以先点**刷新设备能力**，再重新应用到会话。

该阶段提供能力配置与扩展，不提供拖动滑块实时控制硬件的手动操作面板。新的机械
执行原语由固件实现；已有工具的默认参数、用途和命名动作可以在界面编辑。

机器人会话的语音识别任务与设备收帧分别调度。等待 ASR 时仍处理 MCP 回执、取消和
断连；取消或替换连接后的转写不会作为新指令提交。语音只播放当前回合最终有效的
公开回答，不朗读思考、工具前旁白或已撤回的步骤。设备返回 `accepted` 的含义仍由
固件定义，不能从界面回复推断动作已完成。

`auto` 和 `realtime` 模式下，一次 `listen.start` 打开持续监听窗口；服务端 VAD 只划分
每段语音，不因某段识别结束而关窗。明确动作静默完成后，下一段语音仍可识别，不依赖
TTS 开始或结束来恢复监听。连续纯静音只保留有界的前置音频，不反复发起空转写。
明确的 `listen.stop`、`abort` 或连接结束会关闭窗口；手动模式仍以设备的开始、停止为准。
本地回归必须覆盖一次开始监听后连续多段 Opus 音频，不能在每条指令前补发开始监听来
代替持续交互验证。该契约不代表本次实体设备麦克风、播放及交互时延已完成实测。

## 7. 桌面任务与多会话

明确的舵机或表情指令直接执行，全部请求动作成功受理后默认不说话，动作本身就是回应。
有问题需要回答、你明确要求口头回执，或出现失败、受阻、结果不确定、必要澄清时才回复；普通陪聊按你的要求展开。
物理回复使用自然口语，不在句末追加 emoji、颜文字或文字动作表演；人格保留在语气中。
用户要求引用的符号、公式和代码正常保留，已有历史回复不因升级改写。
天气、实时信息、知识检索、电脑工作，以及需要深入构思的动作编排，当前机器人缺少本地能力时，
可以向同一伙伴的桌面角色定向委派，短问题也适用。例如「北京今天的天气怎么样」应查询后回答。
桌面任务在独立的关联会话中，
使用伙伴角色自己的模型、工具和资源；不会把任务插入你正在查看的聊天，也不会把电脑权限交给机器人。
接受委派后机器人结束接待回合，真实结果再回到原设备回答；完成状态与产物须以对应任务回执为准。
实时查询仍需伙伴侧配置可用的联网能力与凭证。未显式选择推理强度的窄机器人，对明确支持的模型
自动采用轻量接待档位；未知模型保留原配置，桌面任务使用伙伴自己的模型设置。
已编辑的官方机器人配置缺少委派能力时，可用**编辑 Agent → 补齐推荐能力**；个人 Agent 则在工作台
手动选入协作模块的 `agent/delegate`。保存后在空闲设备会话**应用最新设定**。
详细边界及验收状态见[伙伴架构](../architecture/companion.zh.md)。

会话选择器用于查看各条独立历史；新建伙伴会话保留共享人格与长期记忆。
**在浮窗继续**只明确修改桌面浮窗的接收目标，不改变机器人或渠道的收件目标。
停止播报与取消桌面任务分别处理；需要取消工作时应选择确切任务。任务中的问题或审批仍须通过对应的正式交互处理，
不能把另一条会话里的附和、历史记忆或停止音频当成授权、取消成功或操作完成。

## 数据流

```text
麦克风 -> 小智固件 -> NomiFun ASR -> 机器人角色模型
                                           |
扬声器 <- Opus 音频 <- 小智固件 <- NomiFun TTS
                                           |
                       设备 MCP 工具 <-----+
                                           |
                       独立桌面任务 <---- 定向委派 -> 伙伴角色模型
```

语音和对话内容会按照 NomiFun 中选定供应商的策略处理。“本地后端”指机器人
网关和会话协同在本机运行；如果选用云端 ASR、TTS 或对话模型，相应数据仍会
发送给该供应商。

## 常见问题

- **弹窗没有 OTA 地址：**在桌面端开启局域网访问，并确认电脑存在非回环网络
  地址。
- **机器人无法访问 OTA 地址：**确认两个设备处于同一局域网、系统防火墙允许
  NomiFun 通信，并关闭访客网络/AP 隔离。
- **没有激活码或激活码无效：**确认 OTA 地址以 `/robot/ota` 结尾，重启
  机器人并使用最新的 6 位号码。
- **`Nomi conversation has no provider/model configured`：**在所绑定伙伴的
  **总览**页检查机器人默认模型，或它继承的伙伴主模型；已有会话还须明确应用可用模型，只配置全局供应商不够。
- **无法识别语音：**为伙伴配置 ASR 模型，并检查供应商凭据和额度。
- **没有语音回复：**为伙伴配置 TTS 模型和音色，再检查扬声器接线及音量。
- **已连接但头部指令无效：**确认机器人角色的当前 Agent 已授权 `robot/motion`、对应机器人会话
  已选择正确的机器人资源、设备已允许动作，且固件提供 `self.head.*`；需要实际
  转动时，还须按板级文档完成校准和动作解锁。`self.head.get_status` 同样归属
  `robot/motion`，也需要相应授权和设备许可。

## 局域网安全

开启局域网访问后，NomiFun 会监听本地网络。请仅在可信局域网中使用，保持
系统防火墙开启，不要把 `25808` 端口直接暴露到公网。不再使用机器人或 WebUI
连接时，可以关闭局域网访问。

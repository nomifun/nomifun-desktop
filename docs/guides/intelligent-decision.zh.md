# 智能决策（IDMM）

IDMM（Intelligent Decision-Making Mode）是 canonical AgentSession 的可选值守层。
它不创建第二个会话、不接管 Agent，也不拥有另一套执行引擎；它只观察当前会话的
持久化回合、消息与实时运行进度，并通过同一个 AgentSession 命令入口实施恢复。

在“Agent 工作台 → 运行策略”中可以为个人 Agent 保存默认值；配置进入不可变
AgentPreset Revision。新 AgentSession 创建时复制一次该 Revision 的默认值，之后不会
跟随 Agent 的后续修改。新建会话页可以在发送前覆盖默认值，会话头部的“智能决策”
胶囊则只修改当前会话。未配置的 Agent 默认关闭。

IDMM 不属于 Capability Catalog，也不会给模型增加 Tool、Context、资源或系统权限。

## 两种模式

### 规则值守

规则值守全程不调用模型，适合无人值守任务的机械性恢复：

- 识别 429、超时、网络中断、网关错误、空响应等可重试供应商故障，提交一个带
  稳定幂等键的恢复回合；
- 读取运行事件的最后进度。在模型阶段超过静默阈值时取消失去进展的精确回合，
  再从持久化上下文继续；
- 识别明确的数字、字母或列表选项，优先推荐项，否则选择第一个安全选项；
- 遇到开放问题、权限、凭据、付款或破坏性选项时停止自动推进，等待人工处理。

工具执行期间不会因静默超时而被强制取消，避免重复外部副作用。

### 规则 + 旁路模型

该模式先执行完全相同的确定性规则。只有规则无法解决开放问题或歧义选择时，才会
调用用户显式选择的旁路模型。旁路模型：

- 只能读取配置范围内的上下文（最后一轮、最近消息或受字符上限约束的完整会话）；
- 上下文在发送前会对常见 API key、token、密码和私钥做尽力脱敏；
- 不获得工具、会话管理或权限能力；
- 必须返回受约束 JSON，只能选择安全选项、给出短文本回答或停止；
- 不能批准权限、提供凭据、确认付款或选择破坏性操作。

旁路模型用于“解开决定”，不会替代主模型继续执行整个任务。

## 模型故障转移

“模型管理 → 故障转移”中的队列会在**新 AgentSession 创建时**冻结进该会话的
主模型路由。运行时模型 Broker 在一次模型调用内负责有限重试和按序切换备用模型；
IDMM 在整个回合仍然失败后负责重新唤醒任务。

已存在会话的 Agent/model binding 是不可变事实，不会因后来修改全局队列而被偷偷
改写。需要应用新队列时，请新建或 fork 会话。

## 防循环与审计

每次介入都有：

- 基于故障回合或消息摘要的稳定指纹；
- 稳定 Idempotency-Key，网络重放不会创建第二个恢复回合；
- 每小时预算、最小介入间隔和连续恢复上限；
- 会话内最近介入记录，包括动作、规则/旁路层、结果与有限错误说明。

配置和有限介入记录使用 `agent_session.idmm.<session-id>` 命名空间持久化；删除会话
会同时清理该记录。删除被旁路配置引用的供应商时，配置会自动降级为“规则值守”，
不会留下失效模型引用。

## API

- `GET /api/agent-sessions/{id}/idmm`：读取配置、运行状态和最近介入。
- `PUT /api/agent-sessions/{id}/idmm`：完整替换该会话配置。
- `POST /api/agent-sessions/{id}/idmm/evaluate`：立即执行一次检查。

三个接口都要求安装所有者身份，并再次校验目标 AgentSession 的 owner。

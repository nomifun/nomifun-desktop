# 伙伴（Companions）

NomiFun 的数字伙伴从「单个 nomi」升级为**多伙伴家庭**：你可以创建多个伙伴并同时使用、分别培养、自定义名称/形象/人格，每个伙伴可以使用自己的聊天模型、绑定自己的**专属知识库**（演进出金融/文学/coding/情感等专业伙伴）；而**每条记忆都只属于一个伙伴**——一个伙伴学到的东西是它自己的，别的伙伴看不到。**学习与技能进化也是按伙伴各自一份**：各自的节奏、各自的学习模型、各自在事件流里的位置，蒸馏出来的东西也全记在自己名下。真正 install 级的只剩*采集*——这台设备到底记录哪些事件。记忆、伙伴、知识库都可以打包成 `.zip` 导出/导入，换机平滑迁移。

> 入口是侧边栏的 **桌面伙伴** 页（即 `/nomi` 路由）；任意桌面伙伴窗口右键菜单的「打开聊天」也会深链到这里。

## 页面结构：伙伴切换条 + 双域 Tab

「桌面伙伴」页顶部是**伙伴切换条**：每个伙伴一张卡片（形象缩略图 + 名字 + 等级），加一个「新建伙伴」按钮。当前选中的伙伴驱动下面的**伙伴域** Tab；少数真正属于这台设备的设置归**install 级** Tab：

| 域 | Tab | 内容 |
| --- | --- | --- |
| 伙伴域（随切换条变化） | 总览 | **桌面伙伴开关** + 该伙伴的等级 / XP / mood |
| | 记忆 | **该伙伴自己的记忆**——这里不会列出别的伙伴的记忆，别的伙伴也读不到这些 |
| | 聊天 | 该伙伴自己的陪伴会话线程 |
| | 模型&知识 | 聊天模型选择 / **知识库绑定** |
| | 远程连接 | 该伙伴的 IM 机器人（按伙伴绑定，详见[渠道指南](./channels.zh.md)） |
| | 进化 | **该伙伴自己的**定时学习 + 技能生成 + 休眠时段 |
| | 设置 | 名称 / 形象 / 人格 / 删除伙伴 |
| install 级（全局唯一） | 数据采集（在**进化** Tab 内） | 这台设备到底记录哪些事件、留多久。整机一套开关——所有伙伴从同一份记录里学。配置本身是全局的，但它存在的唯一目的是给伙伴学习提供素材，所以和学习配置同屏，不再单独占一个设置页 |
| | 迁移 | 导出 / 导入迁移包（见下文） |

## 创建与管理多伙伴

1. 点伙伴条上的**新建伙伴**，起个名字、挑一个形象（mochi / ink / roux / pixel / bolt / boo 六款）即可。
2. **第一个伙伴自动成为默认伙伴**（卡片带「默认」徽标）。默认伙伴是渠道未显式绑定时的回退对象（见下文渠道一节）。
3. 在该伙伴的**设置** Tab 里可以随时改名（即时生效）、换形象、调人格（预设或自定义）、**为这个伙伴单独选聊天模型**、开关桌面伙伴窗口与勿扰时段。
4. **删除伙伴**会级联清理：它的**记忆**、技能、陪伴会话、运行时状态（XP 等）、`('companion', companionId)` 知识库绑定一并移除；若删的是默认伙伴，默认资格自动顺延给下一个。由于每条记忆都属于某一个伙伴，删掉伙伴就等于永久删掉记在它名下的记忆——想留住就先把它导出（伙伴包默认带走它的记忆）。删除允许删到零个——采集照常运行，但一个伙伴都没有时根本不存在学习循环（节奏属于伙伴），事件只会先攒着，等你建出伙伴再学。

每个伙伴在磁盘上是一个目录：`{data_dir}/companion/companions/{companion_id}/config.json`，**目录即真相**——这也是伙伴包导出/导入的单位。

### 多个桌面伙伴同屏

每个开启了桌面伙伴开关的伙伴拥有自己的桌面窗口（透明、置顶、可拖动，窗口 label 为 `companion-{companionId}`）。多个可以同屏共处；建议同屏不超过 5 个（每个窗口是独立的 WebView 实例，开太多影响性能，UI 会提示但不硬限）。右键任意桌面伙伴窗口可直达它的聊天页。

## 记忆归属、采集与学习

**每条记忆都只属于一个伙伴。** 一个伙伴的提示词里只会注入它自己的记忆，它的「记忆」Tab 也只列出自己的记忆；无论在 UI 还是 API 里，都没有把一条记忆改判给另一个伙伴的办法。A 学到的，只有 A 知道。

`{data_dir}/companion/shared/` 下的那套**设施**仍然全局一份（一份采集配置、一棵事件目录、一个 `memory.db` 文件把所有伙伴的记忆行和运行时状态放在一起，每行标着自己的主人）——但**配置**与**产出**都是按伙伴分开的：

- **采集**：单条链路订阅全局事件总线，按开关采集你的工作数据，写入 `shared/events/YYYYMMDD.jsonl`。**只记你的输入，不记模型的输出**——伙伴对话只保存你说的话，伙伴自己的回复不落盘；学习器按设计从来就不许把回复当作你的事实或意愿，所以记它只费磁盘和算力。原始事件默认采用 **30 天目标保留期 + 64 MiB 硬容量上限**：超过目标期限且已被所有启用的学习/进化消费者处理后删除；容量上限始终优先，必要时会删除尚未处理的最旧日文件。可在「数据采集」调整为 7–365 天、16–512 MiB，并查看当前占用和日期范围。
- **学习**：**每个伙伴跑自己的学习器**——自己的间隔、自己的学习模型（与该伙伴的聊天模型相互独立）、自己在共享事件流里的位置。一轮跑出来的记忆、XP、mood 全部记在「配置驱动了这一轮」的那个伙伴名下，也只有它看得到。在该伙伴的**进化** Tab 里配置，改的只是它自己。聊天中保存的记忆仍属于该对话所属的伙伴。
- **技能生成**：同样按伙伴各自一份——各自把重复的多步操作沉淀成自己的技能，各自选保守/激进。背后的模式统计与你的采纳/拒绝记录仍是 install 级的：一段重复的工具序列是关于**你**怎么干活的事实，一次拒绝是你对这个模式本身的判断，与哪个伙伴无关。
- **休眠时段**同时门控这两条循环和桌面气泡：时段内这个伙伴既不打扰你，也不花你的 token。收到 IM 消息仍会正常回复——对一条消息装作没看见才是意外。
- **事件目录共享，游标不共享**：所有伙伴读同一棵 `shared/events/*.jsonl`，但各自从自己的游标读起，所以晚一步开启的伙伴照样能看到兄弟们已经消费过的事件。原始事件只有在**所有**启用了消费者的伙伴都读过之后才会被删除。

### XP 与 mood 的归属规则

| 来源 | 归属 |
| --- | --- |
| 学习 run 产出（按处理事件数 + 新记忆数计分） | 仅跑了这一轮的那个伙伴（节奏是它的，产出也是它的） |
| 陪伴聊天轮次（+2） | 仅参与对话的那个伙伴 |
| 聊天中保存记忆（+5） | 仅该伙伴 |

**mood 也是按伙伴各自一份**：一轮学习设置的是「跑了这一轮的那个伙伴」的 mood。全家再没有任何共享物——记忆不是，XP 不是，mood 不是，学习节奏也不是。真正还共享的只剩原始事件记录本身（那是这台设备的属性）和技能生成背后的模式统计。

## 给伙伴绑定知识库

在伙伴的**模型&知识 Tab → 知识库**区域，用绑定控件为这个伙伴挂载一个或多个知识库（绑定关系为 `('companion', companionId)`）。生效范围：

- 该伙伴的**陪伴聊天**与它接待的**渠道会话**（会话上带 `extra.companionId`）都会挂载这个伙伴绑定的知识库——对话时可检索；不带 companionId 的普通会话维持原有的会话级绑定，二者**不合并**。
- **agent 看到什么**：库挂载到 `{workspace}/.nomi/knowledge/`，注入的上下文按库携带 描述 + AI 梗概 +「何时查阅」提示 + 按预算的目录（每库 20 条 / 全局 60 条，超出按目录聚合），外加一份显式检索协议——要求 agent 先查再答，而不是凭记忆作答。
- **回写**只有一个落点——知识库正文；更新已有文档是以 compare-and-swap **追加**新内容，回写只能给你整理好的正文添东西，不会覆盖它。回写发不发生，由按绑定设置的**回写意识**决定：
  - **手动型**（默认）——只有你在对话里明确要求时，伙伴才回写；不会在回合结束时背着你去抽取；
  - **自动型**——伙伴自己判断，且门槛很高：只沉淀确有长期价值、可复用、明确正确的知识，琐碎、临时、重复的内容一概过滤。
- **AI 自动生成**：知识库页面的「AI 生成」按钮（列表编辑 Modal 与详情页都有）调 `POST /api/knowledge/bases/{id}/autogen`，生成库的描述与 `README.md`；`.zip` 导入会自动补全空描述。需要已配置 AI Provider（否则返回 `409`）。
- **URL 知识源**：创建知识库时可给出最多 16 条 URL。*snapshot* 模式在创建时抓取并把每页转为 markdown 落入库的 `snapshots/`（超过 32 KB 的页面由 AI 压缩），并自动生成梗概——详情页可刷新快照；*live* 模式留给 agent 运行期实时抓取（无网络工具的引擎可调网关工具 `nomi_knowledge_fetch_url`）。仅接受公网 `http/https` URL（SSRF 防护）。
- 伙伴也能**自己养库**：平台 Gateway 提供 7 个知识工具（列表 / 绑定 / 建库 / 写文件 / AI 生成 / 抓取 URL），且伙伴系统提示里内置了「知识沉淀技巧」——陪伴或渠道聊天中它可以不经吩咐就建库并把心得沉淀进去。注意 `nomi_knowledge_create_base` 带 `urls` 建库时，URL 抓取在**后台异步**执行——工具立即返回，Agent 勿因快照尚未出现而重复建库；库描述（description）生成出来即代表抓取与梗概流水线已完成。

给不同的伙伴绑不同的库，就得到了「金融伙伴」「文学伙伴」「coding 伙伴」——人格、模型、知识、记忆都按伙伴独立。

## 渠道绑定伙伴

每个 IM 平台（Telegram / Lark / 钉钉 / 微信）都可以绑定接待远程消息的伙伴：打开该伙伴的 **Remote** tab（`/nomi?companion=<id>&tab=remote`），在那里连接或改绑 bot。渠道行可以保存直接绑定；未直接绑定时才读取平台偏好 `channels.{platform}.companionId`。两级都没有解析到存活伙伴时，渠道保持未绑定，不会隐式取得另一个身份。切换或删除绑定会重置受影响的活跃会话，使下一条消息重新解析归属。详见 [Channels 指南](./channels.zh.md)的「渠道 Agent 接入」一节。

> companionId 不授予任何权限：它决定 persona / 模型 / 知识库挂载，也决定这次对话读写哪个伙伴的记忆。平台 Gateway 是否可用由后端根据已认证的实例所有者边界派生，伙伴或 Conversation 元数据都不能授予该能力。

## 导出 / 导入：换机迁移

install 级的**迁移** Tab 提供三种 `.zip` 迁移包（仅桌面版提供迁移 UI；路径用系统对话框选取）：

| 包 | 内容 | 导入语义 |
| --- | --- | --- |
| **记忆包** | 全部伙伴的长期记忆装在同一个文件里 + mood；**可选**勾选包含原始事件数据 | 与本机记忆**合并去重**（保留原时间戳与来源）。归属在导入时**重新落户**：companion id 跨机器并不稳定，所以每条导入的记忆都会落到主人伙伴（有显式默认伙伴就是它，否则最早创建的那个），除非它原来的主人 id 恰好在本机存在。去重只在同一个主人内部比较 |
| **伙伴包** | 单个伙伴的人格 / 形象 / 设置 / XP + 它绑定的知识库**名称清单**（`knowledge_refs`），加上它自己的**记忆**（`memories.jsonl`，默认带）、可选的**技能**（行 + `SKILL.md` 正文）、以及它在用自定义形象时的**形象图片** | 以新 id 创建新伙伴，名称冲突自动缀 "(2)"；带进来的每条记忆与技能都**改归到这个新 id 名下并重新分配行 id**（伙伴包是克隆，不是合并），形象图变成这个伙伴自己的；知识库引用**按名称**匹配本机已有库自动重建绑定，匹配不到的列出来提示你先导入对应知识库包再手动绑定 |
| **知识库包** | 知识库元数据 + md 文件树原样 | 新建知识库落地，名称冲突缀 "(2)" |

换机迁移步骤：

1. 旧机：导出**记忆包**（按需勾选事件数据）→ 逐个导出**伙伴包** → 逐库导出**知识库包**。
2. 新机：先导入**知识库包**（让伙伴包的绑定重建能按名匹配上）→ 导入**伙伴包** → 导入**记忆包**。
3. 检查每个伙伴的模型设置：模型配置原样随包带走，但若新机没有配置对应 provider，会显示未配置，需在设置里重选。

> 记忆包不保留「哪条记忆属于哪个伙伴」的划分：整堆记忆都会落到同一个伙伴身上。想指定是谁，就在导入**之前**把它设为默认伙伴。若此时名册还是空的，这些记忆会被暂存，等你创建第一个伙伴后（在之后某次启动时）落户到它名下。

### 隐私边界

- `events/*.jsonl` 是**原始采集数据，包含你的工作内容原文**——默认**不**导出，只有显式勾选「包含原始事件数据」才会进记忆包。
- 原始事件不提供逐条查看或手动清空入口；由上述保留策略自动清理。关闭采集不会删除已提炼的长期记忆和技能。带原始事件的记忆包必须整体符合当前硬容量上限才会开始导入；导入成功后会立即执行同一保留清理。
- **聊天历史永远不迁移**：陪伴会话记录存在主数据库里，只留在原机。记忆与技能**会**随伙伴包走，但只带这个伙伴自己的，并且由导出范围决定（记忆默认勾选，技能默认不勾——技能正文是可执行的，要带就得明确说）。整机所有伙伴的记忆一次性搬走，仍然走记忆包。

## 旧版数据自动迁移

从单伙伴版本升级后，首次启动会自动检测旧布局 `{data_dir}/companion/nomi/`：若存在且尚无 `companion/shared/`，自动迁移为 install 级的 `shared/` 文件 + 第一个伙伴（默认名 **"Nomi"**，继承原有 XP / 人格 / 形象 / 模型 / 桌面伙伴位置 / 陪伴会话线程）。迁移幂等可重入，完成后在旧目录写入 `.migrated` 标记并保留原目录（一个版本周期后清理）。无需任何手工操作。

### 从共享记忆升级：记忆各归其主

记忆过去是全家共用的。升级后首次启动，原先共享的每条记忆都会**落户到唯一一个伙伴**名下：若显式默认伙伴仍在名册里就是它，否则是最早创建的那个。不删除、不复制——记忆的 id、内容、时间戳、强度以及置顶/归档状态都原样保留。

**但其余每个伙伴从此看不到它们，而且这一步不可撤销。** 记忆没有「重新共享」开关，也没有任何 UI 或 API 能把它改判给别的伙伴。如果你希望某个特定伙伴继承全家的历史，请在启动升级后的版本**之前**先把它设为默认伙伴。之后新建的伙伴一律从零条记忆开始。

若那次启动时名册是空的，这些行会原样留着：所有伙伴都能读到（此时并没有伙伴），落户推迟到第一次有伙伴的启动。

## 手工走查清单

验证一套多伙伴部署是否健康，按序走一遍：

1. **建两个伙伴**：新建 A、B 两个伙伴，分别改名、换形象；确认第一个带「默认」徽标。
2. **各绑一库**：给 A 绑知识库 X、给 B 绑知识库 Y（伙伴模型&知识 Tab → 知识库）。
3. **各自检索**：分别在 A、B 的聊天里提问只在 X / Y 中存在的内容，确认 A 只命中 X、B 只命中 Y。
4. **记忆隔离**：在 A 的聊天里让它记住一件事（保存记忆），切到 B 的聊天提问，确认 B **不**知道，且这条记忆只出现在 A 的「记忆」Tab 里。
5. **导出导入 roundtrip**：导出记忆包 + A 的伙伴包 + 知识库 X 的包；（换机或清空后）按「知识库 → 伙伴 → 记忆」顺序导入，确认 A 重建后绑定自动恢复、记忆合并无重复，且全部落在本机的主人伙伴名下。
6. **渠道切换伙伴**：在某个渠道平台把接待伙伴从 A 切到 B，确认活跃会话被重置、下一条远程消息由 B 的人格接待并挂 B 的知识库。

## 路由与 API

| 用途 | 位置 |
| --- | --- |
| 伙伴列表 / 创建 | `GET/POST /api/companion/companions` |
| 伙伴详情 / 修改 / 删除 | `GET/PATCH/DELETE /api/companion/companions/{companionId}` |
| install 级配置（采集 / 归档 / 默认伙伴） | `GET/PATCH /api/companion/config` |
| 某个伙伴的记忆列表 / 新增记忆 | `GET /api/companion/memories?companion_id={companionId}`、`POST /api/companion/memories`（`companion_id` 即主人；不传则由后端解析） |
| 修改记忆（只有内容 / 置顶 / 状态，改不了主人） | `PUT /api/companion/memories/{memoryId}`（`companion_id` 是*发起*的伙伴；别人的记忆一律 404） |
| 删除记忆 / 批量 / 合并 | `DELETE /api/companion/memories/{memoryId}?companion_id={companionId}`、`POST /api/companion/memories/batch`、`POST /api/companion/memories/merge`（三者都必须带 `companion_id`） |
| 某个伙伴的疑似重复分组 | `POST /api/companion/memories/merge-suggestions`（`{companion_id}` —— 扫描与返回都只限这个伙伴） |
| 每个伙伴的陪伴线程 | `GET /api/companion/companions/{companionId}/companion/threads`、`…/companion/active` |
| 某个伙伴的聊天历史日期索引 | `GET /api/companion/companions/{companionId}/history/days` → `[{day, message_count, has_digest}]`，最新在前（本地日；只读，从不铸造会话） |
| 读取会话的某一天 | `GET /api/conversations/{conversationId}/messages?day=YYYYMMDD`（最早在前，由后端划界） |
| 导出记忆包 | `POST /api/companion/export/memory`（`{dest_path, include_events}`） |
| 导出伙伴包 | `POST /api/companion/export/companions/{companionId}`（`{dest_path, knowledge_names, include_memories = true, include_skills = false}`） |
| 导入记忆包 / 伙伴包 | `POST /api/companion/import`（按 manifest.kind 分发） |
| 导出 / 导入知识库包 | `POST /api/knowledge/bases/{id}/export`、`POST /api/knowledge/bases/import` |
| 渠道绑定伙伴 | `POST /api/channel/settings/companion` |

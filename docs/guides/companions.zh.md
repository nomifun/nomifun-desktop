# 伙伴（Companions）

可创建多个伙伴，分别设置名称、形象、人格、模型和知识库。每个伙伴拥有自己的记忆、学习设置、技能、XP 与情绪；数据采集设置属于整机。记忆、伙伴和知识库支持 ZIP 导出导入。

同一个伙伴同时具有**伙伴**和**机器人**两个执行角色，可以分别选择 Agent 与默认模型。桌面、浮窗和消息渠道使用伙伴角色，物理设备使用机器人角色；人格和长期记忆仍归属于同一个伙伴。双角色、多会话与共享上下文的实施及验收状态见[伙伴架构](../architecture/companion.zh.md)。

伙伴统一用可直接朗读的自然语言回复，禁止颜文字、emoji、表情包或贴纸标记，以及动作、神态和舞台描写；情绪通过措辞表达。自定义人格、记忆和技能不能覆盖这项规则。桌面气泡与机器人播报会过滤可识别的非语言装饰，避免打断对话和语音。

> 入口是侧边栏的 **桌面伙伴** 页（即 `/nomi` 路由）；任意桌面伙伴窗口右键菜单的「打开聊天」也会深链到这里。

## 页面结构：伙伴花名册 + 相处 / 管理

「桌面伙伴」一级页面承载完整伙伴体验。左侧花名册用于切换伙伴，并可通过标题栏中的列表开关收起或展开；不再把伙伴混入工作「会话」树。选中的伙伴拥有两个一级模式：

| 模式 | 页面 | 内容 |
| --- | --- | --- |
| 相处 | 多会话聊天 | 分别查看伙伴、机器人会话及其独立历史，以及精简的状态、共享记忆与连接摘要 |
| 管理 | 总览 | 名称、形象、桌面显示、等级、人格，伙伴 / 机器人各自的 Agent 与默认模型，以及语音 / 视觉槽位 |
| 管理 | 记忆与知识 | 仅属于当前伙伴的记忆和知识库绑定 |
| 管理 | 渠道与机器人 | IM 渠道、实体机器人与伙伴会话的 MCP 连接 |
| 管理 | 进化 / 技能 | 学习节奏、采集来源、保留策略、休眠时段，以及自动生成和已配置技能 |
| 管理 | 历史 / 迁移与删除 | 按天回看聊天、迁移包和不可逆删除 |

原生桌面快捷窗是同一产品的轻入口：可快速切换伙伴、查看最近对话、立即回复，并深链到完整相处页或管理页；它不会出现在工作会话侧边栏。

相处页顶部提供会话选择器、**新会话**和角色标记。伙伴信息侧栏可以直接修改**桌面显示、状态**，并分别配置**伙伴**与**机器人**的 Agent 和模型。桌面显示控制原生形象窗口，仅桌面端可编辑；状态默认自动跟随学习产生的情绪，手动选择后持续保持，切回「自动」会显示最近学习到的情绪。

查看某个角色的会话时，同角色设置区会说明「更新当前会话，并保存为此角色的后续默认」；另一个角色的设置区只修改后续默认。当前会话的 Agent 与模型必须在空闲、操作已结算时明确切换，保留该会话身份与历史。修改默认值不会改变其他已有会话。当前会话更新成功、默认值保存失败时，界面会分别说明结果并提供重试。

会话区域空间不足时，伙伴信息侧栏会隐藏；增大工作区后可用侧栏按钮恢复。

桌面收起态直接展示最多三个备选伙伴。目标伙伴已有可见窗口时会被提到前台；尚未显示时，则先在当前位置准备好目标窗口，成功后才替换当前形象，避免切换失败后桌面变空。
展开后的「完整相处页 / 管理伙伴」统一收进**更多**。拖动面板任意非交互空白区域即可调整原生窗口位置；收起后会保留新的桌面伙伴位置。
GUID 首页仍保留创意伙伴展台，承担氛围展示、发现与深链入口；从这里选择伙伴会进入「相处」，不会在工作会话树中创建或插入伙伴条目。

## 创建与管理多伙伴

1. 点伙伴条上的**新建伙伴**，起个名字、挑一个形象（mochi / ink / roux / pixel / bolt / boo 六款）即可。
2. **第一个伙伴自动成为默认伙伴**（卡片带「默认」徽标）。渠道仍需明确绑定，不会自动取得默认伙伴的身份。
3. 在**管理 → 总览**里可以随时改名、换形象、调人格、**分别选择伙伴和机器人的默认 Agent 与聊天模型**并开关桌面窗口；勿扰时段与学习配置位于**管理 → 进化**。
4. **删除伙伴**会级联清理：它的**记忆**、技能、陪伴会话、运行时状态（XP 等）、`('companion', companionId)` 知识库绑定一并移除；若删的是默认伙伴，默认资格自动顺延给下一个。由于每条记忆都属于某一个伙伴，删掉伙伴就等于永久删掉记在它名下的记忆——想留住就先把它导出（伙伴包默认带走它的记忆）。删除允许删到零个——采集照常运行，但一个伙伴都没有时根本不存在学习循环（节奏属于伙伴），事件只会先攒着，等你建出伙伴再学。

每个伙伴的配置保存在 `{data_dir}/companion/companions/{companion_id}/config.json`，伙伴包以这个身份为单位导出、导入。会话归属与历史由正式 Session 事实保存，不能从目录名推断。

### 修改伙伴的 Agent 设定

在**管理 → 总览 → 模型配置**分别选择伙伴和机器人使用的 Agent；相处页侧栏提供同样的两个角色设置区。默认分别使用官方**伙伴**和**机器人**（`companion.robot`）Agent，也可以选择满足对应角色要求的个人 Agent。伙伴角色负责电脑端工作，机器人角色负责物理设备交互及向伙伴委派桌面任务，二者同时可用。

这只是默认分工。Agent 工作台对所有预设展示完整能力和动作目录，可以按需给伙伴增加机器人能力，或给机器人增加电脑、文件及协作能力；所选能力按正常授权和资源配置生效。

点击**编辑 Agent**可打开所选官方或个人 Agent。使用同一个 Agent 的伙伴共享其已保存配置，各自的人格与资源归属仍独立。编辑后，使用**应用最新设定**明确更新当前空闲会话；仅保存 Agent 配置不会热替换已有会话。选择器会说明不可用的原因，实际工具还须满足角色、资源、设备许可和运行环境要求。

机器人默认模型未单独设置时继承伙伴模型；保存独立模型后使用自己的选择。**后续默认改为继承伙伴模型**只清除机器人模型覆盖（`robot.model=null`），不改写已有机器人会话的模型。两个角色可以使用不同模型，机器人不必为了接待语音而加载桌面伙伴的全部工具。

正在回复、暂停等待恢复，或尚有未结算操作时，先完成或结束当前工作再修改。若当前会话已经更新、但后续会话的默认设定保存失败，界面会明确提示，并可通过**应用最新设定**重试；当前会话仍以已提交的设定为准。其他保存失败不会把界面选择当作已生效的设定。修改 Agent 不会把这个伙伴的记忆、知识库或机器人权限转给另一个伙伴。

### 多会话与输入目标

**新会话**为当前伙伴创建一条独立的伙伴会话，保留伙伴人格与长期记忆。新会话拥有自己的工作上下文，不复制全部历史，也不清空其他会话。会话选择器可以查看同一伙伴的伙伴或机器人会话，机器人会话带有角色标记。

查看或新建会话不会自动改变浮窗的输入目标。要让浮窗后续输入进入正在查看的伙伴会话，点击**在浮窗继续**；**浮窗正在此会话**标记说明当前收件目标。机器人按伙伴和确切设备接收输入，渠道按自己的绑定接收消息；切换页面或在另一个窗口查看聊天不会改投这些输入。

删除一条会话只清理该 Session，不删除伙伴的共享工作目录和长期记忆。删除整个伙伴才进入所有所属会话、效果和目录的清理流程；活动工作或未确认的操作可能阻止删除。归档和清空上下文也不等于新建会话。跨会话查看任务不会授予控制权限，审批与问题仍须在对应任务中明确处理。

### 多个桌面伙伴同屏

每个开启了桌面伙伴开关的伙伴拥有自己的桌面窗口（透明、置顶、可拖动，窗口 label 为 `companion-{companionId}`）。多个可以同屏共处；建议同屏不超过 5 个（每个窗口是独立的 WebView 实例，开太多影响性能，UI 会提示但不硬限）。右键任意桌面伙伴窗口可直达它的聊天页。

## 记忆、采集与学习

每条记忆只属于一个伙伴。同一伙伴的两个角色和多条会话共享长期记忆，并可按需查询该伙伴的经历；不同伙伴保持隔离。最新共享内容在后续模型调用时读取，已经发出的模型请求不会被追溯改写。共享经历帮助理解当前请求，不会自动重新执行旧任务。学习设置、生成技能、XP 和情绪也分别保存。在聊天中保存的记忆属于参与当前对话的伙伴。

- **采集**按已启用来源记录工作数据，供学习使用。原始学习事件与持久化会话历史是两份不同用途的数据；学习采集只记录用户输入，不代表聊天历史不保存模型回复。
- **保留策略**默认为 30 天目标期限与 64 MiB 硬容量。过期数据在启用的消费者处理后清理，但容量上限可优先淘汰最旧的未处理数据。“数据采集”显示占用与日期范围，可配置 7–365 天、16–512 MiB。
- **学习**在每个伙伴的“进化”页配置间隔和学习模型，学习模型可与聊天模型不同。
- **技能生成**可将重复工作提炼为该伙伴的技能。使用前查看内容及保守/激进设置。
- **休眠时段**暂停该伙伴的学习、进化与桌面气泡，收到 IM 消息仍可正常回复。

关闭采集不会删除已有长期记忆与技能。原始事件包含工作内容，默认不随导出携带；带原始事件的导入必须符合当前容量上限。


## 给伙伴绑定知识库

在伙伴管理页使用知识库绑定控件选择知识库。绑定属于当前伙伴，普通会话继续使用自己的选择。知识库是长期记忆之外的资料来源，可在**知识库**（`/knowledge`）管理。

回写选择**手动型**时，需在对话中明确要求才添加知识；**自动型**由 Agent 判断是否沉淀长期、可复用的事实。知识库可从 ZIP 导入，或从公网 HTTP(S) URL 创建。快照来源保存可刷新的本地副本，实时来源在需要时抓取。AI 描述与梗概需要已配置模型。

所选 Agent 仍须具备相应能力和资源，伙伴名称或知识库绑定不会授予新工具权限。

## 渠道绑定伙伴

每个 IM 平台（Telegram / Lark / 钉钉 / 微信）都可以绑定接待远程消息的伙伴：打开该伙伴的 **Remote** tab（`/nomi?companion=<id>&tab=remote`），在那里连接或改绑 bot。渠道行可以保存直接绑定；未直接绑定时才读取平台偏好 `channels.{platform}.companionId`。两级都没有解析到存活伙伴时，渠道保持未绑定，不会隐式取得另一个身份。切换或删除绑定会重置受影响的活跃会话，使下一条消息重新解析归属。详见 [Channels 指南](./channels.zh.md)的「渠道 Agent 接入」一节。

> companionId 不授予任何权限：它决定 persona / 模型 / 知识库挂载，也决定这次对话读写哪个伙伴的记忆。平台 Gateway 是否可用由后端根据已认证的实例所有者边界派生，伙伴或 Conversation 元数据都不能授予该能力。

## 导出 / 导入：换机迁移

install 级的**迁移** Tab 提供三种 `.zip` 迁移包（仅桌面版提供迁移 UI；路径用系统对话框选取）：

| 包 | 内容 | 导入语义 |
| --- | --- | --- |
| **记忆包** | 全部伙伴的长期记忆装在同一个文件里 + mood；**可选**勾选包含原始事件数据 | 与本机记忆**合并去重**（保留原时间戳与来源）。归属在导入时**重新落户**：companion id 跨机器并不稳定，所以每条导入的记忆都会落到主人伙伴（有显式默认伙伴就是它，否则最早创建的那个），除非它原来的主人 id 恰好在本机存在。去重只在同一个主人内部比较 |
| **伙伴包** | 单个伙伴的人格 / 形象 / 设置 / XP + 它绑定的知识库**名称清单**（`knowledge_refs`），加上它自己的**记忆**（`memories.jsonl`，默认带）、可选的**技能**（行 + `SKILL.md` 正文）、以及它在用自定义形象时的**形象图片** | 以新 id 创建新伙伴，名称冲突自动缀 "(2)"；带进来的每条记忆与技能都**改归到这个新 id 名下并重新分配行 id**（伙伴包是克隆，不是合并），形象图变成这个伙伴自己的；知识库引用**按名称**匹配本机已有库自动重建绑定，匹配不到的列出来提示你先导入对应知识库包再手动绑定 |
| **知识库包** | 知识库元数据 + md 文件树原样 | 新建知识库落地，名称冲突缀 "(2)" |

换机迁移步骤：

1. 旧机：导出**记忆包**（按需勾选事件数据）→ 逐个导出**伙伴包** → 逐库导出**知识库包**。
2. 新机：先导入**知识库包**（让伙伴包的绑定重建能按名匹配上）→ 导入**伙伴包** → 导入**记忆包**。
3. 检查每个伙伴的模型设置：模型配置原样随包带走，但若新机没有配置对应 provider，会显示未配置，需在设置里重选。

> 换机后，原主人 ID 在本机不存在的记忆会分配给本机默认伙伴，或最早创建的伙伴。导入前先选好默认伙伴。若要把某个伙伴的记忆带到它的新身份，使用该伙伴的伙伴包。

### 隐私边界

- `events/*.jsonl` 是**原始采集数据，包含你的工作内容原文**——默认**不**导出，只有显式勾选「包含原始事件数据」才会进记忆包。
- 原始事件不提供逐条查看或手动清空入口；由上述保留策略自动清理。关闭采集不会删除已提炼的长期记忆和技能。带原始事件的记忆包必须整体符合当前硬容量上限才会开始导入；导入成功后会立即执行同一保留清理。
- **聊天历史永远不迁移**：陪伴会话记录存在主数据库里，只留在原机。记忆与技能**会**随伙伴包走，但只带这个伙伴自己的，并且由导出范围决定（记忆默认勾选，技能默认不勾——技能正文是可执行的，要带就得明确说）。整机所有伙伴的记忆一次性搬走，仍然走记忆包。

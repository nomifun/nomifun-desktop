# NomiFun 应用

侧栏「应用」的首页提供「创建」和「导入」两个入口。卡片展示名称、说明、标签和实际运行状态。
搜索匹配名称、说明和标签，分类与分页作用于当前登记的应用。点击卡片进入这个应用的工作区。

## 创建、开发和继续修改

1. 点击「创建」，进入应用工作区。左侧是这个应用的项目会话，右侧是当前应用的详情、设置、操作与程序预览。
2. 输入框固定使用「内置应用」Agent；选择可用的模型后描述需求。无需先到工作台创建编程 Agent，
   也无需另选开发文件夹。应用自己的目录就是这次普通会话的工作区。
3. Agent 使用普通文件与进程工具开发项目，按需读取开发指南，并填写同一应用的名称、说明、标签和命令。
   完整的消息、思考、工具过程和历史沿用普通会话，不隐藏为一条“已完成”。
4. 在右侧查看实际设置和输出，预览或开始使用。运行中只表示受管进程存在，仍需检查实际业务功能。
5. 以后从应用卡片重新进入工作区，通过「项目会话」继续历史会话，或点击「新会话」开始下一项修改。
   这些会话共享同一个应用目录，修改直接作用于当前项目；需要重新准备时点击「重新构建并启动」。

一个应用对应一个独立项目，使用该应用自己的托管目录；不同应用不共用项目。
同一应用项目可以有多个会话，
历史列表包含名称、时间和运行状态，并可继续查看已归档会话。文件与应用设置属于项目，
切换会话时保留右侧预览和未保存的设置。会话记录仍由统一的 canonical Session 存储管理，
不会在源码目录中再复制一份聊天日志。

新会话从当前项目文件开始，聊天上下文独立；在同一 Host 运行期间，由 Agent 写入的项目记忆可由同项目的新会话读取。
现役记忆 owner 不跨 Host 重启持久化；项目文件与 canonical 会话历史持久保留。
不同项目的新会话使用不同记忆范围。已有会话的冻结配置和旧记忆范围保持原样，
新会话不会自动加载项目全部历史消息。应用项目会话只从「应用 → 对应应用 → 项目会话」管理，
不会混入「会话」侧栏、普通项目或普通会话的批量操作。搜索和旧会话链接会打开所属应用。
普通会话即使使用相同目录或相同 Agent，也不会变成应用专属会话。
已切换为其他 Agent 的应用专属会话仍在应用内只读查看，不自动替换它的配置。

例如：

> 帮我开发一个待办通知应用，支持新增、完成和删除，刷新后保留数据。
> 通过普通后端显示 NomiFun 的连接状态，检查实际功能并配置预览和启动命令。

开发 Agent 与应用运行时调用的 Agent 分开选择。前者是工作区固定的「内置应用」；
后者只在应用需要请求平台 Agent 时，在右侧高级配置中选择。
运行时可选择官方对话 Agent（例如「最简」「通用」）或个人 Agent；官方选项使用工作台中已保存的配置，
不要求先创建个人副本。平台仍准备本应用的 RemoteBinding，应用后端收到的是连接引用。

## 导入已有代码或产物

点击「导入」进入相同布局的工作区。选择源码或编译产物，提供 Host 上的文件夹/ZIP 路径，
或从当前电脑上传 ZIP。桌面端还可使用文件夹和 ZIP 选择器。文件复制到应用自己的目录，原文件保留。

右侧可以直接手工导入、修改说明和命令、保存设置并运行，**不要求配置模型或使用 Agent**。
也可在左侧请内置应用 Agent 检查项目，区分需要构建的源码与可直接运行的产物，填写配置并协助导入。
已有当前应用时，导入始终更新这个应用，保持相同 ID、目录和开发会话。

命令识别来自项目脚本、锁文件和常见入口，并非所有技术栈都能自动识别。
高级配置可修改项目子目录、安装、预览、构建、生产启动、静态产物目录、网页地址、Node 路径和环境变量。
项目目录是应用目录内的相对路径；非必需命令可留空。静态产物可选择普通 HTTP 预设，
SSR、Python 或其他后台服务填写真实的前台启动命令。无网页的应用不必填写网页地址。

## 预览、使用和停止

首次「预览」执行安装和预览命令；没有预览命令时执行安装、构建和启动。
「开始使用」执行安装、构建和启动，之后日常「启动」只执行启动命令。
「重新构建并启动」先停止，再安装、构建和启动。任何一步失败即停下，保留实际错误与有限输出。

右侧程序预览按需加载应用自己的普通 HTTP(S) 页面，支持放大、收起、关闭预览，也可在浏览器打开。
关闭或收起网页不会停止程序；停止生成与停止应用是不同操作。预览与使用共享当前文件和数据，
切换时先结束原进程树，不保留两份常驻服务。

嵌入预览不加载 NomiFun renderer 同源页面，也不向应用注入 SDK、平台凭据或前端 Bridge。
应用页面若禁止嵌入，可使用浏览器打开。远程 WebUI 不会把 Host 的 localhost 当成当前电脑的地址；
仅本机可达的网页不能从另一台电脑直接预览，应用提供可达网页地址后才能打开。平台不提供跨机网页代理。

Node 默认来自系统 PATH，也可以指定已有可执行文件。Node、npm、Bun 分别检测。
缺失时可打开 [Node 官方下载页](https://nodejs.org/en/download)，已有环境不会自动替换；其他工具按实际错误处理。

## 文件更新与删除

会话修改直接写当前应用目录。「覆盖」从外部来源替换当前文件并保留来源中没有的业务数据，之后重新构建。
导入助手重新识别来源与运行命令；普通覆盖保留当前设置，两者都保持应用身份。

开发回合活动或存在未结算、结果未知的效果时，手工导入、覆盖和删除拒绝执行，避免和 Agent 同时改文件。
先停止开发，并由原操作确认或处理未结算结果，再重试。详情读取、名称/说明/标签等设置保存和停止应用仍可使用。
未确认的操作不能靠再次点击自动重放。

删除确认会展示应用专属会话数量。确认后停止进程树，删除应用自己的源码、产物、本地数据、
专属项目会话及其历史，再移除应用登记。原导入来源、外部数据、普通会话和其他应用保留。
应用会话不能从普通会话删除入口误删。删除遇到未确认清理时保留应用登记和文件，处理后可重试。

应用管理不提供版本、部署、发布、业务数据库迁移、回滚或专属创作验收流程。

## 应用连接 NomiFun

预览和启动的后端进程自动获得 `NOMIFUN_HOST_URL`、`NOMIFUN_LOCAL_TRUST`，
以及需要时的 `NOMIFUN_AGENT_BINDING_ID`。用户不填写 token，不安装 SDK，不经过额外权限审批。
安装、构建和静态网页不会获得凭据；网页通过自己的普通后端调用已有 REST 接口。

```js
const response = await fetch(`${process.env.NOMIFUN_HOST_URL}/api/apps`, {
  headers: { 'x-nomi-local-trust': process.env.NOMIFUN_LOCAL_TRUST },
});
if (!response.ok) throw new Error(`NomiFun returned ${response.status}`);
const result = await response.json();
```

不要把环境变量内容返回网页或输出日志。Host 重启更换凭据，应用下一次启动获得新连接。
调用 Agent 复用现役 [REST open / turn / observe / cancel](remote-capability-api.zh.md)；
平台准备连接引用。更换或清除运行时目标 Agent 前先停止应用，下一次启动使用新配置。

应用也可提供普通 MCP 地址。平台沿用现役发现与调用链，必须由 Agent/会话明确选择应用来源，
不会默认加入所有 Agent。MCP 失败只提示当前来源，不自动启动程序。Provider、Skill、主题仍使用原有入口。

## 在个人 Agent 中使用应用开发能力

个人 Agent 也可在工作台选入系统能力「NomiFun 应用开发」，并选择需要的导入、配置、预览、重新构建和启停动作。
编程仍由原有工作区和进程能力提供，详细指南由 `read_app_guide` 按需读取。
只有应用工作区的官方「内置应用」模板默认选择这组动作；其他官方模板不默认启用。
已有个人配置和冻结会话不会因模板更新自动扩权。

个人 Agent 在普通外部工作区开发时，可以导入托管副本；导入不会自动扩大该会话的文件权限。
要继续修改托管文件，可从应用卡片进入固定内置应用工作区，或明确把托管目录绑定为普通会话工作区。

支持 Tauri 与桌面级 WebUI，最低窗口 880×600。实现边界见 [应用托管架构](../architecture/app-hosting.zh.md)。

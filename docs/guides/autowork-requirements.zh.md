# AutoWork 与需求平台

AutoWork 将带同一个标签的需求交给绑定的 AgentSession 逐条处理。需求平台负责排队和结果，工作过程保留在同一个主会话中。已启用的绑定在后端启动后恢复；只关闭浏览器页面不会停止，退出宿主进程会停止运行。

![AutoWork 总览](../images/autowork-01-tag-sessions.png)

## 提交与查看需求

1. 打开**需求平台**（`/requirements`），点击**新建需求**。
2. 填写标题、标签和内容。内容写清背景、要做的工作与完成条件。
3. 设置排序键，越小越早；按字符串字典序比较，例如 `1.0`、`1.1`、`1.2`。
4. 保存为 `pending`。已有会话启用该标签时，会在前面的工作完成后认领它。

列表支持标签、状态和全文过滤，点击需求打开详情抽屉，可在其中编辑。看板位于 `/requirements?view=board`，按状态展示同一份数据；更改状态使用详情控件。

![需求列表](../images/autowork-02-list.png)

## 开启自动执行

1. 打开具备合适模型、能力和工作目录的普通会话。
2. 在会话头部的 **AutoWork** 控件选择标签，可选设置完成数量上限，然后启用。
3. 在主会话查看 Agent 的流式工作和结果。AutoWork 复用绑定会话，不为每条需求创建协作子会话。
4. 在**需求平台 → 扩展能力 → 自动执行**（`/requirements/extensions?tab=autowork`）集中查看绑定与 Idle、Active、Paused 状态。

队列为空时保持等待，新需求到达后继续。达到数量上限、主动关闭或删除绑定会话后停止。已打开会话使用其冻结配置；先确认模型、资源和工具适合待执行的需求。

## 暂停和人工检查

需求通常从 `pending` 进入 `in_progress`，再结算为 `done`、`failed` 或 `cancelled`。进程中断、租约到期或外部效果不确定时，可能进入 `needs_review` 并暂停标签。到期不代表操作未发生，不能依靠重复提交来确认。

先检查主会话、需求结果和实际文件或外部操作，处理需要人工输入或结果未知的问题，再点击会话头部的**恢复执行**。这次显式操作才会重新排队失败项并继续。模型回答“完成”也不能替代真实结果检查。

模型调用的故障转移与[智能决策](intelligent-decision.zh.md)属于另一层控制；AutoWork 不为终端中的第三方 CLI提供队列执行。

## 完成通知

在**需求平台 → 扩展能力 → 通知**（`/requirements/extensions?tab=notify`）创建通知渠道，可选择**飞书/Lark**、**通用 HTTP**或 **Slack**。

1. 填写名称、URL，飞书可选填写签名密钥，保存并启用。
2. 使用**测试**确认渠道可达。
3. 在同页的标签路由中为标签绑定渠道，选择完成、失败、待复核等需要通知的事件。
4. 清空绑定或停用渠道可停止该路由的通知。

通知包含需求与结果摘要。发送失败会记录诊断，但不会回滚已结算的需求结果。群聊机器人接入与通知 webhook 是不同配置；双向聊天参见[渠道](channels.zh.md)。

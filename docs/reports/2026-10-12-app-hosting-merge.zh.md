本次按用户要求先保存应用托管工作，再合入远程 main；用户随后明确要求推送 `origin/main`。
本报告记录代码与验证，不代表安装包发布。
原实现提交为 `c5f7adbf2`，第一批远程合并为 `c9d3865f8`（远程 `ae44c172b`）。
验证期间远程继续新增 5 个提交，随后接入 `102e52654` 的 0.8.5 版本号、更新清单与启动测试修正。

## 实际整合

- 保留应用首页、创建/导入、普通会话开发、配置自动识别与内嵌预览，以及一个应用一个自有项目目录、多份普通 canonical Session 的实现。
- 接入远程的官方 Agent 身份、普通 Agent 切换、资源选择、原生执行与工具展示预算；应用开发使用正式官方模板。旧个人 App Agent 的合法历史保留，不通过同名猜测官方身份。
- 应用工具按本轮最终授权集合原子预激活，避免五项搜索分批挤掉导入动作；仍遵守授权与可见工具数硬上限。
- 数据存储位置迁移接入纯离线 App 登记检查、精确目录复制、正式 canonical 位置证明和登记目录重写。保持 owner、逻辑资源 ID、权限、原始历史不变；同项目的新 Session 复用迁移后的 scoped memory 身份。
- 修正同一次多 Session 迁移的全局幂等键冲突、未发布登记重写后的中断恢复，以及重复源 SQLite 探测产生 sidecar 的问题。重试继续核验完整源摘要、暂存库和所有应用文件，不扩大复制豁免。
- 已删除应用的普通 Session 在后续数据迁移后仍可读取合法历史；不补建应用目录、不制造新的路径授权。损坏的证明或当前定义仍拒绝读取。
- 删除分支只释放有明确来源的闲置运行资源，保留 canonical 事实；无关 fork、其他 owner、活动调用和未知效果继续受保护。
- 被替代的 Plugin 平台、开发域、JS Runtime、旧 UI 与 SDK 没有恢复。外部工具检查改为核验现役 Node、普通命令进程 owner 与独立环境探测。

## 边界与未覆盖项

- 本次没有重跑真实 LLM 生成、原生桌面窗口验收或 macOS/Linux 安装与签名发布。此前产品闭环记录保留在同目录的应用实现与项目会话报告中，不能把它们当作本次最终版本的复测。
- scoped project-memory 保持现役 Host 内存存储合同；源码及 canonical 历史持久保留，不声称 memory 跨进程重启持久。
- portable backup/restore/reset 尚未完整纳入应用文件根与登记路径的专门处理。这是现有覆盖缺口，本次只完成同一数据集的位置迁移；没有操作用户真实备份、恢复或重置。
- `.tmp` 的测试数据库、密钥、锁与日志保留在磁盘且不提交。源码冲突全部解决；上游 Node 许可证的原始缩进保留，源码与本次文档的 whitespace 检查通过。

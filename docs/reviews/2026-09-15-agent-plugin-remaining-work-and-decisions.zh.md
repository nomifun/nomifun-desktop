# Agent 插件开放化：剩余工作与产品决策

日期：2026-09-15。最新决定：值得开发的能力必须开放可用，不长期隐藏在实验开关后。hooks 只新增 before_tool/after_tool；页面复用已有会话工作区，保留业务输入与结果展示；应用 Shell 替换和其他 hook/UI 扩展候选移出计划。外部模型插件、安装型/热加载引擎仍取消，保留内置模型和源码引擎。当前在 Windows 开发，macOS 按交接 TODO 验证；未执行制品发布。

已有页面入口开放及 Windows 定向回归已完成，证据见发布台账 §2.7；发布剩余工作为安装包、真实模型和 macOS 验收，见本文 §3。本轮移除已有页面的实验开关；新 hooks 与业务页面增强尚未实现，不能计为已交付。发布声明按真实完成项确定，不以未完成能力填充支持清单。

## 2. 已确定的原则：不重复要求用户决策

- 正式默认保持内置 Agent、模型链路和 UI。
- 已支持 Tool、Context、discovery、`before_model` 和包内只读 Skill，限已接线来源与阶段，不承诺全领域替换。
- Rust native Service 和 SDK 已删除，不再提供启用或作者开发承诺。Node 普通 Service 与内置模型 Broker/生产模型合同保留；已删除的 Service streaming 不作为当前能力。
- 插件 Agent 页面正常开放选择，内置仍默认；无需实验开关，插件不能自授权，Shell 替换计划取消。
- 外部插件模型 Provider 已取消；整 Runtime 仅走源码注册/编译打包接入，不保留安装型或热加载替换待办。深层基础设施仍为未排期候选。
- 当前 capability 插件 hook 仅 `before_model`；新增只保留 before_tool/after_tool，尚未实现。完成后直接作为可选能力发布，使用不要求开发者开关。
- 保留唯一编译/执行授权链，最小信任根不交给普通插件自行替换或绕过。
- 当前共享桌面 renderer 最小 880×600；不把手机、平板或独立 Mobile 产品加入此次目标。

未来如需改变上述原则，应提出明确变更和代价；历史原生插件讨论不构成恢复后端的授权。

- 用户原则：在保证结论可靠的前提下，选择交付最快的方案，由代理选择执行方式，不再要求用户比较流程方案。
- 执行方案：复用已有自动化专项证据，并在最先具备已授权模型配置的环境补最小实模冒烟；不新建测试平台，不扩展多厂商覆盖。
- 环境记录：此前仅检查专用 `NOMIFUN_LIVE_STEPFUN_API_KEY` 是否存在，结果为未配置，未读取凭据库或用户日常密钥；本轮文档修改未重新检查环境。不为实模另搭平台，优先把 §8.1 最小检查交给已有配置的产品环境（用户或目标机接手者）；若本机先获得专用环境，则由代理执行。不把目标环境已就绪当作事实。
- 自动化备选：已有 `scripts/validation/run-nomi-core-live-provider-smoke.mjs` 支持 `--engine-smoke --engine-family=nomi`，固定 StepFun `step-3.7-flash`；仅在相应测试凭据可用时复用，不改写成通用模型平台。该窄测不证明双引擎或全部插件来源。
- 结论：D4 的方法已确定，R5 实模证据仍待完成；环境未就绪不阻止其他开发，但不得因此宣称实模通过或全部上线验收完成。不要在聊天、文档或日志中粘贴密钥。

### 8.1 D4 最小实模交接检查

1. 记录实际候选提交/制品、OS/架构及模型名称；在隔离测试数据目录使用已有模型配置，不修改生产用户数据。
2. 在默认内置 Agent/UI 中发起普通请求，确认真实模型响应、流式结束、无服务错误；不能只看界面显示成功。
3. 安装/选择一个已验证的无副作用插件 Tool，在会话中明确请求调用；核对实际调用记录和预期结果，再发一轮确认会话可继续。若模型未调用工具，记录未覆盖，不把文字声称调用算作成功。
4. 保存脱敏结果和失败信息，回填发布台账 R5/P0-2。已有自动化专项承担其他 Context/Skill/discovery/before_model 的定向证据；此最小实模不证明全部来源、阶段或模型服务。

此检查并入安装后技术验收，不新增用户试用阶段。没有实模环境则保留待验标记；失败需定位影响正式范围的问题，不能通过缩小描述掩盖实际缺陷。

### D5：彻底删除 Rust native 插件后端与 SDK（最新决定已确认）

- 最新决定替代此前“默认关闭但保留”：原生插件后端、Rust 作者 SDK、示例、专属打包/测试和启用入口已移除，不保留可信开发者实验。
- Node 普通 Service、存储 IPC/生命周期、内置模型 Broker/合同及普通产品路径保留；Service streaming 已删除，不增加授信、沙箱或分发体系。
- Windows 删除专项回归已通过，具体证据统一见[发布台账 §2.5](2026-09-15-plugin-release-readiness.zh.md#25-原生插件删除后的验证进展2026-09-15)。历史 native 测试不代表现行支持，正式制品与跨平台验收尚未完成。
- Windows x64 + macOS arm64 首发不变；平台交接只要求 Node/正常产品的适用验收，不再要求 native 插件验证。

### D6：页面直接开放，Shell 不做（已确定）

- 已有 Agent 页面移除实验环境变量及隐藏门槛，普通用户可选，内置仍默认，不默认信任或自动选择第三方。
- 页面内业务输入与结果展示为唯一增强项 U1；Shell、独立插槽系统和全部客户端交互不做，不再要求用户比较整包方案。
- 保留精确发布身份、owner/Session 授权、停用撤销、取消和切回内置；开放功能不等于取消安全边界。

### D7：下一开放化工作包（优先 hooks 设计）

- 已筛选保留 H1a 工具前门禁、H1b 工具结果消费视图；H2 和其他阶段移出计划，不再逐项讨论候选。
- 具体生产落点、失败/取消边界和验收见 [hooks 设计](2026-09-15-agent-hooks-design.zh.md)。当前只有设计，下一步实施按单张纵向卡推进，不同时启动全部候选。
- 其他能力继续未排期，不要求用户重新比较外部模型插件或热加载引擎；新 hooks 未经实际实现和验证，不计入既有 release 的支持声明。

### D8：是否有必须运行脚本的 Skill 需求？

- 问题：只读 Skill 是否已经足够，还是存在需要 shell/fork/hook 的具体用例？
- 建议：没有明确用例就维持只读范围；有需求再按最小执行模式设计权限、取消和副作用管理。
- 备选：将具体可执行 Skill 用例纳入后续工作包，但不能通过放宽解析或直接执行包内脚本临时实现。
- 影响：E6 的安全和实现范围；该项可以延期决策，不阻塞近期上线。
- 结论：维持包内只读范围，可执行 Skill 延期；不单独提问或放宽执行权限。更多 Agent hooks 的设计不等于授权执行 Skill 脚本。

## 9. 实施范围与完成标准

以 §0.1 为 hooks/UI 唯一开发清单，D1～D5 的发布与删除决定保留。外部插件模型 Provider、安装型/热加载整 Runtime、Shell 和被筛除的 hook/UI 扩展不再是开发目标。新 hooks 未实现；已有页面移除开关，普通用户可以选择使用。

对仍在范围内、获准实施的安装型插件领域，只有同时具备以下证据才记为完成；此标准不用于要求源码 Engine 改成安装型插件，也不把 hooks 设计草案算作运行时交付：

1. 插件能按支持方式发布、安装。
2. 用户有明确选择入口。
3. 唯一编译链冻结身份、依赖和权限。
4. 实际生产消费者使用所选实现。
5. 失败、取消、撤下与资源回收符合声明。
6. 所声明 OS/架构完成相应验收。

当前发布剩余项按 §3 R1～R7 执行，制品、Windows x64 + macOS arm64 和最小实模仍须取得实际证据。长期新领域、hooks 运行时和完整 UI 不自动成为本次上线条件，也不构成新一轮全量开发授权。

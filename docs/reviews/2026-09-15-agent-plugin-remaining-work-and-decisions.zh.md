## 0. 历史全局方案（已由本轮批准的收敛范围替代）

本节保留此前方案的背景，不再作为待回答问题或现行执行指令。曾提出的“除 native 外全部保留”“共享流式继续保留”已被最新审查清理决定替代；制品验收与数据安全要求仍适用。

### 0.1 已固定的约束

| 已决定 | 本次执行含义 |
|---|---|
| Windows x64 + macOS arm64 首发 | 当前做 Windows；macOS 在目标机交接开发/验收。其他架构和 Linux 不排期 |
| 直接正式上线 | 不设置灰度、试用阶段或反馈等待窗口；仍做必要技术验收 |
| 兼容投入最小 | 保留已有迁移，不新增历史版本适配、转换工具或升级矩阵；不删旧数据 |
| 结论可靠前提下选最快测试方式 | 复用已有专项，只补安装后链路与最小实模；不新建测试平台 |
| Rust native 后端/SDK 删除 | 删除原生插件执行、启用入口、SDK、示例及专属打包/测试路径；已移除，Windows 删除专项回归通过；保留 Node 与共享 Service 能力 |
| 默认 Agent/模型/UI 保持内置 | 允许用户主动选择插件页面与“默认换掉内置页面”是两回事，不能混为一谈 |

### 0.2 只需要选择的两个整包方案

| 维度 | A：最短交付（推荐） | B：首发增加可发现的页面定制 |
|---|---|---|
| 现有 Tool/Context/发现策略/before_model/只读 Skill | 按已支持边界交付，修阻断缺陷 | 相同 |
| 用户 capability/Provider 选择与组装 | 交付已接线机制，不扩新领域 | 相同 |
| 插件 Agent 页面 | 保留已有能力与环境变量启用，默认关闭 | 默认允许用户发现、主动选择基础插件页，内置页仍默认；继续标明实验/有限支持 |
| Rust native | 按最新决定彻底删除，不保留显式启用实验 | 相同，不随 UI 改变 |
| 新领域、可执行 Skill、整 Runtime/Shell | 全部延期，不预建接口或中间实现 | 相同 |
| 新增功能工作 | 无新增功能包；只做验收发现的必要修复 | 仅增加 T2 页面开放包及两平台相关回归 |
| 用户收益与代价 | 交付最快；自定义页面需要开发者显式启用，首发可发现性较弱 | 普通用户可直接选择自定义页面；需接受部分操作仍切回内置页，并增加验证工作 |
| 主要不确定性 | 安装包/目标平台实际缺陷、签名与实模环境 | A 的不确定性，加页面切换与恢复的真实缺陷 |

推荐 A 的依据是用户已明确优先快速上线、减少新增工作；不是页面在技术上必须关闭。若“安装后即可选择自定义 Agent 页面”是此次必须展示的产品价值，则选 B。B 不以完成附件、审批、多视图或 Shell 为前置，不借开放入口扩大成完整 UI 项目。

不列“全部做完再发布”为候选：它与当前目标冲突。上线后的第一项新能力及可执行 Skill 需求暂不排期，无需现在决定；缺少这些决策不阻碍 A/B 实施。

## 2. 已确定的原则：不重复要求用户决策

- 正式默认保持内置 Agent、模型链路和 UI。
- 已支持 Tool、Context、discovery、`before_model` 和包内只读 Skill，限已接线来源与阶段，不承诺全领域替换。
- Rust native Service 和 SDK 曾实现，现按范围收敛决定删除；不再提供启用或作者开发承诺。Node 普通 Service 与生产模型合同保留；Service 流式前置本轮删除。
- 插件 Agent 页面仍默认关闭，显式启用后保留页面替换；本轮简化专用事件/参考客户端，不开放更多 UI 区域，插件不能自授权。
- 模型插件、整 Runtime、Shell 和深层基础设施替换延期，不作为本次上线必清清单。
- 保留唯一编译/执行授权链，最小信任根不交给普通插件自行替换或绕过。
- 当前共享桌面 renderer 最小 880×600；不把手机、平板或独立 Mobile 产品加入此次目标。

未来如需改变上述原则，应提出明确变更和代价；历史原生插件讨论不构成恢复后端的授权。

## 5. Agent 页面实验的剩余工作

已有页面贡献发布/选择、会话命令和事件接缝、预设偏好与基础参考页。尚缺：

| L2 | 历史 / 上下文选择 / 压缩 | 可替换策略与事实存储分离，不能篡改持久化历史 |
| L3 | 记忆 / RAG / embedding | 独立资源与策略绑定、溯源、删除语义 |
| L4 | Planner / 推理循环 / 停止 | Nomi 内策略扩展，与整 Runtime 替换分开验收 |
| L5 | 工具编排 / 并行 / 结果转换 | 实际调度、副作用重试、审批和授权边界 |
| L6 | 子 Agent / 多 Agent | 子任务授权、预算、取消传播和协调策略 |
| L7 | Session 初始化 / 事件 / 生命周期 / 后台服务 | 可扩展初始化、通用事件贡献、健康、恢复与资源回收 |
| L8 | Transport / Channel / Scheduler | 部署/安装级通道、触发与调度，保留单一会话和任务所有权 |
| L9 | 日志 / tracing / 评估 / 计量 | 用户导出、评估接口与慢消费者隔离 |
| L10 | 整 Agent Runtime | 已有引擎基础与安装型插件生命周期接线；编译期引擎扩展不算安装型替换交付 |
| L11 | Session / 事件 / checkpoint 存储 | 替代后端、一致性与迁移 |
| L12 | 编译选择策略 / Registry 存储 | 可替换策略/存储，保留一个最终校验权威 |
| L13 | 认证 / 授权 / Secret | 部署者选择、受控委托与交互审批；插件不能自批权限 |
| L14 | supervisor / sandbox / Kernel | 隔离后端与最小信任根边界；不承诺作为普通插件任意替换 |

这些领域需要具体需求和收益证明后才进入排期。语言选择不会自动解决状态所有权、凭据、安全或迁移问题；普通 UI/异步业务也不必为了语言一致性改写为 Rust。

## 8. 逐项决策清单

各条目按下方结论记录状态。推荐方案不是已确认决策；既有默认/实验边界在用户明确改变前继续有效。

### D1：首发 OS、架构与分工（已确认）

- 已确认（2026-09-15）：用户接受推荐，首发支持 **Windows x64 + macOS Apple Silicon（arm64）**；当前在 Windows 环境开发，为 macOS 记录 TODO，交接给目标机补充开发和验证。
- 执行边界：当前本机是 Windows x64，可继续相关开发与验收准备；不能把本机证据记为 Windows arm64 或 macOS 通过。macOS 必须完成首发所选架构的适用验收，不因交接而变成可省略项。
- 首发不包含 Intel Mac（x64）、Windows arm64、Linux，也不要求 macOS universal 制品；这些目标如后续有需求，另行评估，不撤销已有代码或历史支持记录。
- 桌面宿主 Rust 构建目标：Windows 为 `x86_64-pc-windows-msvc`，macOS 为 `aarch64-apple-darwin`；这不是原生插件目标支持表。范围确认不是验收通过。

### D2：直接正式上线（已确认）

- 执行方式：复用已有正式发布方式；文中的“候选包”仅指发布前用于技术验收的构建产物，不再表示单独的用户试用阶段。

- 结论：D2 已确认。后续只讨论影响实现、兼容范围或必要环境的事项，不追加发布运营流程。

### D3：历史数据兼容范围（已确认：最小工作量）

- 已确认：此次大重构以快速交付和最小工作量为优先，不为了旧版本迁移兼容追加大量工作。
- 执行方案：保留已实现的迁移和回归，不为清理旧兼容逻辑另做重构；不新建历史版本适配、数据转换工具、兼容层或多版本升级/回滚矩阵，也不再要求“最近正式版本必须升级通过”作为本次放行条件。

## 9. 实施范围与完成标准

以 §0 为唯一当前实施方案入口，D1～D4 已确认结论保留，D5 更新为 native 后端/SDK 删除。D6～D8 合并进整包范围，不再按编号串行提问；选包前不改变页面功能开关，已确认的 native 删除不等待选包。

一个领域只有同时具备以下证据才记为完成：

1. 插件能按支持方式发布、安装。
2. 用户有明确选择入口。
3. 唯一编译链冻结身份、依赖和权限。
4. 实际生产消费者使用所选实现。
5. 失败、取消、撤下与资源回收符合声明。
6. 所声明 OS/架构完成相应验收。

当前 native 代码删除已完成，其余按 §0 T1～T8 的选定范围执行。长期新领域和完整 UI 另行按收益评估，不作为本次上线条件，也不构成新一轮全量开发授权。

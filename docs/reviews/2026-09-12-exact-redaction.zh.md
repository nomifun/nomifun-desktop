# R19 审计记录：精确凭据的重叠匹配

日期：2026-09-12。续接入口：[全局台账](audit-progress.zh.md)。

## R19-01：替换必须基于原始匹配区间

四项新增回归在旧实现失败：不同凭据交叠留下前缀；同一凭据自交叠留下后缀
（含中文）；先生成的替换标记参与后续凭据匹配；截断 partial 凭据时切坏与它
重叠的完整凭据，留下无法再识别的前缀。

现在基于原始字节查找所有匹配，合并真正交叠的区间后一次输出，不反复改写输入。
与截断逻辑共用 KMP 前缀表，单模式扫描保持线性；同模式交叠先合并，再跨模式
排序合并。截断边界也回退到跨越该边界的完整交叠区间起点。相邻但不重叠的匹配
继续各自输出标记。删除不再需要的“最长凭据先替换”排序与逐次线性去重包装，
变体表仍统一排序/去重。

## 验证与校正

- 4 项旧实现失败，最终全部通过；新增小规模穷举字节 oracle 验证重叠区间。
- 初次调用方验证发现将相邻区间也合并会改变 provider 的标记扩张用例；已修正为
  只合并真正交叠，增加相邻标记断言。没有删除或放宽调用方原测试。
- 最终 net 58/0、1 子进程夹具 ignored；provider retryable_tests 19/0，包括实际
  HTTP 响应截断、原始/编码凭据、输出上限和流错误边界。
- model-invoke 脱敏定向 2/0；其 URL 诊断跨层整合将在 R20 后重新验证。
- 模式脱敏 nomi-redact 与本模块职责不同，保持独立。未声称覆盖任意网关自定义
  编码，百分号混合大小写/二次编码变体仍需核对。URL 与共享客户端待续审。

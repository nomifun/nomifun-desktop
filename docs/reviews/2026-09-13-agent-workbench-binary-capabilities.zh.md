# Agent 工作台二态重构与 WebUI 验收

## 实现范围

正式工作台采用“已启用能力 / 全部能力”双栏，分别提供分类、搜索、滚动与批量选择。勾选不改变授权；移入启用、移出禁用，行尾加减支持单项操作，撤销恢复完整配置（包括动作范围）。不可用能力仍可查看原因，不能新增启用；已失去来源的已启用能力仍可移出。

Agent 列表直接使用会话页的 `ContentSider`、收起偏好 hook 和拖动宽度 hook。默认 300px、范围 240–480px，标题栏固定入口与内部收起按钮同步。窄窗口使用遮罩抽屉，进一步缩窄时能力面板上下排列。

预设、官方种子、API DTO、前端类型、编译快照、运行时配置和会话能力投影统一使用 `enabled_capabilities`。删除第二能力集合、按需索引、预计算激活计划、能力激活命令、延迟 Context/Lifecycle 工具、视觉激活工具以及相关旧测试。Kernel 会话能力集合从已编译闭包一次构造。通用工具引擎的资源连接与工具注册机制仍属于引擎内部实现，不提供扩大 Agent 能力权限的入口。

启用依赖或禁用依赖方之前展示整个关联变更；依赖不可用、版本不一致、循环或冲突阻止整批提交。后端继续独立校验闭包、精确来源、动作范围、主体和资源归属。未提供旧三态数据兼容路径，也未迁移或清除用户数据。

已删除本轮独立设计原型的源码与临时截图，仅保留用户认可的参考图用于验收对照。原有多页面开发 harness 已更新为新契约。

## 真实 WebUI

前端以 `vite --mode webdev --port 5174` 运行；后端为 `nomifun-web --host 127.0.0.1 --port 8787 --api-only --insecure-no-auth`，使用独立的临时验收数据目录。没有模拟网络响应，也没有读取或改写正常安装的数据目录。配置了验收目录已有的免费模型作为默认模型，仅用于保存与路由解析，没有发起真实模型对话。

在 Codex 内嵌浏览器中已检查：

- Codex 预设能力 35 → 移出文件读取后 34 → 重新启用后 35，两侧状态一致。
- 创建“能力重构验收” Agent（1 项能力），禁用后保存为 0 项，刷新并重新打开仍为 0 项。
- 侧栏拖动至 270px、收起、刷新、重新展开后仍为 270px。
- 分类、搜索、不可用项、详情及按钮可达性。
- 页面无横向溢出，能力列表独立滚动，底部保存操作可见。
- 650×850 窗口下两栏上下排列，外层内容可以滚动到右栏，保存按钮仍固定可见。
- 不可用能力以明确的原因说明展示；详情使用具备对话框语义、焦点约束与可访问关闭按钮的 Modal。

## R26-01：UTF-8 分包（已验证）

旧 append_output 对每个 SSH Data/ExtendedData 分别 from_utf8_lossy，会把跨包 UTF-8 的前后半段分别替换成乱码。输出及 sentinel 的 cwd 都受影响，替换字符还可能令合法的临界长度输出误报超限。

- 先写三项生产函数回归，旧实现 0/3：中文首字节边界变成三个替换字符；混合非法字节输出 a�中b� 被拆坏；8 MiB 临界合法输出被误报 8388614 字节。
- 新增私有 ShellOutput，只保留最多三字节的未完成 UTF-8 后缀。完整合法内容直接追加；完整非法内容保留标准 lossy 语义；成功/超时/EOF 收尾时仅刷新一次后缀，同时检查替换膨胀后的最终限额。
- 合并 Data/ExtendedData 重复分支；clean 原来在 replace 后再复制整个字符串，改成原位去掉一个尾换行。未改变 CR 清理契约。
- 最终 cargo test -p nomi-ssh --lib：33/0，新增 6 项测试；其中三项红→绿、所有 UTF-8 切分边界、4681 个长度不超过四字节的小流及每个二段切分/逐字节切分、空包、尾字节重复收尾和上限、原清理语义。
- 日志：临时目录 nomifun-review-r18-2EEsPY/ssh-utf8-before.log、ssh-output-final.log。仅格式化新增源码/测试；git diff --check 通过。
- 这是实际生产解码器的测试，不是远端 SSH/PTY 集成验证。后续协议夹具会继续验证初始化和生命周期，不把这些单元测试等同于整个 shell 已审计。

## R26-02：初始化 cd 失败（状态校验已验证）

- 新增本机随机端口的脚本式 russh 服务端，调用真实 SshConnection::connect/open_shell，处理真实认证、PTY、shell 和 Data 消息；不执行远端脚本、不接外部主机。
- 旧实现对 cd 状态 2 仍返回可用 shell：定向 1/1。修复后只接受初始化 sentinel 的零状态，非零返回包含请求目录的 InvalidInput，避免在原目录继续执行。
- 最终 nomi-ssh --lib：35/0。对端在测试断言前显式 disconnect 并等待结束；known_hosts 使用 tempfile，测试密钥为公开固定种子，未引入随机数依赖。
- 初版夹具随机数 API 与锁定 ssh-key 的 rand_core 不匹配，编译失败；改为固定测试密钥再取得可靠红→绿，记录而不把编译错误当行为证据。
- 随后以真实 Git for Windows POSIX sh 执行生产 cd 生成器，三项旧实现失败：CDPATH 重定向、-target 选项、单独 - 跳 OLDPWD。相对路径统一加 ./，绝对路径保持原样；引号/空格和缺失目录回归保留。nomi-ssh 44/0，未运行其他原生平台 shell。

## R26-03：总预算与取消退役（已验证子范围）

- 五项可靠修改前失败：命令锁等待、窗口耗尽后的部分提交、初始化首写、关闭 exit 写入，以及关闭拿锁后重启预算（实测约 354ms，预算 200ms）。修复后同一截止时间覆盖初始化全程；命令包含排队/写入/读出/回答；读取超时另有最多 3 秒恢复预算，包含恢复写入和读取，不在截止后追加无界信号 await。
- 部分提交超时返回 TimedOut 并标记结果未知，不自动重放。排队超时未碰通道，保留可用性；恢复得到新 sentinel 才恢复复用。
- 关闭只有一个总预算，覆盖锁、exit/EOF、读取证据和最终 close，保存已取得的部分证明；超时不伪装成已回收。
- 另三项修改前失败：取消部分写入时 Ctrl-C 卡住导致 close 永远未发；初始化 cd 失败仅丢本地接收器；闲置 RemoteShell Drop 不发 channel close。现在移除脱管退役任务，通过不需要数据窗口的控制请求进行非阻塞退役尝试。
- 通道所有权、可用标记和不可用原因合并为单个短同步状态槽，只有命令串行入口需要异步锁。退役通道不能再用于 run，但保留接收器给显式 close 读取退出状态。未知状态下不向半条命令追加 exit 文本。
- 生产 Drop 不创建任务，不等网络；控制发送队列满时只作尽力尝试，不能承诺对端收到。仍存活的 Shell 所有者可显式 close 重试并收证；Shell 最终 Drop/初始化取消本身不提供远端回收证明。
